## 3. 怎么打开

原型是**纯静态 HTML**，不需要构建、不需要后端：

1. 直接用浏览器打开 `index.html`（批次 2-1 起提供）
2. 或在本目录起一个静态服务：`python -m http.server 8080`，然后访问 `http://localhost:8080/`

原型**不连后端**，所有数据来自 `content-samples.json`，交互后果用页面内的提示块演示。

### 3.1 深链接（评审与截图用）

页面支持把角色、状态、浮层写进 URL，便于直接定位到某个形态：

| 参数 | 取值 | 示例 |
|---|---|---|
| `role` | `super_admin` / `academic_director` / `homeroom` / `grade_leader` / `subject_teacher` / `school_leader` / `platform_ops`（教师页面另有 `tenant_admin`） | `student-list.html#role=homeroom` |
| `state` | `normal` / `loading` / `empty` / `error` / `forbidden` / `submitting` / `partial` / `queued` | `student-list.html#state=error` |
| `panel` | `PAGE-STU-CREATE` / `PAGE-STU-EDIT` / `PAGE-TCH-DETAIL` / `PAGE-TCH-CREATE` / `PAGE-TCH-EDIT` / `PAGE-TCH-ROLE` / `DIALOG-TCH-LEAVE` / `DIALOG-TCH-DISCARD` / `DIALOG-TCH-COPY` / `DIALOG-GRD-DELETE` / `PAGE-GRD-DETAIL` / `PAGE-GRD-CREATE` / `PAGE-GRD-BATCH` / `PAGE-GRD-LEADER` / `PAGE-GRD-ARCHIVE` | `grade-list.html#panel=PAGE-GRD-LEADER` 直接打开指定年级主任弹窗 |
| `school` | `201` / `202` | `student-list.html?school=202#role=platform_ops`（平台运营切换他校的协助视图；学校用户看不到他校数据） |
| `sample` | 教师详情样例：`1007`（跨校任教）/ `1003`（班主任 + 任课） | `teacher-list.html#panel=PAGE-TCH-DETAIL&sample=1003` |
| `step` | 向导类浮层的步骤序号，如 `3` | `teacher-list.html#panel=PAGE-TCH-CREATE&step=3` |
| `enroll` | 年级列表的入学年份筛选，如 `2021` | `grade-list.html#enroll=2021`（只看空年级） |
| `leader` | 年级列表的年级主任筛选，教师姓名或 `__none` | `grade-list.html#leader=__none` |
| `stage` | 年级列表的学段筛选，`primary` / `junior` / `senior`，逗号分隔 | `grade-list.html#stage=junior,senior` |
| `sample` | 年级详情的样本：`A`（2026 级 高一）/ `B`（空年级） | `grade-list.html#panel=PAGE-GRD-DETAIL&sample=B` |

> **深链接在"已经打开的页面"上也生效**：外壳在 `hashchange` 时会重新解析参数并派发 `prototype:params` 事件，
> 页面监听该事件重放自己的筛选参数。因此直接在地址栏把 `#enroll=2021` 加到一个已经打开的年级列表后面即可生效，
> 不需要刷新（`GL-34` 实测）。

多个参数用 `&` 连接，例如 `student-list.html#role=homeroom&panel=PAGE-STU-EDIT`。

## 4. 原型要遵守的六条硬规则

1. **每个可交互元素必须带 `markup-contract.md` 要求的 `data-*` 标记**，缺标记视为不合格。
   这是阶段 6 能把 `div` / `a` / `button` 准确映射成 `el-button` 等组件的前提。
2. **页面上的每个字段、按钮、筛选项都要能在 PRD 中找到出处**（页面规格里写 `REQ-` 与 `BR-` 编号）。
3. **必须给出六类状态**：加载中、空数据、无权限、查询失败、提交中、部分失败。只画"有数据"的正常态不算完成。
4. **数据必须真实且带边界**：取自 `content-samples.json`，表格不少于 10 行，每页至少用到 3 类边界样本
   （空、满、超长、缺失、特殊字符、终态、待办中、跨校）。
5. **至少给出两种角色形态**：差异要落在按钮与字段可见性上，用角色切换器演示，不复制多份页面。
6. **原型必须能点**：纯 JS 演示切状态、开抽屉、模拟提交与校验失败，2 分钟能点通主流程。

以上 6 条的完整依据、判断标准与验收清单见 `prototype-quality-spec.md`。

## 6. 与阶段 3 的边界

| 议题 | 阶段 2（本目录） | 阶段 3（高保真） |
|---|---|---|
| 布局与栅格 | **定稿** | 沿用 |
| 字段、按钮、跳转 | **定稿** | 沿用，不得增删功能 |
| 颜色、字体、间距精修 | 用 Element Plus 默认值与 `apps/plus-ui` 既有变量 | 用 `design-tokens.json` 覆盖 |
| 组件映射 | 用 `data-component` 标注目标组件 | 在 `component-mapping.yaml` 中细化为属性级映射 |
| 交互反馈（动效、过渡） | 只画状态，不做动效 | 明确过渡与微交互 |

## 7. 已知约束

- 原型按 **1440×900** 为主基准设计，兼顾 1366×768 与 1920×1080（`NFR-COMPAT-02`）。
- 首轮不做移动端；原型只需在窗口宽度小于 992px 时给出"请在 PC 端使用"的提示态。
- 原型里的中文样例数据取自 `content-samples.json`，**不得使用 `张三` / `李四` / `test` 这类占位数据**。

## 8. 批次 2-1 的工程决策（待确认，若不认可可回退）

| 事项 | 做法 | 理由 |
|---|---|---|
| 外壳实现 | 侧边菜单、顶部导航、页签栏、面包屑、角色与状态切换放在 `assets/prototype-shell.js`，由 `#app-shell` 占位容器注入；每个页面底部仍保留自己的内联脚本写本页差异 | 86 个页面共用一份外壳，避免"每页侧边栏宽度不同"这类漂移（对应根因 1、根因 12） |

## 10. 批次 2-2b-2 的工程决策（待确认，若不认可可回退）

| 事项 | 做法 | 理由 |
|---|---|---|
| 任教关系设置的承载 | 新增独立页 `pages/teacher-assign.html`，双栏（左栏主体选择器 320px + 右栏主体与任教关系） | 教师 PRD 6.1 写明为独立页；"需要对照列表数据填写 + 含表格与批量选择"按 `prototype-quality-spec.md` 第 5 节必须用独立页 |

配套修的两处实现问题：

- `.dialog-body` 原来没有 `flex:1`，弹窗内的高内容（如三步新增教师）会被 `.dialog { overflow:hidden }` 裁掉且无法滚动；

- 弹窗内部仍沿用 `drawer-header` / `drawer-body` / `drawer-footer` 三个样式钩子，已按容器类型改名 `dialog-*`，
  避免阶段 6 组件映射时误判容器。
