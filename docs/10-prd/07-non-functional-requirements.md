# 非功能需求

编号规则 `NFR-<域>-<序号>`。

## PERF 性能

| 编号 | 需求 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-PERF-01 | 目标规模 | 单租户 65 所学校、10 万学生、200 并发活跃用户 | 压测模型 |
| NFR-PERF-02 | 列表查询响应 | P95 ≤ 1 秒 | 在目标规模数据量下压测 |
| NFR-PERF-03 | 普通写入响应 | P95 ≤ 2 秒 | 同上 |
| NFR-PERF-04 | 单表数据量 | 学生主表按 10 万行设计，班级关系表按 100 万行以内设计 | 数据量核对 |
| NFR-PERF-05 | 分页 | 列表默认每页 20 条，最大 200 条，全量导出走异步 | 代码检查 |
| NFR-PERF-06 | 批量导入校验 | 5000 行以内，校验阶段同步返回，耗时 ≤ 30 秒 | 端到端测试 |
| NFR-PERF-07 | 学年升级 | 1 万名学生以内单次升级 ≤ 5 分钟，异步执行不阻塞界面 | 端到端测试 |
| NFR-PERF-08 | 前端首屏 | 生产构建后首屏可交互 ≤ 3 秒（内网 100Mbps） | 前端性能测量 |

## SEC 安全

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-SEC-01 | 租户隔离 | 学校级及以下的教育数据查询必须带 `tenant_id`，跨租户访问一律拒绝。**例外**见 NFR-SEC-10 |
| NFR-SEC-02 | 学校隔离 | 除平台运营外，任何角色不得跨校读取教学数据 |
| NFR-SEC-03 | 默认拒绝 | 数据范围解析失败或为空时返回空结果或拒绝，禁止降级为全量 |
| NFR-SEC-04 | 越权防护 | 覆盖跨租户、跨校、跨年级、跨班、ID 猜测、批量操作、导出、文件下载、异步任务结果查询的测试用例 |
| NFR-SEC-05 | 功能权限 | 所有写接口必须校验功能权限，禁止只在前端隐藏按钮 |
| NFR-SEC-06 | 敏感字段 | 证件号、手机号默认掩码；查看全量需要独立权限并留痕 |
| NFR-SEC-07 | 越权响应 | 返回统一的"无权限"错误码，不泄漏对象是否存在 |
| NFR-SEC-08 | 传输 | 生产环境强制 HTTPS |
| NFR-SEC-09 | 密码与令牌 | 沿用基线 Sa-Token 方案，不新建认证体系 |
| NFR-SEC-10 | 平台级实体的例外条款 | 学生主体（`edu_student`）与监护人主体（`edu_guardian`）是平台级实体，不设 `tenant_id`、不参与学校租户隔离。两者的访问改用平台级数据权限，且必须满足三条：① 学校侧一律经在校记录 / 班级关系做两段式取数，禁止直接查询主体表；② 每次查询显式携带数据范围条件；③ 查询条件必须能追到 `DS-DENY-01` ~ `DS-DENY-09` 中的具体一条。见 D-037、D-030 |

## AUDIT 审计

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-AUDIT-01 | 关键写操作留痕 | 操作人、角色、租户、学校、对象类型、对象 ID、变更前后值、时间、来源 IP |
| NFR-AUDIT-02 | 敏感数据访问留痕 | 查看证件号、联系方式全量时记录访问日志 |
| NFR-AUDIT-03 | 导出留痕 | 记录筛选条件、行数、耗时、导出人 |
| NFR-AUDIT-04 | 平台运营留痕 | 平台侧任何数据访问都可被追溯，并可按租户导出 |
| NFR-AUDIT-05 | 不可篡改 | 审计日志只可追加，不可修改或删除 |
| NFR-AUDIT-06 | 保留期限 | 不少于 3 年 |

## DATA 数据

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-DATA-01 | 结构权威 | 迁移脚本是数据库结构的唯一权威来源，物理表结构文档必须与脚本一致 |
| NFR-DATA-02 | 外键 | 同服务内核心关系使用物理外键，禁止级联删除 |
| NFR-DATA-03 | 跨服务引用 | 使用逻辑引用 + 一致性检查 SQL |
| NFR-DATA-04 | 迁移可验证 | 空库安装与存量升级都必须在真实 MySQL 8 上验证 |
| NFR-DATA-05 | 备份与恢复 | 提供备份与恢复方案，恢复演练纳入验收 |
| NFR-DATA-06 | 历史保留 | 学籍、班级关系、选科的历次变更必须可回溯到任一时间点 |
| NFR-DATA-07 | 时区 | 统一使用东八区，数据库与服务器时间一致 |

## CACHE 缓存

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-CACHE-01 | 键设计 | 所有缓存键必须带租户前缀，学校级数据带学校前缀 |
| NFR-CACHE-02 | 失效 | 每类缓存必须有明确失效策略，不允许只写不删 |
| NFR-CACHE-03 | 权限 | 缓存命中不得绕过数据范围判定；权限相关结果不缓存 |

## MQ 消息

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-MQ-01 | 幂等 | 所有消费者必须幂等，使用业务幂等键 |
| NFR-MQ-02 | 重试 | 定义重试次数与退避策略 |
| NFR-MQ-03 | 死信 | 超过重试次数的消息进入死信队列，并提供查看与重放 |
| NFR-MQ-04 | 异步任务 | 耗时的导入、导出、升班走异步，返回任务编号，前端可查询进度 |

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-COMPAT-01 | 浏览器 | Chrome ≥ 87、Edge ≥ 88、Safari ≥ 14、Firefox ≥ 78（沿用 `apps/plus-ui/package.json` 的 browserslist） |

| 编号 | 需求 | 说明 |
|---|---|---|

## CODE 工程质量

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-CODE-01 | 前端门禁 | 新增代码零 TypeScript 错误、零 ESLint 错误；既有错误数不增加（见 D-024） |
| NFR-CODE-02 | 后端门禁 | JDK 17 编译通过；显式启用测试并核对用例数量 |
| NFR-CODE-03 | 测试覆盖 | 业务规则、数据权限、幂等与并发、迁移脚本四类测试必须存在 |
| NFR-CODE-04 | 接口契约 | 后端实现与 OpenAPI 声明一一对应 |
| NFR-CODE-05 | 文档追踪 | 每个需求可追到原型、接口、表、代码与测试 |

## 首轮不做的非功能项

| 项 | 原因 |
|---|---|
| 多活与异地容灾 | 首轮为私有化单机房部署 |
| 分库分表 | 目标规模不需要，过早引入会显著增加复杂度 |
| 全链路压测自动化 | 首轮做一次性压测并留证据 |
