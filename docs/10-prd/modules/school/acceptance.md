## 1. 验收怎么进行

三层验收（需求 / 实现 / 交付），本轮只做**需求验收**。
用例状态五选一：`通过` / `失败` / `未执行` / `不适用` / `已失效`。
缺陷分级与通过判定与 `modules/student/acceptance.md` 一致：P0 与 P1 未关闭时不得判定通过。

## 2. 测试数据与账号准备

### 2.1 必备账号

| 账号 | 角色 | 数据范围 | 用途 |
|---|---|---|---|
| `ops_admin` | 平台运营 | 全平台 | 建校、停用、跨集团用例 |
| `group_admin` | 集团租户管理员 | 集团及其子树组织 | `DS-10` 边界用例 |
| `t_admin_a` | A 校租户管理员 | A 校组织配置 | 本校信息与校区维护 |
| `s_leader_a` | A 校校领导 | A 校 | 只读与学段审批用例 |
| `academic_a` | A 校教务主任 | A 校 | 只读本校信息 |

### 2.2 必备数据

| 数据 | 数量 | 说明 |
|---|---|---|
| 运营方租户 | 1 个 | 超级租户 |
| 集团租户 | 1 个 | 下挂 3 所学校租户 |
| 独立学校租户 | 2 个（无集团） | 编码唯一性口径用例 |
| 学校 | 5 所（集团下 3 所 + 独立 2 所） | 列表与范围用例 |
| 未绑定租户的学校租户 | 1 个 | 新建学校用例 |
| 校区 | A 校 2 个 | 校区用例 |
| 有年级引用的学段 | A 校高中 | 学段移除限制用例 |
| 有班级引用的校区 | A 校主校区 | 校区删除限制用例 |

### 2.3 前置系统能力

现有租户管理能力可用（创建租户、设置套餐）；学年学期、学科、年级、班级模块已可用，
用于验证引用与统计。

## 4. 权限与数据范围验收用例

任何一个失败即判定本模块不通过。

| 用例 | 场景 | 期望结果 |
|---|---|---|
| `AC-SCH-101` | 缺 `tenant_id` 调用学校列表 | 拒绝，不返回数据 |
| `AC-SCH-102` | 学校侧角色未带 `school_id` 调用本校信息接口 | 拒绝 |
| `AC-SCH-103` | 数据范围为空的账号调用列表 | 返回空列表，不返回全量（`DS-DENY-03`） |
| `AC-SCH-104` | A 校账号按 B 校学校 ID 请求详情 | 返回空 / 无权限并记录拒绝原因（`DS-DENY-07`） |
| `AC-SCH-105` | 校领导查询其他学校信息 | 返回空 |
| `AC-SCH-106` | **集团租户管理员**维护下属学校组织信息 | 允许（`DS-10`） |
| `AC-SCH-107` | **集团租户管理员**读取下属学校的学生、班级花名册、任教关系 | **拒绝**（`DS-03` 不含下属学校教学数据） |
| `AC-SCH-108` | 集团专家读取下属学校学生名单 | 拒绝 |
| `AC-SCH-109` | 学校统计摘要接口用不同账号调用 | 统计值随数据范围变化（`DS-DENY-08`） |
| `AC-SCH-110` | 平台运营查看学校详情 | 写入留痕，且租户侧可导出该留痕记录 |
