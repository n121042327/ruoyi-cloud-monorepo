## 0. 怎么读这份文档

需求编号 `REQ-SCH-xxx`。公共前置的编号只引用不复制。

学校是本平台**教学数据的边界**（`BR-ORG-006`）。学校与学校租户一一对应（`BR-ORG-002`），
所以本模块同时扮演两个角色：组织管理入口，以及租户开通流程的落地点。

| 内容 | 归属 |
|---|---|
| 学校主体、校区、学校开设的学段、学校状态 | 本模块 |
| 租户本身的创建与套餐、到期时间、账号上限 | 租户管理（现有 `sys_tenant` 能力，本模块只引用其 ID） |
| 学年学期 | 学年学期模块 |
| 学科与选科角色 | 学科模块 |
| 年级、班级、教师、学生 | 各自模块 |

## 1. 模块定位与范围

### 1.1 解决什么问题

学校管理要解决三件事：

1. **把组织落到数据上**：一个学校租户对应一所学校，教学数据全部挂在它上面
2. **把"学校开设哪些学段"说清楚**：这直接决定它能建哪些年级，而年级又决定数据范围
3. **把校区表达出来但不破坏权限边界**：校区是物理位置，不是权限单元（`BR-ORG-009`）

### 1.2 范围内

| 能力 | 说明 |
|---|---|
| 学校列表与检索 | 平台运营视角的全局列表，学校侧视角的单校信息 |
| 学校详情 | 基本信息、校区、开设学段、统计摘要 |
| 新建学校 | 由平台运营创建，同时完成租户绑定 |
| 编辑学校 | 名称、办学类型、地址、联系方式等 |
| 校区管理 | 新增、编辑、停用校区 |
| 学段配置 | 学校开设学段（小学 / 初中 / 高中），决定可选年级范围 |
| 学校状态 | 启用 / 停用，停用后该租户下人员登录被拒绝 |
| 开通初始化 | 新建学校后引导初始化学年学期、学科、基础角色 |
| 审计 | 关键写操作留痕 |

### 1.3 范围外

| 不做 | 归属 |
|---|---|
| 租户套餐、到期时间、账号上限的维护 | 租户管理（现有能力） |
| 集团层级与租户树的建立 | 租户管理（现有能力） |
| 学年学期、学科、年级、班级的批量初始化内容 | 各模块；本模块只提供"初始化向导"入口 |
| 学校合并 | 首轮不做（涉及跨租户数据迁移，属重大操作） |
| 校区的权限隔离 | 明确不做（`BR-ORG-009`） |
| 学校画像、办学质量统计 | 后续阶段 |

## 3. 术语与逻辑实体

### 3.1 术语

租户、学校租户、集团租户、运营方租户、根租户、学校、校区、学段的定义见 `03-glossary.md`。

本模块必须强调三个区分：

| 区分 | 说明 |
|---|---|
| 租户 vs 学校 | 学校租户是隔离单位，学校是教学实体，二者一一对应（`BR-ORG-002`）。学校记录上冗余保存 `tenant_id`，但**不能用它做跨校查询的依据** |
| 学校 vs 校区 | 校区不改变数据权限边界（`BR-ORG-009`）。校领导看本校全部校区，不能被校区切分权限 |
| 学校编码 vs 租户编码 | 学校编码在集团内唯一（`BR-ORG-011`），独立学校租户则在本租户内唯一 |

### 3.2 逻辑实体

| 实体 | 含义 | 权威来源 |
|---|---|---|
| 学校 | 教学实体，与学校租户一一对应 | 本模块（`edu_school`） |
| 校区 | 学校内的物理校区 | 本模块（`edu_campus`） |
| 学校开设学段 | 该学校提供哪些学段 | 本模块（`edu_school_stage`） |

### 3.3 实体关系

```mermaid
erDiagram
  TENANT ||--|| SCHOOL : "学校租户对应一所学校"
  SCHOOL ||--o{ CAMPUS : "校区"

  SCHOOL ||--o{ GRADE : "年级"
  SCHOOL ||--o{ CLASS : "班级"
  SCHOOL ||--o{ TEACHER : "教师"
  SCHOOL ||--o{ STUDENT_SCHOOL_RECORD : "在校记录"
```

| `REQ-SCH-004` | 默认列表列：学校名称、学校编码、上级集团、办学类型、开设学段、校区数、状态、创建时间 | `BR-ORG-003` | — |
| `REQ-SCH-005` | 学校侧角色（校领导、教务主任）进入本模块时只看到本校一行，列表退化为信息卡 | `DS-04` | — |
| `REQ-SCH-006` | 列表结果逐行通过数据范围过滤，范围为空时返回空列表 | `DS-DENY-03` | — |
| `REQ-SCH-007` | "新建学校""编辑""管理校区""配置学段""停用"按钮按功能权限显示，后端二次校验 | `NFR-SEC-05` | `05-permission-matrix.yaml` |
| `REQ-SCH-008` | 平台运营导出学校清单需显式授权，且导出写审计 | `BR-DATA-015`、`BR-IMP-005` | 平台运营 `data.export` |

**列表派生列的取数口径**（`CR-159`，用户 2026-10-10 确认按推荐实现）

| 列 | 口径 |
|---|---|
| 开设学段 | `edu_school_stage.status = '1'` 的学段编码，按编码升序以逗号拼接（CR-107） |
| 校区数 | `edu_campus.school_id = 学校` 的记录数（逻辑删除由框架过滤） |
| 班级数 | `edu_class.school_id = 学校` 的记录数 |
| 在读学生 | `edu_student_enrollment.school_id = 学校` 且 `enrollment_status = 'enrolled'` 的**去重学生数**，不限学年 |
| 在职教师 | `edu_teacher.school_id = 学校` 的记录数 |

- 「在读学生」与 4.2 的统计摘要（`REQ-SCH-010`）共用同一口径，不得出现两套数字；
- 「按开设学段筛选」（`REQ-SCH-002`）命中 `edu_school_stage.status = '1'` 的记录：
  没有开设任何学段的学校不会命中任何学段筛选；筛选结果为空时返回空列表，不退化为全量（`DS-DENY-03` 同口径）。

## 5. 权限需求

### 5.1 功能权限

| 资源 | 操作 | 说明 |
|---|---|---|
| `org.school` | read / create / update | 学校主体 |
| `org.tenant` | read | 绑定租户时需要读租户列表 |
| `org.grade` | read | 学段移除前需要检查年级引用 |
| `org.class` | read | 校区停用前需要检查班级引用 |
| `data.export` | export | 导出学校清单 |
| `audit.log` | read | 变更记录 |

### 5.2 数据范围

| 角色 | 范围编号 | 落地方式 |
|---|---|---|
| 平台运营 | `DS-01` | 全平台学校清单 |
| 租户管理员 | `DS-02` / `DS-10` | 本租户学校；集团租户管理员可管理下属学校**组织信息** |
| 校领导 / 教务主任 | `DS-04` | 仅本校 |
| 集团专家 / 领导 | `DS-03` | 集团自有数据，不含下属学校教学数据 |

**集团租户管理员的边界**：可维护下属学校的组织信息（名称、校区、学段），
**不可读取下属学校的教学数据**（学生、班级花名册、任教关系）。这两件事分别落在
`DS-10` 与 `DS-03`，实现时必须分开判定。

### 5.3 拒绝规则

严格遵守 `DS-DENY-01` ~ `DS-DENY-09`。本模块特别需要落实：

| 规则 | 落地要求 |
|---|---|
| `DS-DENY-01` | 缺少租户上下文时拒绝任何学校级查询 |
| `DS-DENY-07` | 学校详情先过滤范围再按 ID 取数 |
| `DS-DENY-08` | 学校统计摘要受范围约束 |

## 12. 设计选择确认

本模块未发现阻塞性缺项。以下三处属于设计选择，已于 2026-09-30 经用户整体确认：

| 序号 | 事项 | 采纳方案 | 备选 | 结论（2026-09-30） |
|---|---|---|---|---|
| 1 | 学校是否提供删除入口 | 不提供，只提供停用 | 提供逻辑删除（需无教学数据） | **已确认**：只提供停用 |
| 2 | 开通初始化向导是否强制完成 | 不强制，可在学校列表行内标记"初始化未完成" | 强制完成才能进入其他模块 | **已确认**：不强制，用行内标记提示 |
| 3 | 集团租户管理员是否可维护下属学校的组织信息 | 可以（`DS-10`），但不可读教学数据 | 不可以，只由平台运营维护 | **已确认**：可以维护组织信息，但读不到教学数据 |

第 3 项决定集团是否有"统一维护下属学校信息"的能力，已确认为**有**，边界是组织信息与教学数据分离。
