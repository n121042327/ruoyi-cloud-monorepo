## 0. 怎么读这份文档

需求编号 `REQ-CLS-xxx`。公共前置的编号只引用不复制。

本模块是**唯一有权写入"学生在哪个班"和"谁是班主任"的模块**。
这两件事分别是学生数据权限（`DS-06`）与班级花名册的权威来源，
所以本模块的写入入口不与其他模块重复（`DP-01`）。

| 内容 | 归属 |
|---|---|
| 行政班、教学班、花名册、班主任字段 | 本模块 |
| 学生主体与学籍状态 | 学生管理模块 |
| 教师主体与任教关系 | 教师管理模块（本模块只读展示任课教师） |
| 年级主体与年级主任 | 年级管理模块 |
| 学年学期 | 学年学期模块 |
| 升班批量执行 | 升班与学籍异动模块（本模块提供班级维度的只读视图） |

## 1. 模块定位与范围

### 1.1 解决什么问题

班级管理回答**"这个学年学期，学生被编到哪些班，谁带这个班"**。

期末最容易出问题的三件事都在这里：编班时把同一名学生编进两个班；
换班主任后新班主任看不到班、老班主任还能看到；跨学年改历史班级把往年花名册改坏。
本模块的规则设计就是为了让这三种情况在系统里做不到。

### 1.2 范围内

| 能力 | 说明 |
|---|---|
| 班级列表与检索 | 按学年学期、年级、类型、班主任筛选 |
| 班级详情 | 基本信息、花名册、任课教师、班主任、变更记录 |
| 新建与编辑班级 | 含名称唯一性与学年学期保护 |
| 花名册管理 | 添加、移出、调班、批量操作、历史只读 |
| 教学班管理 | 与行政班完全独立；首轮交付**表结构 + 界面 + 接口**（`GAP-023` 裁决选 A） |
| 班主任指定 | 唯一写入入口，含历史任职 |
| 班级停用 | 有在读学生时不允许删除；**合并延后** |
| 班级复制与批量迁学生 | 作为"学年学期 / 年级不可修改"的缓解措施 |
| 导入导出 | 班级导入、花名册（编班表）导入、导出留痕 |
| 审计 | 关键写操作留痕 |

### 1.3 范围外

| 不做 | 归属 |
|---|---|
| 自动编班、智能分班、自动优化 | 首轮不做（`01-product-context.md` 4.2 节） |
| 自动排课 | 首轮不做 |
| 学生主体与学籍状态的维护 | 学生管理模块 |
| 任教关系的维护 | 教师管理模块（本模块只读展示） |
| 升班的批量执行 | 升班与学籍异动模块 |
| 班级公告、班级群、家校沟通 | 后续阶段 |
| 班级容量强制校验 | 明确不做（`BR-CLASS-005`） |
| 班级合并 | 延后。合并涉及学生冲突、历史关系与班主任归属，是完整业务流程；首轮只做停用 |

## 3. 术语与逻辑实体

### 3.1 术语

行政班、教学班、班级花名册、班主任、调班的定义见 `03-glossary.md`。

本模块必须强调三个区分：

| 区分 | 说明 |
|---|---|
| 行政班 vs 教学班 | 两套独立关系（`BR-CLASS-001`）。一名学生同一学年学期只能属于一个行政班，但可同时属于多个教学班（`BR-STU-003`、`BR-STU-004`） |
| 班级归属 vs 学籍状态 | 学生休学期间保留行政班关系但不计入在读名单（`BR-STU-012`），所以花名册需要区分"全部成员"与"在读成员" |
| 班主任 vs 任课教师 | 班主任是班级表上的一个字段（`DP-01`），任课教师来自任教关系表。两者不是同一来源 |

### 3.2 逻辑实体

| 实体 | 含义 | 权威来源 |
|---|---|---|
| 班级 | 行政班或教学班 | 本模块（`edu_class`） |
| 花名册关系 | 某学生在某学年学期的行政班归属 | 本模块（`edu_student_class`） |
| 班主任任职 | 班级表上的 `head_teacher_id` 与起止日期 | 本模块（`edu_class`） |
| 任课教师关系 | 教师在班级的授课关系 | 教师管理模块（`edu_teaching_assignment`，本模块只读） |

### 7.3 状态取值与字段登记（`CR-010`）

班级 `class_status` 只有两个取值（`FD-class_status`）：

| 取值 | 标签 | 业务含义 | 约束 |
|---|---|---|---|
| `studying` | 在读 | 班级正常使用 | 参与编班、班主任指定、批量迁学生 |
| `disabled` | 已停用 | 班级不再使用 | 不在新建学生与编班的可选班级中；历史花名册仍可查；不再接受编班、班主任变更与批量迁学生（`REQ-CLS-044`） |

两条口径说明：

- **学年归档不改变班级状态**：学年学期模块 `REQ-TERM-030` 只把已归档学年移出"新建班级"的可选列表，
  班级本身保持 `studying`，历史数据与统计照常可查（`REQ-TERM-031`）。
- **「已合并」暂不登记**：班级合并（`REQ-CLS-045`）首轮延后，合并引入的终态等到启用该功能时一并评估。

同期登记的字段：`campus_id`（引用校区，`BR-ORG-009`：校区不参与权限判定）与 `classroom`（自由文本）。
