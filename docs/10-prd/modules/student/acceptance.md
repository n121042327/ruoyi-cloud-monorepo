## 1. 验收怎么进行

三层验收，缺一层不算通过：

| 层次 | 谁执行 | 何时 | 判定 |
|---|---|---|---|
| 需求验收 | 用户 + 产品 | 本批次现在 | 逐条确认需求本身是否写对、是否够用 |
| 实现验收 | 开发 + 测试 | 阶段 6 / 7 完成后 | 按本文件用例逐条执行 |
| 交付验收 | 用户 + 业务方 | 阶段 8 | 真实数据走通主流程 |

本批次只做**需求验收**：确认 `PRD.md` 中的 97 条需求与下列验收要点是否可接受。
实现验收与交付验收在后续阶段按同一份清单执行。

### 1.1 状态口径

用例状态只允许五选一：`通过` / `失败` / `未执行` / `不适用` / `已失效`。
不得把"代码写完"记为"通过"。

### 1.2 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 阻塞 | 越权、数据错乱、主流程不可用 | 必须修复后才能通过本批 |
| P1 严重 | 关键功能不可用或有绕行成本 | 必须修复后才能通过本批 |
| P2 一般 | 非关键功能异常、体验问题 | 可带缺陷通过，登记到 `known-issues.md` |
| P3 轻微 | 文案、样式细节 | 可带缺陷通过 |

任何 P0 与 P1 未关闭时，本模块不得判定通过。

## 2. 测试数据与账号准备

### 2.1 必备账号

| 账号 | 角色 | 数据范围 | 用途 |
|---|---|---|---|
| `ops_admin` | 平台运营 | 全平台 | 跨租户与留痕用例 |
| `t_admin` | 租户管理员 | 本校组织配置 | 验证其**看不到**学生 |
| `s_leader` | 校领导 | 本校 | 本校范围用例 |
| `academic` | 教务主任 | 本校 | 主流程用例 |
| `grade_leader_a` | 年级主任 | 高一 | 年级范围用例 |
| `homeroom_1` | 班主任 | 高一(1)班 | 班级范围与监护人编辑用例 |
| `teacher_1` | 任课教师 | 高一(1)班数学 | 字段限制与禁止导出用例 |
| `student_1` | 学生 | 本人 | 只读本人用例 |

### 2.2 必备数据

| 数据 | 数量 | 说明 |
|---|---|---|
| 学校租户 | 2 个（A 校、B 校），同属一个集团 | 跨校用例 |
| 独立学校租户 | 1 个（C 校，无集团） | 跨根租户用例 |
| 年级 | A 校 3 个（高一、高二、高三） | — |
| 行政班 | A 校 6 个（高一 1–3 班、高二 1–3 班） | — |
| 学生 | A 校 120 名、B 校 40 名、C 校 20 名 | 分页与范围用例 |
| 学籍状态分布 | 转入未报到 3、在读 152、休学 8、出国 2、失踪 1、已转出 6、毕业 4、结业 2、肄业 1、开除 2、退学 2、死亡 1 | 状态用例 |
| 监护人 | 每名学生 1–3 名，其中 5 名学生有 3 名 | 上限用例 |
| 超规模数据 | 10 万学生（独立压测库） | 性能用例 |

### 2.3 前置系统能力

| 能力 | 要求 |
|---|---|
| 租户与学校 | 已建好三类租户与学校 |
| 学年学期 | 已设置当前学年学期，且有历史学年 |
| 学科与年级 | 已配置 |
| 数据共享授权 | 已创建一条 A 校 → B 校教师的只读授权，用于验证授权范围 |
