## 0. 怎么读这份文档

需求编号 `REQ-GRD-xxx`。公共前置的编号只引用不复制。

年级是**数据范围的第四层**（`DS-05`）。年级主任能看到什么，完全由本模块维护的任职关系决定，
所以年级不是一张单纯的字典表。

| 内容 | 归属 |
|---|---|
| 年级主体、年级与学段的对应、年级主任任职 | 本模块 |

## 1. 模块定位与范围

### 1.1 解决什么问题

年级管理回答**"这所学校有哪些年级、每个年级谁负责"**。

它的作用有两个：一是给班级提供归属维度；二是给年级主任提供数据范围的依据。
如果年级建错或年级主任漏配，后果不是少一个下拉选项，而是
**该年级的班主任与任课教师数据范围解析不出来**，进而整年级数据不可见。

### 1.2 范围内

| 能力 | 说明 |
|---|---|
| 年级列表与检索 | 按学段、入学年份筛选 |
| 年级详情 | 基本信息、班级列表、学生统计、年级主任、变更记录 |
| 新建与编辑年级 | 含学段与序号的固定映射校验 |
| 批量生成年级 | 按学段一次性生成全部年级 |
| 年级主任指定 | 支持一名或多名，绑定学年学期 |
| 归档与删除约束 | 有班级或学生关系时不允许删除 |
| 与学年升级的配合 | 提供按学段内序号推进的年级视图 |
| 审计 | 关键写操作留痕 |

### 1.3 范围外

| 不做 | 归属 |
|---|---|
| 学段字典的可配置维护 | 明确不做（`BR-GRADE-001`、`BR-GRADE-006`） |
| 年级组的组织化建模 | 首轮不做，年级主任任职已覆盖数据范围需求 |
| 班级与学生的直接维护 | 班级管理 / 学生管理模块 |
| 年级层面的成绩、考勤、课表统计 | 后续阶段 |
| 自动升级执行 | 升班与学籍异动模块 |

### 1.4 上游依赖

| 依赖 | 用途 | 缺失后果 |
|---|---|---|
| `docs/10-prd/04-business-rules.md` | `BR-GRADE-*` | 无法判定名称唯一性与学段映射 |
| `docs/10-prd/05-permission-matrix.yaml` | 功能与数据权限 | 按钮显隐与范围判定无依据 |
| `docs/10-prd/06-field-dictionary.yaml` | `stage_code` 枚举、`grade_name`、`grade_level` | 学段与序号无权威定义 |
| `docs/10-prd/10-data-permission-schema.md` | `edu_grade_leader` 表结构 | 年级主任任职无表可用 |
| 学校管理模块 | 年级所属学校 | 归属无法表达 |
| 学年学期模块 | 年级主任任职的学期维度 | 任职无法按期表达 |

## 2. 角色与场景

### 2.1 涉及角色

| 角色 | 本模块数据范围 | 本模块关键限制 |
|---|---|---|
| `PER-PLATFORM-OPS` 平台运营 | 全平台（`DS-01`） | 默认只读；留痕 |
| `PER-TENANT-ADMIN` 租户管理员 | 本租户组织配置（`DS-02`） | 可维护年级与年级主任任职（属非教学配置） |
| `PER-SCHOOL-LEADER` 校领导 | 本校（`DS-04`） | 只读全部，审批年级主任变更 |
| `PER-ACADEMIC-DIRECTOR` 教务主任 | 本校（`DS-04`） | 本模块主要操作者 |
| `PER-GRADE-LEADER` 年级主任 | 所负责年级（`DS-05`） | 只读本人负责的年级信息 |
| `PER-HOMEROOM` / `PER-SUBJECT-TEACHER` | 班级 / 任教班级（`DS-06` / `DS-07`） | 只读年级摘要 |

> 口径说明（2026-09-30，CR-005 / `GAP-034`、`GAP-035`）：
> 校领导对本模块**只读**，年级主任任职的变更由校领导**审批**，不由校领导直接录入；
> 年级主任、班主任、任课教师对本模块只有 `read`，数据范围分别按 `DS-05` / `DS-06` / `DS-07` 收窄。
> 年级的删除只有教务主任与租户管理员可用，且仅限「无班级且无学生关系」的年级；删除是逻辑删除，禁止物理删除。
>
> 系统超级管理员（`PER-SUPER-ADMIN`）不受本表限制，可执行全部功能，见 `BR-ORG-014`。

## 3. 术语与逻辑实体

### 3.1 术语

学段、年级、年级组的定义见 `03-glossary.md`。

本模块必须强调两个区分：

| 区分 | 说明 |
|---|---|
| 学段 vs 年级 | 学段是固定的三段（小学 / 初中 / 高中），年级是学段下的具体一层。**对应关系不可配置**（`BR-GRADE-001`） |
| 年级 vs 学年 | 年级由"入学年份 + 学段 + 学段内序号"确定（`BR-GRADE-003`），因此"2026 级高一"与"2026 级高二"是两条不同记录，跨学年不修改，而是新学年对应另一条记录 |

### 3.2 逻辑实体

| 实体 | 含义 | 权威来源 |
|---|---|---|
| 年级 | 某校某学段某入学年份下的第 N 个年级 | 本模块（`edu_grade`） |
| 年级主任任职 | 按学年学期的年级负责关系 | 本模块（`edu_grade_leader`） |

### 3.3 实体关系

```mermaid
erDiagram
  SCHOOL ||--o{ GRADE : "归属"
  GRADE ||--o{ CLASS : "下辖班级"
  GRADE ||--o{ GRADE_LEADER : "年级主任任职"
  TERM ||--o{ GRADE_LEADER : "学年学期"
  TEACHER ||--o{ GRADE_LEADER : "担任"
```

|---|---|---|

### 4.6 归档与删除

| 编号 | 需求 | 规则依据 |
|---|---|---|
| `REQ-GRD-028` | 年级下存在班级或学生关系时**不允许删除**，只允许归档 | `BR-GRADE-005` |
| `REQ-GRD-029` | 归档后年级不在新建班级的可选列表中，但历史数据与统计仍可查 | `BR-GRADE-005` |
| `REQ-GRD-030` | 年级禁止物理删除，数据库层不得开放删除语句 | `NFR-DATA-02`、`BR-AUDIT-003` |
| `REQ-GRD-031` | 删除与归档必须二次确认并填写原因，写入审计 | `BR-AUDIT-001` |

权限与前置条件（2026-09-30，CR-005 / `GAP-036`）：删除由教务主任与租户管理员执行，
且仅在年级下**无班级且无学生关系**时可用；存在引用时接口直接拒绝并提示改用归档；
归档由教务主任执行。两者都必须二次确认并填写原因，并写审计（`REQ-GRD-035`、`REQ-GRD-036`）。

### 5.2 数据范围

| 角色 | 范围编号 | 落地方式 |
|---|---|---|

### 5.3 拒绝规则

| 规则 | 落地要求 |

| `DS-DENY-08` | 班级数、在读学生数统计受范围约束 |
| `DS-DENY-05` | 教育数据权限独立实现，不继承租户管理员的放行逻辑 |

## 12. 待确认事项

本模块未发现阻塞性缺项。以下三处属于设计选择，已于 2026-09-30 经用户确认：

| 序号 | 事项 | 当前写法 | 备选 | 结论（2026-09-30） |
|---|---|---|---|---|
| 1 | 年级名称是否允许人工微调 | 允许，默认按"入学年份 + 学段 + 序号"生成 | 强制生成，不可修改 | **已确认**：允许微调 |
| 2 | 年级主任是否允许多名 | 允许，可标记一名主要负责人 | 只允许一名 | **已确认**：允许多名 |
| 3 | 年级主任任职是否必须绑定学年学期 | 必须绑定 | 不绑学期，长期有效 | **已确认**：必须绑定，与教师模块同口径 |

另有一项已明确：**学段与学段内序号的映射不可配置**（`BR-GRADE-001`、`BR-GRADE-006`），
小学 1–6、初中 1–3、高中 1–3，超范围直接拒绝。
