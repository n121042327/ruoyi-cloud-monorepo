## 1. 验收怎么进行

三层验收（需求 / 实现 / 交付），本轮只做**需求验收**。
用例状态五选一：`通过` / `失败` / `未执行` / `不适用` / `已失效`。
缺陷分级与通过判定与 `modules/student/acceptance.md` 一致：P0 与 P1 未关闭时不得判定通过。

## 2. 测试数据与账号准备

### 2.1 必备账号

| 账号 | 角色 | 数据范围 | 用途 |
|---|---|---|---|
| `ops_admin` | 平台运营 | 全平台 | 跨租户与留痕用例 |
| `t_admin_a` | A 校租户管理员 | A 校组织配置 | 主流程用例 |
| `s_leader_a` | A 校校领导 | A 校 | 只读用例 |
| `academic_a` | A 校教务主任 | A 校 | 只读与下拉清单用例 |
| `teacher_1` | A 校任课教师 | 高一(1)班数学 | 只读用例 |

### 2.2 必备数据

| 数据 | 数量 | 说明 |
|---|---|---|
| 学校租户 | 2 个（A 校、B 校） | 跨校用例 |
| 独立学校租户 | 1 个（C 校，无集团） | 跨根租户用例 |
| 学科 | A 校 9 个标准学科 + 1 个自定义学科 | 选科角色用例 |
| 学段启用 | A 校：小学 4 科、初中 8 科、高中 9 科 | 学段启用用例 |
| 参与选科学科 | 物理（首选）、历史（首选）、化学 / 生物 / 思想政治 / 地理（再选） | 选科角色用例 |
| 被引用学科 | 数学（有任教关系与教学班）、物理（有学生选科） | 引用检查用例 |
| 未被引用学科 | 自定义学科 1 个 | 删除用例 |

### 2.3 前置系统能力

## 4. 权限与数据范围验收用例

任何一个失败即判定本模块不通过。

| 用例 | 场景 | 期望结果 |
|---|---|---|
| `AC-SUB-101` | 缺 `tenant_id` 调用学科列表 | 拒绝，不返回数据 |
| `AC-SUB-102` | 缺 `school_id` 且角色不是平台运营 | 拒绝 |
| `AC-SUB-103` | 数据范围为空的账号调用列表 | 返回空列表，不返回全量（`DS-DENY-03`） |
| `AC-SUB-104` | A 校账号按 B 校学科 ID 请求详情 | 返回空 / 无权限并记录拒绝原因 |
| `AC-SUB-105` | 教务主任尝试修改选科角色 | 拒绝（只读） |
| `AC-SUB-106` | 集团租户管理员为下属学校维护学科 | 允许（`DS-10`） |
| `AC-SUB-107` | 批量化学段启用时含一条越权学段 | 整体拒绝并说明原因（`DS-DENY-06`） |
| `AC-SUB-108` | 引用检查计数接口用不同账号调用 | 计数随数据范围变化（`DS-DENY-08`） |
