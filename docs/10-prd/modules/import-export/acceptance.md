## 1. 验收怎么进行

三层验收，缺一层不算通过：

| 层次 | 谁执行 | 何时 | 判定 |
|---|---|---|---|
| 需求验收 | 用户 + 产品 | 本批次现在 | 逐条确认需求本身是否写对、是否够用 |
| 实现验收 | 开发 + 测试 | 阶段 6 / 7 完成后 | 按本文件用例逐条执行 |
| 交付验收 | 用户 + 业务方 | 阶段 8 | 真实数据走通主流程 |

本批次只做**需求验收**：确认 `PRD.md` 中的 52 条需求与下列验收要点是否可接受。

### 1.1 状态口径

用例状态只允许五选一：`通过` / `失败` / `未执行` / `不适用` / `已失效`。
不得把"代码写完"记为"通过"。

### 1.2 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 阻塞 | 越权、数据错乱、主流程不可用 | 必须修复后才能通过本批 |
| P1 严重 | 关键功能不可用或有绕行成本 | 必须修复后才能通过本批 |
| P2 一般 | 非关键功能异常、体验问题 | 可带缺陷通过，登记到 `known-issues.md` |
| P3 轻微 | 文案、样式细节 | 可带缺陷通过 |

任何 P0 与 P1 未关闭时，本模块不得判定通过。

## 4. 权限与数据范围验收用例

| `AC-IMP-108` | 租户管理员调用导入或导出接口 | 拒绝 |
