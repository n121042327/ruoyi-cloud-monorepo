## 0. 怎么读这份文档

本文件只定义**教师管理模块特有的需求**。角色、业务规则、权限矩阵、字段定义、非功能指标一律
引用公共前置的编号，不复制正文。需求编号 `REQ-TCH-xxx`，一经发布不得重排。

本模块与另外两个模块强耦合，阅读时注意边界：

| 内容 | 归属 |
|---|---|
| 教师主体、教育角色、任教关系、教师账号 | 本模块 |
| 班主任字段（`edu_class.head_teacher_id`）的写入入口 | 班级管理模块，本模块只做角色视图 |
| 年级主任任职（`edu_grade_leader`）的年级侧语义 | 年级管理模块，本模块负责选择人与任职 |
| 教师给学生布置任务、题库、作业 | 首轮不做 |

## 1. 模块定位与范围

### 1.1 解决什么问题

教师管理要回答三个问题：**谁在这个学校教书、他担任什么教育角色、他教哪些班。**

这三个答案直接决定数据权限。`BR-TEACHER-005` 规定教育角色与任教关系共同决定数据范围，
所以教师模块不是一张人事表，而是权限模型的输入源之一。教师数据错一行，
就会有人多看到或看不到整班学生。

现状痛点：

1. 任教关系靠线下排课表，系统里没有依据，导致"任课教师能看哪些班"无法自动判定
2. 教师跨校任教时，权限按"所属学校"而不是"任教学校"判定，会造成越权或无权
3. 年级主任、班主任这类角色与具体年级、班级绑定，手工维护易漏易错

### 1.2 范围内

| 能力 | 说明 |
|---|---|
| 教师列表与检索 | 多条件筛选、关键字检索、排序、分页 |
| 教师详情 | 基本信息、教育角色、任教关系、账号、变更记录 |
| 新增与编辑教师 | 含工号唯一性与字段级权限控制 |
| 教育角色分配 | 校领导、教务主任、年级主任、班主任（班主任入口在班级模块） |
| 任教关系管理 | 学年学期 + 学科 + 班级的授课关系，支持批量设置 |
| 教师账号 | 登录名、初始密码、停用 |
| 离职与调离 | 状态登记与历史保留 |
| 批量导入导出 | 模板、校验、异步执行、按范围导出 |
| 审计 | 关键写操作与角色变更留痕 |

### 1.3 范围外

| 不做 | 归属 |
|---|---|
| 班主任的指定与解绑界面 | 班级管理模块（字段权威来源在 `edu_class`） |
| 年级与班级本身的维护 | 年级管理 / 班级管理模块 |
| 学科清单维护 | 学科配置模块 |
| 教师考勤、排课、课时统计、绩效 | 首轮不做 |

| 移动端与 Pad 教师端 | 后续阶段 |

## 3. 术语与逻辑实体

### 3.1 术语

教师、工号、教育角色、任教关系的定义见 `03-glossary.md`。

本模块需要强调三个区分：

| 区分 | 说明 |
|---|---|
| 所属学校 vs 任教学校 | 教师的组织归属是一所学校，但可在多所学校任教。**数据范围按任教学校判定**（`BR-TEACHER-002`） |
| 教育角色 vs 系统角色 | 教育角色（校领导 / 教务主任 / 年级主任 / 班主任 / 任课教师）决定**数据范围**；系统角色决定**功能权限** |
| 任教关系 vs 排课 | 任教关系是"某学期某学科某班由某教师授课"的稳定事实，不含上课时间与教室 |

### 3.2 逻辑实体

| 实体 | 含义 | 权威来源 |
|---|---|---|
| 教师主体 | 教职工这个人 | 本模块 |
| 教师与学校关系 | 教师可跨校任教形成的多对多关系 | 本模块（由任教关系与教育角色共同体现） |
| 教育角色记录 | 学校级角色（校领导 / 教务主任） | `edu_user_role`（本模块写入） |
| 年级主任任职 | 按学年学期的年级负责关系 | `edu_grade_leader`（本模块写入） |
| 任教关系 | 学年学期 + 学科 + 班级的授课关系 | `edu_teaching_assignment`（本模块写入） |
| 教师账号 | 登录名与状态 | 本模块 + `sys_user` |
| 教师变更记录 | 关键字段与角色的变更留痕 | 审计模块 |

### 3.3 实体关系

```mermaid
erDiagram
  TEACHER ||--o{ USER_ROLE : "学校级教育角色"
  TEACHER ||--o{ GRADE_LEADER : "担任年级主任"
  TEACHER ||--o{ TEACHING_ASSIGNMENT : "任教关系"
  TEACHING_ASSIGNMENT }o--|| TERM : "学年学期"
  TEACHING_ASSIGNMENT }o--|| SUBJECT : "学科"
  TEACHING_ASSIGNMENT }o--|| CLASS : "行政班或教学班"
  TEACHER ||--|| TEACHER_ACCOUNT : "登录账号"
  CLASS }o--|| TEACHER : "班主任（字段在班级侧）"
```

> 班主任不出现在本模块的写入路径里。它的权威来源是 `edu_class.head_teacher_id`（`DP-01`），
> 本模块只展示"该教师担任哪些班的班主任"这一只读视图。

**筛选控件与行为**

| 筛选项 | 控件 | 默认值 | 约束 |
|---|---|---|---|
| 学校 | 下拉选择 | 当前上下文学校 | 仅平台运营可选；其他角色锁定为只读显示（教师数据不跨校共享，`BR-DATA-018`） |
| 教育角色 | 多选 | 空 | 选项取自 `edu_role` 枚举 |
| 任教年级 | 多选 | 空 | 只列出数据范围内的年级 |
| 任教班级 | 多选 | 空 | 只列出数据范围内的班级 |
| 任教学科 | 多选 | 空 | 选项取自 `subject_code` 枚举 |
| 在职状态 | 单选 | 在职 | 在职 / 离职 / 调离 |
| 关键字 | 单行输入 | 空 | 工号或姓名 |

**异常与边界**

| 情况 | 行为 |
|---|---|
| 用户没有任何教师数据范围 | 显示"当前账号没有可查看的教师数据" |
| 筛选无结果 | 显示空态与"清空筛选条件" |
| 请求缺少租户上下文 | 直接拒绝（`DS-DENY-01`） |
| 教师跨校任教 | 同一教师在不同学校各占一行，行内显示任教学校；不做跨校合并展示 |

## 5. 权限需求

### 5.1 功能权限

权威来源为 `05-permission-matrix.yaml`。本模块涉及的资源与操作：

| 资源 | 操作 | 说明 |

| `data.export` | export | 导出 |
| `data.async_task` | read | 异步任务进度 |
| `audit.log` | read | 变更记录 |

### 5.2 数据范围

| 角色 | 范围编号 | 落地方式 |
|---|---|---|
| 平台运营 | `DS-01` | 超级租户；导出需独立授权 |
| 租户管理员 | `DS-02` / `DS-10` | 本租户组织配置；可维护教师主体与角色，不含教学数据 |
| 校领导 / 教务主任 | `DS-04` | 本校全部教师 |
| 年级主任 | `DS-05` | 通过 `edu_grade_leader` 解析负责年级，再反推该年级的教师与任教关系 |
| 班主任 / 任课教师 | `DS-06` / `DS-07` | 只读本人信息 |

**跨校任教的处理**：教师的数据范围按**任教学校**判定（`BR-TEACHER-002`）。
一名教师在 A 校任教、在 B 校仅挂名而无任教关系时，B 校的教务主任看不到他的任教明细。
跨校可见只来自平台运营的 `DS-01` 全平台范围（只读并留痕）；共享授权只针对教学资源，不放开教师数据（`BR-DATA-018`）。

### 5.3 字段级权限与脱敏

| 字段 | 默认展示 | 全量展示条件 |
|---|---|---|
| 姓名 / 工号 | 全量 | — |
| 手机号 | 掩码（中间 4 位） | `read_contact` |
| 邮箱 | 全量 | — |
| 身份证号（若后续补录） | 掩码 | `read_sensitive` |

### 5.4 拒绝规则

严格遵守 `08-data-scope-model.md` 第 5 节：`DS-DENY-01` ~ `DS-DENY-09`。
本模块特别需要落实的两条：

| 规则 | 落地要求 |
|---|---|
| `DS-DENY-06` | 批量设置任教关系时逐条校验范围，任一条越权则整体拒绝 |
| `DS-DENY-08` | 教师人数统计、任课班级数统计同样受范围约束 |
