# 页面字段布局约束（表单 / 表格通用）

用户于 2026-10-01 明确要求加入约束。适用于生成或修改的页面、表单、表格、列表、详情和查询条件；既有冻结版本通过变更单产生新版本，逐批验收。

## 1. 语义分组

- 按业务含义分组，同组只包含同一主题字段。组名统一使用基础信息、联系方式、教育信息、职业信息、账户信息等；业务专用组名须表达明确主题，并在同类页面保持一致。
- 不同组不得交叉掺杂：基础信息不得混入职业字段，教育信息不得混入公司字段。同义字段相邻。
- 同一信息不得在多个组重复展示；必要的只读引用须标注来源或引用性质。

## 2. 组内顺序

- 按业务逻辑和用户认知排列：先父级、后子级，先主信息、后补充信息，开始时间在结束时间前。
- 层级字段按学校 → 校区 → 年级 → 班级、国家 → 省 → 市 → 区、公司 → 部门 → 职位排列；页面不存在的字段不强行补造。
- 联动字段相邻，条件字段紧跟触发字段；禁止学校 → 公司 → 校区等无逻辑跳转。
- 学年学期作为教育信息的时间上下文，放在年级、班级之前；班级列表顺序为学校 → 校区 → 学年学期 → 年级。
- 必填优先是建议，不是硬性排序：只有不破坏语义分组、依赖顺序和主次关系时，才将必填项置前。
- 显示顺序不自行定义业务联动：下拉选项是否按父级收窄必须依据已确认规则；缺少依据按根级缺项流程处理。

## 3. 表单、详情与查询条件

- 使用分组标题、卡片或分节区；每组内部遵守上述顺序。只读详情采用相同业务分组。
- 提交、重置、搜索等操作区独立，不混入字段组。
- 换行或响应式布局仍保持阅读与键盘顺序，不为填满一行插入其他组字段。

## 4. 表格

- 列顺序与表单和业务分组顺序一致，同组列相邻；列表只展示部分字段时，保留这些字段的相对顺序。
- 可用分组表头、列分隔或颜色辅助识别，但不能只靠颜色区分。
- 禁止为了列宽或列数把不同语义列插入同组。
- 操作列固定最右或最左，独立分组。调整列顺序时须同步行数据、列配置、导出和依赖列位置的交互。

## 5. 自检与验收

每批交付记录：每个字段属于哪个组、组内是否同主题、是否跨组掺杂、依赖顺序是否正确、表单与表格顺序是否一致；不适用项注明理由。不得仅凭已写规则声称全部既有页面通过。
