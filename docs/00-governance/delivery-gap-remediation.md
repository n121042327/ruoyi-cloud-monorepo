## 4. 已确认方案：编班 Excel 的具体列

**这是什么：** 约定学校工作人员上传编班表时必须填写什么；这里的 4 列目前只是原型推荐值。

| 列名 | 推荐要求 | 用途 |
|---|---|---|
| 学号 | 必填 | 识别学生，不能仅靠姓名识别人 |
| 姓名 | 选填 | 供工作人员核对；姓名不一致如何处理还需检查既有校验规则 |
| 目标班级 | 必填 | 指定学生要进入的班级；以哪个标识准确定位须与接口和同名班级规则核对 |
| 班级类型 | 选填，默认行政班 | 沿用原型推荐；不据此授权新的教学班编班入口 |

**不选会怎样：** 下载模板与上传校验可能各用一份定义，学校下载的表格未必能按同一规则导入。

**可选项：**

- A：以以上 4 列为基础，经变更申请补入 PRD；明确定位和核对规则后同步模板、校验与验收。
- B：仅确定“学号 + 目标班级”两列，移除可选列的方案先写入变更申请，取得确认后再改原型。
- C：暂不确定，保留 GAP-056，暂停依赖该列定义的模板下载与导入校验实现。

**推荐：A。** 与学生、教师模板的文档口径一致，且可以沿用现有原型；不能把确认列名理解成批准尚未定义的校验行为。

**位置：** `D:/work/person_work/ruoyi-cloud-monorepo/docs/10-prd/modules/class/PRD.md` 第 234 行；`D:/work/person_work/ruoyi-cloud-monorepo/prototypes/functional/v1/pages/class-import-roster.html` 第 79—82 行。

**验收方法：** PRD、模板示例、下载列定义和上传校验一致；学号准确定位学生，目标班级限定本校有效范围；同名班级和姓名不一致的处理有明确依据。
