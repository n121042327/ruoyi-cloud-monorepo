# CR-121 — 阶段 6 第四十批：学籍异动登记与审批

自动化队列第 5 项。`EduEnrollmentController` 的 `POST /edu/enrollment/change`（异动登记）与
`POST /edu/enrollment/change/{id}/approve`（异动审批）此前前端只接了列表查询。

## 1. 交付内容

| 层 | 内容 |
|---|---|
| api 层 | 补 `addEnrollmentChange` / `approveEnrollmentChange` 两个函数 |
| 类型 | 补 `EnrollmentChangeForm` / `EnrollmentApproveForm`（对齐 `EduEnrollmentChangeBo`）；`EnrollmentChangeVO` 补 `approvalStatus` |
| 弹窗 | 新增 `EnrollmentApproveDialog`（通过 / 驳回 + 审批意见，驳回强制填意见） |
| 页面 | 异动历史列表操作列加「审批」（仅 `approvalStatus === 'pending'` 时出现，权限 `enrollment.status:approve`），列宽 100 → 160 |

保留原有的「查看」入口（只读详情弹窗）。

## 2. 口径

- **登记**：`addEnrollmentChange` 是追加式写入（BR-PROMO-012 不更新不删除），api 已接；
  入口沿用学生列表的「学籍异动」弹窗（`StudentStatusDialog`，CR-118 已交付），异动历史页只做查看与审批。
- **审批**：只有 `approvalStatus === 'pending'` 的记录显示审批入口。按 REQ-PRM-043 的口径，
  退学 / 开除 / 死亡三类异动需要校级管理员审批；弹窗里 `approved=true` 为通过，`false` 为驳回，
  **驳回时必须填写审批意见**（前端表单校验），通过时意见选填。
- **审批不可撤销**：审批动作写审计（后端 `@Log(title = "学籍异动审批")`），前端不做撤销入口。
- 审批状态没有单独成列：高保真异动历史表是 9 列（学号 / 姓名 / 异动类型 / 生效日期 / 原状态 / 新状态 /
  操作人 / 原因 / 操作），没有审批状态列；状态通过操作列的按钮是否出现来体现，避免破坏列对齐
  （`check_fe_page_structure.py` 对这张表有对照条目）。
