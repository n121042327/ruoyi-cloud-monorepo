# CR-132 — 阶段 6 第五十一批：导入导出链路请求 / 响应形状对齐

第三轮队列第 1 项，收口 GAP-109。前端导入导出 api 层此前是按猜测形状写的，与 `openapi.yaml` + 后端 VO 全面不一致，
导致导入向导、学生导入、编班表导入、教师导入四条链路「页面齐全、按钮可点、调用必失败」。

## 1. 逐项对照

| 端点 | 契约 / 后端 | 修正前前端 | 修正后 |
|---|---|---|---|
| `POST /edu/import/validate` | `application/json`，`EduImportValidateBo(moduleCode/fileId/strategy)` | multipart + `file` + `module/duplicatePolicy` | 先 `POST /resource/oss/upload` 拿 `ossId`，再 JSON 提交 |
| `GET /edu/import/template/{module}` | `R<EduFileRefVo>`（signedUrl） | `responseType: 'blob'` | 解析引用后跳 signedUrl |
| `GET /edu/import/{batchNo}/failed-rows`、`/result` | `R<EduFileRefVo>` | blob | 同上 |
| `GET /edu/async-task/{taskNo}/file/{fileId}` | `R<EduFileRefVo>` | blob | 同上 |
| `POST /edu/export` | `R<EduExportResultVo>`（同步带 file 引用，超限转异步），入参 `moduleCode` | `responseType: 'blob'`，入参 `module` + 非契约字段 `teacherId` | JSON，`moduleCode`，教师筛选走 `filters` JSON |
| 模板清单 | `moduleCode/templateVersion/columnCount` | `module/version/columns` | 按后端 VO |
| 校验结果 | `rowTotal/invalidRows[].failReason` | `totalCount/errors[].errorMsg` | 按后端 VO |
| 异步任务 | `taskStatus/progressPercent/ownerName/durationSeconds` | `status/progress/owner/elapsed` | 按后端 VO |

## 2. 改动面

- `api/edu/importExport/types.ts`：按后端 VO 重写类型，新增 `OssUploadVO` / `EduFileRefVO` / `ImportExportResultVO` / `ImportValidateForm`。
- `api/edu/importExport/index.ts`：新增 `uploadImportFile`；`validateImportFile` 改 JSON；四个下载改返回 `EduFileRefVO`；`exportData` 改 JSON + `moduleCode`。
- `api/edu/teacher/index.ts`：`importTeacherValidate` 改 JSON（教师端点服务端钉 `moduleCode=teacher`）；`downloadTeacherImportTemplate` 改返回 `EduFileRefVO`。
- 新增 `utils/eduFileRef.ts`：统一用 `signedUrl` 触发下载，处理 `hint`（模板过期强提示）与缺失链接。
- 页面：`imp_wizard`、`stu_import`、`cls_roster_import`、`tch_import`、`imp_task_list`、`tch_assign`。
- 编班表导入 `IMPORT_MODULE = 'class_roster'`（与 DDL 列注释、后端 `importRosterValidate` 一致）。
- 教师「设置任教」页与 `tch_assign` 的导出改用 `moduleCode: 'teaching_assignment'`（下划线风格，与其他模块编码一致）。
