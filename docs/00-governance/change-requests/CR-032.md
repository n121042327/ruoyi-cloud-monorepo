# CR-032 — 架构图 Mermaid 渲染缺陷修复

用户于 2026-10-02 指出 `docs/30-architecture/02-architecture.md` 的「架构分层（逻辑视图）」渲染报错：
`Lexical error on line 18. Unrecognized text. ... end subgraph 能力层（公共组件） TENANT["r`。

## 原因

该图的 `subgraph` 标题未加引号，Mermaid 按标识符解析标题；全角括号 `（`、`）` 不是合法标识符字符，解析在 `能力层（公共组件）` 处中断，整张图渲染失败。同一份图在 `docs/30-architecture/diagrams/logical.mmd` 与 `docs/diagrams.md` 里各有一份副本，也需要一致处理。

## 改动

1. `docs/30-architecture/02-architecture.md`：两个代码块的 `subgraph` 全部改为 `subgraph <ascii_id>["标题"]`（client / access / business / capability / storage / browser / host / external）。标题文字未改，「能力层（公共组件）」保持原文。
2. `docs/30-architecture/diagrams/logical.mmd`：`接入层` / `业务层` / `能力层` 三个分组原先共用同一个 id `access`（解析能过，但三个分组 id 重复，一旦有跨分组的边就会挂错锚点），改为 `access` / `business` / `capability`，与 `02-architecture.md` 的副本一致。
3. `docs/diagrams.md`：由 `tools/make_diagrams_doc.py` 重新生成（41 张图），与 `.mmd` 源文件同步。
4. 新增 `tools/check_mermaid.py`：不依赖 Node 的静态检查，扫出「`subgraph` 标题既没加引号、又含有 Mermaid 不接受的字符（括号 / 方括号 / 逗号 / 冒号 / 斜杠等）」的写法并给出改法。覆盖全部 `*.mmd` 与 Markdown 里的 mermaid 代码块。

## 验证

用真实 Mermaid 解析器（`mermaid@10` + `jsdom`，装在临时目录，未写入仓库依赖）遍历仓库全部 103 张图逐个 `mermaid.parse`：修复前 1 张失败（正是用户报的那张），修复后 0 张失败。语法对照确认：`subgraph id["标题"]` 与纯中文标题合法，`subgraph ["标题"]`、`subgraph 标题（含括号）` 非法。静态检查 `python tools/check_mermaid.py` 全仓库通过；负例自检确认它能抓到这一写法（报 1 项问题、退出码 1），改写成引号形式后通过。

详见 `evidence/governance/2026-10-02_mermaid-check.log`。

## 边界

`tools/check_mermaid.py` 是静态规则检查，只覆盖「subgraph 标题含危险字符」这一类；重复 id、节点与边的语法错误仍需用真实解析器复跑，本批未把它接成 CI 步骤（仓库目前没有 CI 门禁要求）。Node 与 mermaid 未加入仓库依赖，`package.json` 未改动。
