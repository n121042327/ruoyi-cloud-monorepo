# CR-097 — 阶段 7 第十八批：补 ruoyi-edu 的网关路由（否则前端访问不到 /edu/**）

排查「哪些 API 走 Spring WebFlux」时发现：`script/config/nacos/ruoyi-gateway.yml` 与
`ruoyi-gateway-mvc.yml` 的路由清单里只有 auth / gen / system / resource / workflow / warm-flow /
demo / test-mq，**没有 `ruoyi-edu`**。edu 服务虽然在 compose 里起来了（CR-096），
但外部请求 `/edu/**` 到网关后没有任何路由能匹配，前端调不通——CR-096 的部署链路实际少了一环。

## 改动

| 落点 | 说明 |
|---|---|
| `script/config/nacos/ruoyi-gateway.yml`（改） | 路由清单新增 `ruoyi-edu`：`uri: lb://ruoyi-edu`、`predicates: - Path=/edu/**`、**不加 `StripPrefix`** |
| `script/config/nacos/ruoyi-gateway-mvc.yml`（改） | 同上（两个网关实现的路由清单保持一致，切换网关不用重配） |

## 为什么 edu 这条不能写 StripPrefix（关键口径）

网关现有路由的 `StripPrefix=1` 是**因为下游服务的内部路径不含该前缀**：例如路由 `Path=/system/**`
配 `StripPrefix=1`，而 `SysUserController` 自身的映射是 `@RequestMapping("/user")`，
所以 `/system/user/list` 到下游时被剥成 `/user/list` 才能匹配。

教育域不一样：edu 的控制器映射**本身就带 `/edu`**（`EduClassController` 是 `@RequestMapping("/edu/class")`、
`EduStudentController` 是 `/edu/student`、`EduExportController` 是 `/edu`……与 `openapi.yaml` 的路径逐字一致）。
所以 edu 这条路由必须**不加 `StripPrefix`**，让 `/edu/class/list` 原样转发；一旦加了 StripPrefix=1，
下游会收到 `/class/list` 而全部 404。
