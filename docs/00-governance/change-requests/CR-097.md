## 为什么 edu 这条不能写 StripPrefix（关键口径）

网关现有路由的 `StripPrefix=1` 是**因为下游服务的内部路径不含该前缀**：例如路由 `Path=/system/**`
配 `StripPrefix=1`，而 `SysUserController` 自身的映射是 `@RequestMapping("/user")`，
所以 `/system/user/list` 到下游时被剥成 `/user/list` 才能匹配。

教育域不一样：edu 的控制器映射**本身就带 `/edu`**（`EduClassController` 是 `@RequestMapping("/edu/class")`、
`EduStudentController` 是 `/edu/student`、`EduExportController` 是 `/edu`……与 `openapi.yaml` 的路径逐字一致）。
所以 edu 这条路由必须**不加 `StripPrefix`**，让 `/edu/class/list` 原样转发；一旦加了 StripPrefix=1，
下游会收到 `/class/list` 而全部 404。

## 附带修正：`ruoyi-job` 的 `BillDTO.java` → `BillDto.java`

`9af6eab` 里除了网关路由，还带进了一个「非本意但正确」的改动：`ruoyi-modules/ruoyi-job` 的实体文件
从 `BillDTO.java` 变成 `BillDto.java`（git 判定为 100% 相似度重命名，内容零改动）。说明：

- 该文件在 `main` 上叫 `BillDTO.java`，但文件内容声明的是 `public class BillDto`——**文件名与 public 类型名大小写不一致**。
- 这在大小写不敏感的 Windows 文件系统上能编译通过，但**在 Linux/macOS 上 javac 会直接报错**（"class BillDto is public, should be declared in a file named BillDto.java"），
  而 `script/docker/*` 里的镜像构建都是 Linux 容器、在 Linux 上执行 `mvn package`——也就是说这处迟早会炸在 Linux 构建或 CI 上。
- 重命名后 **`ruoyi-job` 编译 BUILD SUCCESS**（`mvn -o -DskipTests -pl ruoyi-modules/ruoyi-job -am compile`）。
- 全仓库扫描（脚本比对「文件名 vs 文件内 `public class/interface/enum/record` 名」，大小写敏感）：
  **0 处不一致**，即这是唯一一处。
- 仓库内无 `.github/workflows`，所以此前不会有 CI 报错把这处暴露出来。
