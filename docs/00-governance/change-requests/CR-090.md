## 口径（与 PRD / BR 对齐）

- **默认只展示本人发起的任务**（`REQ-IMP-032` / `BR-IMP-014`）：`ownerId` 未传时按 `LoginHelper.getUserId()` 收窄；非平台范围显式传他人 `ownerId` 直接拒绝。
- 平台运营（`DS-01`）按 `LoginHelper.isSuperAdmin()` 放行，可传 `ownerId` 精确过滤或留空查全平台；这不算「共享授权」，与 `BR-DATA-018` 的只读教学资源授权无关。
- **状态推进** `queued → running → succeeded / partial_failed / failed`（`REQ-IMP-034`）：**只有 `queued` 可取消**，**只有 `failed` / `partial_failed` 可重试**，其余状态一律拒绝并给出当前状态。
- **重试沿用原任务号与批次号**，即沿用原幂等键，不产生重复数据（`REQ-IMP-037` / `BR-IMP-009`）；最大重试次数默认 3（`REQ-IMP-039`，`RV-IMP-04` 已裁决「可配置」），本批落常量并在本 CR 记录待接配置中心。
- **超过最大重试次数转死信**（`REQ-IMP-038` / `NFR-MQ-03`）：写 `edu_dead_letter_task` 并把任务置 `dead`；死信**重放原因必填（≥ 5 字）**、状态置 `replayed` 并回写任务为 `queued`；**重放记录只追加，不提供删除入口**。
- **结果查询与文件下载都重新解析数据范围**，不复用发起时的判定（`REQ-IMP-036` / `DS-DENY-04` / `DS-DENY-07`）。
- **文件有效期**：结果文件默认 7 天（`BR-IMP-013` / `RV-IMP-03`），过期下载一律拒绝；任务元数据保留 90 天（`REQ-IMP-040`，归档动作归审计 / 运维批次）。
- 下载返回**短时签名链接描述**，有效期 5 分钟，每次下载 `download_count + 1`（`REQ-IMP-042` / `043`）。
- 取消 / 重试 / 重放原因都要求 ≥ 5 个字，`@RepeatSubmit()` 防重复提交，写接口全部带 `@Log`。

## 边界与下一步

- **新增 GAP-093**：`ruoyi-edu` 的 `pom.xml` 没有引入 `ruoyi-common-oss`，无法签发真实短时签名链接。
  本批按推荐方案（远程文件服务契约）先落地 `edu_file_ref` 引用表、有效期判断、范围重解析与下载计数，
  `buildSignedUrl` 只返回 `storage_key` 描述；签发动作在文件服务那一批替换。
- **审计留痕待接**：`REQ-IMP-043`（下载写审计）与 `REQ-IMP-038`（重放写审计）需要 `edu_audit_log`，
  该表属队列第 7 项的审计模块，本批在代码注释与 GAP-093 / 本 CR 标注，不伪造审计记录。
- `recordRetryResult` 与 `moveToDeadLetter` 是给导入导出执行器用的**非契约内部方法**，不对应端点；
  导入导出引擎（模板 / 批次 / 行结果 + 全部 `export*` 端点）是队列第 6 项的下半段。
- `EduAsyncTaskVo.ownerName` 需要连接 `sys_user`，随 `*Mapper.xml` 在后续批次补齐（与 CR-089 的展示字段同类）。
