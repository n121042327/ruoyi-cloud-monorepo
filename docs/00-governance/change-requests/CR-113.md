# CR-113 — 阶段 6 第三十二批：教育域页面对齐高保真（page-head 全量）+ 接口契约纠偏

用户要求：「所有前端页面应该和高保真页面保持一致」「前后端联调的功能，如果没有对接可以对接了」。

## 1. 盘点结论

| 检查项 | 结果 |
|---|---|
| 45 条路由的 view 文件 | 全部存在（`PAGE-CLS-MERGE` 高保真未提供，见 D-087） |
| 高保真 41 个业务页 ↔ 生产 41 个页面 | 数量对齐；**「班级详情」（`class-detail.html`）在生产前端没有对应实现** |
| `.page-head` 页面标题区 | 高保真 44 页全有；**生产此前只有学校管理页有（CR-107）**，其余 40 页从查询区直接开始 —— 这是最系统的不一致 |
| 前端调用 ↔ 后端接口 | 前端 129 个调用中 **7 个 method 与 openapi/后端不一致（会 404）**；另有 **56 个后端接口前端尚未接入** |

## 2. 本批处置（第一部分：视觉骨架对齐）

按 `docs/40-detailed-design/frontend-page-tree.yaml` 的 `high_fidelity_file` 映射，为 **39 个页面**补齐
与高保真同构的页面标题区：

```html
<div class="page-head">
  <h1>学生管理</h1>
  <span class="scope-hint">数据范围：本校 · 全部年级 · 含历史状态</span>
  <el-tag type="primary">共 {{ total }} 名学生</el-tag>
</div>
```

- 标题、数据范围、状态标签的内容**以高保真为准**，但按 CR-112 的口径**去掉内部编号**
  （例：高保真 `数据范围：本校（DS-04）· 只读` → 生产 `数据范围：本校 · 只读`）。
- 高保真里带具体样例数字的标签（`共 137 名学生`、`列表数据截止 2026-09-30 10:12`）改为真实值或省略：
  数量类统一用列表已有的 `total`；「数据截止时间」这类样例元数据不进入生产页（真实系统数据是实时的）。
- 同一页里与新标题重复的 `<h2>`（教师任教关系 / 组合分布统计 / 导入向导 / 选科配置 / 学生选科）一并删除。
- `.page-head` / `.scope-hint` 的样式 CR-107 已写入 `src/assets/styles/index.scss`，本批复用。

## 3. 本批处置（第二部分：接口契约纠偏）

系统比对「前端 api 层 `url` + `method`」与「后端 controller `@XxxMapping`」，发现 7 处前端 method 与
`docs/40-detailed-design/api/openapi.yaml`、后端实现**三方不一致**，这些调用目前会 404：

| 前端函数 | 前端原写法 | openapi / 后端 | 修正 |
|---|---|---|---|
| `exportPromotionTask` | GET `/edu/promotion/task/export` | POST（同） | 改 POST，query 转 body |
| `exportPromotionResult` | GET `.../{id}/result/export` | POST（同） | 改 POST |
| `exportPromotionPreview` | GET `.../{id}/preview/export` | POST（同） | 改 POST |
| `updatePromotionItem` | POST `.../{id}/item` | PUT（同） | 改 PUT |
| `batchUpdatePromotionItem` | POST `.../{id}/item/batch` | PUT（同） | 改 PUT |
| `saveStreamConfig` | PUT `/edu/stream/config` | POST（同） | 改 POST |
| `exportStreamSelection` | GET `/edu/stream/export` | POST（同） | 改 POST，query 转 body |

注释里同步写错的 method 描述一并订正。修正后复扫：前端调用中「后端不存在」的只剩 1 条，
且经人工核实为扫描误报（`getStudent` 用字符串拼接 `'/edu/student/' + id`，路径本身正确）。
