# CR-109 — 阶段 6 第二十九批：编辑学校弹窗只读字段的提示处理

用户在浏览器里对「编辑学校」弹窗提了两条批注：

1. 指着「学校编码」下方的提示（`编码变更需单独申请（updateSchoolCode）并写审计；编码是导入 / 导出对照表的键。`）：
   **"这个 tip 不应该出现在界面上吧？？？"**
2. 指着「所属租户」下方的提示（`学校不能跨租户迁移；需要换集团时新建学校并迁移数据。`）：
   **"这个应该出现吧？"**

## 1. 判断口径

两条批注指向同一条规则：**只读字段的"操作说明"不常驻界面，约束说明要保留**。

- 「学校编码」在编辑态是只读（改编码有独立入口 `updateSchoolCode`，不在这个弹窗里），常驻一段"变更需单独申请…"的文案
  既占位又没有可操作对象 → 与高保真的文案保留方式相比，用户的判断更贴合实际使用；
- 「所属租户」的文案是**约束**（不能再改、换集团要新建学校）——用户明确说"应该出现"，保留。

## 2. 改动

| 位置 | 改动 |
|---|---|
| `SchoolFormDialog.vue` 编辑态「学校编码」 | 删除常驻 `.hint`；说明改为 `el-tooltip`（鼠标移到只读输入框上才显示），内容合并为"编码由系统生成（SCH-租户后 6 位）；变更需单独申请 updateSchoolCode 并写审计；编码是导入 / 导出对照表的键。" |
| `SchoolFormDialog.vue` 编辑态「所属租户」 | 不变，保留 `.hint` |

实现细节：tooltip 的 trigger 用一层 `<span class="w-full cursor-help">` 包住禁用的 `el-input`
（禁用的表单控件不派发鼠标事件，直接套在 input 上提示不会触发）。

## 3. 与高保真的差异说明

高保真 `prototypes/high-fidelity/v1/pages/school-list.html` 的编辑弹窗把这两段都写成常驻 `.hint`。
本批按用户批注只调整「学校编码」一处（改为 hover），其余文案与结构保持与高保真一致；
新建弹窗「学校名称」下的文案仍按高保真保留（那里同时说明了"没有编码输入框"的原因，属于解释性文案而非操作指引）。
