# CR-145 — 阶段 7 第六十四批：学生导入执行器 + 补齐学号发号与在校记录（GAP-094 第四批其二）

## 1. 交付

| 组件 | 说明 |
|---|---|
| `IEduStudentService.insertWithEnrollment` | 发号 + 建档 + 在校记录（同一事务），返回新学生 ID |
| `EduStudentServiceImpl`（改） | 用平台级 `SequenceUtils` 发号；`insertByBo` 委托到新方法 |
| `job/StudentImportExecutor` | 学生导入执行器：幂等去重 → 建档 → 监护人 |

## 2. 顺手补上的能力缺口

`insertByBo` 的注释写着「发号与在校记录写入在同一事务内」，但实现既没发号也没写在校记录：
新增出来的学生没有学号、没有在校记录，而学校侧读学生一律经在校记录两段式取数 —— 等于新增完就查不到。
本批把这条路径补齐（人工新增与导入共用同一个方法）。

## 3. 学号格式（D-225）

`入学年份(4) + 6 位全局流水`，由平台级 `SequenceUtils` 发号（按年份分 key，永不回收，BR-STU-001）。
依据：学生 PRD 第 1.3 节把「发号器本身」列为**平台级公共能力，本模块只调用不实现**，格式未冻结；
本批按可读、可排序、平台唯一的规则落地并记录，外部学号与系统学号的对应关系走导入结果的学号对照表（BR-STU-019）。

## 4. 幂等与失败处理

| 情形 | 结果 |
|---|---|
| 证件号 / 全国学籍号已存在 | `skipped`（平台唯一约束，BR-STU-008 / 022） |
| 学生建档成功、监护人写入失败 | `failed` + 原因写进 `edu_import_error`（学生保留，不整行回滚） |
| 行政班 | 不写：导入产生的学生默认不带行政班（REQ-STU-062），编班走班级模块 |
