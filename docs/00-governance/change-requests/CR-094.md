## 口径

- **明文在服务间传递、加密在 provider 做**：远程契约入参是明文新密码，`RemoteUserServiceImpl` 用 `BCrypt.hashpw` 后写库，避免摘要值跨进程传输（GAP-091 的推荐方案）。
- **停用必须同时下线**：`changeAccountStatus` 在状态置为 `1`（停用）时调用 `StpUtil.kickout(userId)`，否则被停用账号仍能用旧 token 访问。
- **跨租户要走 `TenantHelper.dynamic`**：`tenantId` 非空时在动态租户上下文里执行，避免误伤调用方自身租户的数据。
- **教师账号关联**：`edu_teacher.user_id`（该表有这一列）。
- **学生账号关联**：`edu_student` **没有 `user_id` 列**，全库也没有「学生主体 ↔ sys_user」的关联列；学生账号按登录名约定 `s` + 学号 关联（`REQ-STU-023` / `BR-ACCOUNT-002`），因此实现是「取学号 → 拼登录名 → `getUserInfo` 取 userId → `resetPassword`」。**不给 `edu_student` 加列**，也不改冻结的建表脚本（见 D-169、GAP-090）。
- **原因类字段必填**：停用 / 启用原因至少 5 个字，与既有「离职 / 停用必须填原因」口径一致，便于审计追溯。
