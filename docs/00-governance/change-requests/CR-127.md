# CR-127 — 阶段 6 第四十六批：升班就绪检查接入 + 升班明细接口地址修正

第二轮队列第 5 项「升班：就绪检查与明细查询」。核对时发现两个问题：
① 前端 `listPromotionItem` 的 url 写成了任务详情接口；② 新建升班任务页的「能否创建」提示是**本地猜的**，
从没调后端的 readiness 接口。

## 1. 交付内容

| 问题 | 处置 |
|---|---|
| `listPromotionItem` 请求 `/edu/promotion/task/{id}`（详情接口），靠 `withItems: true` 期望明细随详情返回 | 改为 `GET /edu/promotion/task/{id}/item`（后端本来就有这个端点） |
| `prm_create` 的就绪提示由 `form.sourceTermId && form.targetTermId ? '可以创建' : '请先选择…'` 本地判断 | 改为调 `GET /edu/promotion/task/readiness`，按后端返回的 `level` / `message` / 缺失项渲染 |

新增 `getPromotionReadiness` 到 `api/edu/promotion`；`PromotionReadiness` 类型此前已在 `types.ts` 里
（说明当初设计时留了口子，只是没接）。

## 2. 就绪提示的渲染口径

后端 `SchoolSummaryVo` 同级的 `EduPromotionReadinessVo` 返回 `level`（ready / warning / blocked）
与明细字段，前端按下面的映射渲染：

| level | alert 类型 | 标题 |
|---|---|---|
| `ready` | success | 可以创建 |
| `warning` | warning | 可以创建，但请确认 |
| `blocked` | error | 暂不能创建 |
| 未选择学期 | info | 请先选择源与目标学年学期 |

消息体把 `message`、缺失年级、缺失班级数、是否存在未结束任务、源学期在读人数拼成一句话。
**前端不再自行判断能否创建** —— 页面本来就有一句「前端校验不作为安全边界：后端在 addPromotionTask 内重复校验」，
提示口径也应该来自后端，否则两边说法可能不一致。

触发时机：`watch` 源 / 目标学期两个字段，变化即重新检查。

## 3. 影响面

改 `listPromotionItem` 的 url 会影响三个调用方，都是明细列表场景，语义不变（原本就是想要明细）：

- `prm_preview/composables/usePromotionPreview.ts`
- `prm_validate/index.vue`
- `prm_result/index.vue`

改动后它们拿到的仍是 `PromotionItemVO[]`，只是从「详情接口顺带返回」换成「明细接口直接返回」。
