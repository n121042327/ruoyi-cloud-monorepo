## 2. 盘点发现的真问题

### GAP-109 导入导出请求形状与契约不一致

`openapi.yaml` 的 `/edu/import/validate` 写的是 `requestBody: content: application/json`，后端也是
`@Validated @RequestBody EduImportValidateBo`；前端却用 `multipart/form-data` 传 `file`。同理，
后端 `validateImportFile` 的入参是 `moduleCode` / `fileId` / `strategy`，前端发的是 `module` / `duplicatePolicy`，
并且缺少「先上传到统一文件服务拿 `fileId`」这一步（BO 注释写明「文件已先上传到统一文件服务，这里只传 file_id」）。

四个下载端点后端都返回 `R<EduFileRefVo>`（`signedUrl` 短时签名链接），前端一律 `responseType: 'blob'`，
拿到的是 JSON 而不是文件。

**为什么本批不改**：这不是「补一个函数」，而是导入导出三条链路（模板下载 / 上传校验 / 结果下载）的
形状对齐，涉及 `api/edu/importExport/index.ts`、`api/edu/teacher/index.ts`、`api/edu/class/index.ts`
与三个页面（导入向导、学生导入、编班表导入），要一次做完才不留半截。已按缺项流程登记 GAP-109，
下一批整包处理。本批只修了其中唯一无争议的取值错误（模块编码）。

### GAP-110 任教关系导出没有执行器

`exportData({ module: 'teachingAssignment' })` 在通用导出引擎里只创建异步任务，没有任何模块导出器
按该编码产出文件；页面原来提示「已生成任教关系导出文件，开始下载」，属于谎报。本批把提示改为
「已提交任教关系导出任务，请到异步任务中心下载」，并登记 GAP-110。
