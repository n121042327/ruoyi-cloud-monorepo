# CR-133 — 阶段 6 第五十二批：导入导出执行器依赖链裁决 + 人工验收清单

第三轮队列第 2 项（GAP-110 任教关系导出执行器）与第 4 项（人工验收清单）。

## 1. 核对结论：导入导出引擎目前是「地基已落、执行器全缺」

核对 `EduImportExportServiceImpl` 与全模块扫描后确认：

| 能力 | 现状 | 位置 |
|---|---|---|
| 上传后校验 | 只登记批次（`rowTotal=0`）后返回指引，不读文件、不逐行校验 | `EduImportExportServiceImpl.validateImportFile` 第 174—208 行 |
| 确认执行 | 只写一条 `edu_async_task`（`queued`），没有执行者 | 同文件 `executeImport` 第 212—254 行 |
| 任意导出 | 只创建导出任务，`guidance` 里明说「实际取数与文件生成由模块导出器执行」 | 同文件 `exportData` 第 297—336 行 |
| 任务推进 | ruoyi-edu 内**没有任何** `@Scheduled` / `@XxlJob` / MQ 监听，`edu_async_task` 无人消费 | 全模块扫描 |
| 文件服务 | `ruoyi-api-resource` 已引入、`RemoteFileService` 可用（学生照片已走通）；但签名链接仍是占位描述 | GAP-093 |

结论：GAP-110（任教关系导出无执行器）不是孤立问题，而是 GAP-094「解析器 + 逐模块导出器 + xlsx/csv 生成器」的
导出半边。单独给 `teaching_assignment` 补一个导出器解决不了链路 —— 任务没人跑、文件签名链接是占位，
用户依旧拿不到文件。

## 2. 处置

1. **合并缺项**：GAP-110 关闭，并入 GAP-094（同一执行器批次交付），并把本批新增证据追加到 GAP-094 的 resolution。
2. **裁决依赖顺序**（D-213）：先补 GAP-093 的真实短时签名链接与流式下载（含导入导出结果文件），
   再补 GAP-094 的解析器 / 逐模块导出器 / 异步执行器。理由是执行器产出的文件必须能被子系统真实下载，
   否则就是「生成了但拿不到」的半成品。
3. **交付人工验收清单**：`evidence/stage6-frontend/2026-10-10_manual-acceptance-checklist.md`，
   把第二轮与第三轮新增能力（详情抽屉、在校记录段、四类删除、任教关系入口、导入导出形状、学段配置）写成可逐条勾选项，
   并单列「已知不可验收项」及其缺项编号，避免阶段 8 把它们记成回归失败。
