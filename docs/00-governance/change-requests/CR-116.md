## 2. 暴露并修复结构检查器的 `<thead>` 缺陷

`tools/check_fe_page_structure.py` 解析原型表头用的是 `<th([^>]*)>`，这个正则会**先命中 `<thead>`**，
把 `<thead>` 到第一个 `</th>` 之间的内容当成一列。后果是**原型表首列被静默吞掉**：
生产页明明少一列，检查器却报「一致」。

修成 `<th\b([^>]*)>` 后，之前被掩盖的真实差异一次性暴露，本批逐个处理：

| 页面 | 真实差异 | 处置 |
|---|---|---|
| `PAGE-SUB-LIST` | v1 业务原型只有 6 列（无「学科编码」「选科角色」）；高保真与生产同为 8 列 | 该条目对照原型改为高保真文件 |
| `PAGE-CLS-LIST` | 生产缺「校区」列 | 补列；后端 `fillNames` 同时补 `campusName` |
| `PAGE-GRD-LIST` | 生产缺「学段」列 | 补列（`stageLabel` 转换） |
| `PAGE-AUDIT-ARCHIVE` | 生产缺「操作」列 | 补「查看」列（只读弹窗） |
| `PAGE-PRM-HISTORY` | 生产缺「操作」列 | 补「查看」列（只读弹窗） |
| 其他 18 处 | `extra_columns` / `deferred_labels` 的说明在正则修复后已不成立 | 清理过时声明 |

> 说明：`extra_columns` / `deferred_labels` 的用途是登记「原型确实缺标记」或「本批确实不做」的列，
> 不是用来让检查器闭嘴的。原型能解析出来后就必须删掉，否则会掩盖真实缺列。
