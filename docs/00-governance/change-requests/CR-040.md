# CR-040 — 需求到接口与表的逐条对应（GAP-081，学生与班级模块）

按 GAP-081 的推荐 A「按模块推进，先做学生与班级两个模块」，本批把学生 97 条与班级 62 条需求逐条挂到接口与表上。

## 做法

新增人工维护的 **`docs/00-governance/requirement-links.yaml`**，每条需求一行：

```yaml
REQ-STU-043: {api: [transferClass], tables: [edu_class_member]}
REQ-CLS-052: {api: [...], tables: [edu_audit_log], note: copyClass / batchTransferClass 在第 8 节没有独立 operationId……}
```

依据只有两类：**模块 PRD 第 8 节的 operationId 与说明**、**`docs/40-detailed-design/database/schema.yaml` 的表名与注释**。没有依据的一律不填：

- `api: []` + note 说明「第 8 节没有对应接口」，例如 `REQ-STU-010`（用户偏好持久化尚无设计落点）、`REQ-STU-027`（首轮不提供学号修改，GAP-030 裁决 B）、`REQ-STU-051`（家长端明确延后）；
- 认证侧能力（首次登录、设置密码、登录限流）明确标注由 `ruoyi-auth` 承载，不硬挂到教育域接口上；
- 复用关系写明依据，例如 `REQ-CLS-061` 复制班级复用 `addClass`（GAP-049 裁决 A）、`REQ-CLS-062` 批量迁学生复用 `transferClass`（D-067）。

`tools/gen_traceability.py` 增加 `parse_links()`，把这份对应表合并进 `traceability.yaml`（优先于历史值），生成物保持可重跑。

## 结果

- 学生 97 条 + 班级 62 条 = **159 条**已逐条挂接；其中 **149 条**有接口、**145 条**有表，10 条按依据写明「第 8 节无对应接口」。
- 矩阵的 `coverage_summary`：`linked_to_api` 8 → **149**，`linked_to_tables` 8 → **145**（另有 159 条状态从「未开始」升为「部分覆盖」，因为原型与验收用例已挂、生产代码与测试仍缺）。

## 新发现

逐条核对暴露一组缺契约，登记为 **GAP-082**：`REQ-STU-087` 查看激活码、`REQ-STU-088` 打印密码条、`REQ-STU-089` 下载加密清单、`REQ-STU-092` 班主任代激活——四项都要读写 `edu_activation_code`（敏感凭据），学生 PRD 第 8 节没有对应 operationId。推荐按既有模式补 4 个接口并统一审计口径。
