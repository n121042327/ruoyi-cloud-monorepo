# CR-101 — 阶段 7 第二十二批：教育域菜单 SQL（让登录后左侧出现「教育管理」）

用户反馈登录后左侧没有教育相关菜单。核查后确认：**侧栏完全由后端 `sys_menu` 驱动**——
`apps/plus-ui/src/store/modules/permission.ts` 的 `generateRoutes()` 调 `getRouters()`
拿菜单树拼侧栏，而 `src/router/index.ts` 里那 41 条 `dynamicRoutes` 是 `hidden: true` 的隐藏路由，
只让页面「可访问」，不会出现在侧栏。因此本批生成菜单种子 SQL 并已在本地库执行。

## 产出

| 落点 | 说明 |
|---|---|
| `services/RuoYi-Cloud-Plus/script/sql/edu-menu.sql`（新增） | 教育域菜单种子：**教育管理(M) → 12 个分组(M) → 41 个页面(C) → 64 个按钮(F)**，共 118 行，id 区间 13000-13999，幂等（先删区间再插，含 `sys_role_menu` 清理） |
| `script/docker/README-deploy.md`（改） | 建库导表一节补一步「导入教育域菜单 `edu-menu.sql`」 |

生成口径（全部取自已核对的事实源，未自造）：

- **页面清单与 URL**：`docs/40-detailed-design/frontend-page-tree.yaml` 的 45 条路由（其中 `/login`、`/403`、`/404`、`/500` 是静态路由，不进侧栏），配合 `src/router/index.ts` 的 `dynamicRoutes`（41 条）；
- **`component` 写法**：`views/` 相对路径去掉 `.vue`（如 `edu/student/stu_list/index`），与前端 `loadView()` 的匹配规则一致；
- **`path` 写法**：顶级目录 `edu`，二级分组取路由第 2 段（`student`/`class`/…），页面取剩余段（如 `roster/add`），拼接后正好等于目标 URL；
- **目录的 `component` 留空**：后端 `getComponentInfo()` 会自动回退 `Layout`（顶级）/ `ParentView`（二级）；
- **权限点**：41 个页面取各自 `dynamicRoutes` 的首个 `permissions`；另外把 ruoyi-edu 控制器里 64 个 `@SaCheckPermission` 权限点全部生成为按钮(F)行，便于角色授权；
- **图标**：沿用前端 `icon`，对 `icons/svg` 里不存在的三个（`swap`/`check`/`set`）回退为 `switch`/`finish`/`edit`，保证侧栏图标能渲染。

## 执行与验证（本机 docker 的 ry-cloud 库）

```
按类型：M=13（1 根 + 12 分组）、C=41、F=64
URL 拼接校验：DB 生成的 41 条 URL 与前端 dynamicRoutes 逐条比对 -> 不一致 0
component 校验：41 个 component 与 apps/plus-ui/src/views/<component>.vue 比对 -> 不一致 0
权限点校验：41 个页面 perms 全部非空；后端 64 个权限点全部有 F 行
```

## 使用说明

1. 执行 `services/RuoYi-Cloud-Plus/script/sql/edu-menu.sql`（含中文，务必带 `--default-character-set=utf8mb4`）；
2. **重新登录**（前端只在登录/刷新时重建侧栏），即可看到「教育管理」及其 12 个分组、41 个页面；
3. `super_admin`（role_id=1）由后端 `selectMenuTreeAll()` 直接放行，无需授权；**其它角色**要在「系统管理 → 角色管理」里勾选这些菜单；
4. 生产环境若用 nginx 托管旧 dist，需重新 `pnpm build` 发布，否则新菜单点开是空白。
