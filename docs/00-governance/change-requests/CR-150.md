# CR-150 — 阶段 7 第六十九批：修复 ruoyi-edu 启动失败（审计 ↔ 导入导出 循环依赖）

## 1. 问题

用户在本机用 IDEA 启动 `ruoyi-edu` 时失败（编译是通过的）：

```
'eduAsyncTaskServiceImpl'（构造参数 4）-> 'eduAuditServiceImpl'（构造参数 4）
  -> 'eduImportExportServiceImpl'（构造参数 5）-> 'eduAuditServiceImpl'（正在创建中）
  Is there an unresolvable circular reference ...?
```

根因：CR-136 为了「下载审计」在 `EduImportExportServiceImpl` / `EduAsyncTaskServiceImpl` 注入 `IEduAuditService`；
而 `EduAuditServiceImpl` 本来就注入 `IEduImportExportService`（审计导出复用通用导出引擎）→ 构造期循环。

## 2. 修复

审计侧改为延迟注入（打破构造期循环），并对为什么选这一侧给了理由（审计导出是低频入口，引擎写审计是高频路径）：

```java
@Lazy
@Autowired
private IEduImportExportService importExportService;
```

## 3. 验证

```
mvn -o -DskipTests -pl ruoyi-modules/ruoyi-edu spring-boot:run "-Dspring-boot.run.jvmArguments=-Dfile.encoding=UTF-8"
-> Started RuoYiEduApplication in 16.537 seconds
```

这是本批最重要的部分：**编译通过与能启动是两件事**，bean 循环只在使用期暴露。
另外记录一个环境细节：不带 `-Dfile.encoding=UTF-8` 时 Nacos 配置里的中文会让 snakeyaml 抛
`MalformedInputException`（IDEA 运行配置自带该参数）。

## 4. 教训与口径

后端批次以前只跑 `mvn -o -DskipTests -pl ruoyi-modules/ruoyi-edu -am compile`。
从现在起，**涉及 bean 依赖 / 配置变更的后端批次要加一次最小启动验证**（命令见上，约 17 秒），
否则这类问题会积压到用户启动时才暴露。
