# CR-031 — 年级详情、指定年级主任、归档与删除浮层字段分组

用户要求继续。本批把 `docs/00-governance/page-field-layout.md` 的约束落到年级管理列表页剩余四个浮层，使该页不再有未整理浮层。继续授权不记为人工验收通过。

## 覆盖对象

`prototypes/{functional,high-fidelity}/v2/pages/grade-list.html`：

| 页面 ID | 名称 | 载体 | 字段 |
|---|---|---|---|
| `DIALOG-GRD-DELETE` | 删除年级 | 弹窗（sm） | 删除原因 |
| `PAGE-GRD-DETAIL` | 年级详情 | 抽屉（lg） | 所属学校、学段、入学年份、学段内序号、年级名称、状态 + 四张只读子表 |
| `PAGE-GRD-LEADER` | 指定年级主任 | 弹窗（md） | 学年学期、当前任职清单、新增任职（教师 / 主要负责人 / 生效日期） |
| `PAGE-GRD-ARCHIVE` | 归档年级 | 弹窗（sm） | 归档原因 + 影响范围与引用情况 |

## 分组与顺序

- 删除确认：删除影响（影响范围 → 当前状态）→ 删除说明（删除原因）。原因排在状态之后，先看「能不能删」再填理由。
- 年级详情：原「基本信息」卡片改名为**年级信息**，卡片内分两组——教育信息（所属学校 → 学段 → 入学年份 → 学段内序号 → 年级名称，再到年级名称规则说明）与管理信息（状态）。字段顺序与 CR-027 的年级表格、新建年级表单一致（父级到子级）。其余四张卡片（下辖班级 / 在读学生统计 / 年级主任任职历史 / 变更记录）是子表与时间线，保持原样。
- 指定年级主任：任职信息（学年学期 → 当前任职清单）→ 新增任职（教师 → 主要负责人 → 生效日期）。学年学期是任职的时间上下文，排在最前；新增任职使用 `.form-inline` 横向排列。
- 归档确认：归档影响（影响范围 → 当前引用情况）→ 归档说明（归档原因）。
- 四个浮层的提交与取消都固定在页脚；分组内只保留子清单的行动作（`ACT-GRD-024` 添加、`ACT-GRD-027` 移除），不是表单级操作。

## 细节修复

- 删除确认补上 `data-validate-summary` 校验汇总，与同页其余三个弹窗一致；此前只有字段级红字，提交失败后没有汇总提示。
- 分区宽度规则（`.layout-sections .input/.select { width:100% }`）会把 `.form-inline` 里的控件拉满并拆行，本批为该页补一条例外，让「添加年级主任」行保持横向。
- 详情字段仍按 `data-detail-field` 取值，重排不影响填充逻辑（读取不依赖列位置或 DOM 顺序）。

## 关于验证器复制的说明

`verify-teacher-grade-detail.html` 自 CR-027 起就取不到年级行：它按「第一列」匹配年级名称，而 CR-027 已把第一列改为学段，脚本在第一步抛错并停在「运行中」。本批的副本修了两处——① 改为匹配整行文本，不再依赖列位置；② 三个 iframe 的就绪判断补轮询 `readyState` 与超时兜底，避免本地文件在本脚本挂监听前就 load 完导致永久停在「运行中」。原版保留为历史文件。
