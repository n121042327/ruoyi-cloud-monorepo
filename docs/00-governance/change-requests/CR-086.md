## 口径（与 PRD / BR 对齐）

- 学籍状态的**唯一流转入口**是升班与学籍异动模块（`DP-01`）：`changeEnrollmentStatus` 同时更新在校记录并**追加**异动记录（`BR-PROMO-012` 追加式，不更新不删除）。
- **开除在义务教育阶段不可用且后端拒绝**（`REQ-PRM-043`）：用在校记录的入校年级反查学段，命中 `primary` / `junior` 直接抛业务异常；选项列表里也会把该动作置灰并给出原因。
- **退学 / 开除 / 死亡需校级管理员审批**：这三类异动写入时把 `approval_status` 置「待审批」，审批动作在学籍异动模块批次接入。
- **复学 / 报到必须指定班级**，但班级关系仍由班级管理写（`DP-01`：学生班级归属唯一写入入口在班级管理）——本批只做参数校验与异动记录。
- 异动动作选项与「当前状态 → 可选新状态」的流转矩阵联动：与当前状态不匹配的动作在列表里禁用并给出原因，避免前端误选。
- 监护人主体是**平台级实体**（手机号平台唯一，一个家长可对应多个孩子）；一个学生的监护人在绑上限 **3**（`BR-ACCOUNT-018` 同口径）；解绑必须填原因（`GAP-015`），本批置为「待解绑」并写 `unbind_time` 与意见，班主任确认入口随班级管理批次补齐。
- 敏感字段：证件号 / 手机号**默认掩码**（`guardianPhoneMasked`），明文只在 `person.student:read_sensitive` 下返回并写审计（`NFR-AUDIT-02`）。
- 删除学生：仍在花名册（`status='1'`）或有异动记录时**拒绝物理删除**（历史与学籍类数据禁止物理删除）。
- 改学号需原因（≥ 5 字）且**学号永不回收**（`BR-STU-001`）：目标学号已被占用直接拒绝。
