# CR-153 — 阶段 7 第七十二批：多校账号导入显式选校（GAP-115）

## 1. 交付

| 层 | 改动 |
|---|---|
| 入参 | `EduImportValidateBo` 增可选 `schoolId`（学校租户留空即本校） |
| 服务 | `validateImportFile` 改用 `resolveImportSchoolId(bo.getSchoolId())` 定学校归属 |
| 幂等 | `findReusableBatch` 增 `school_id` 条件：同一份文件给不同学校导入时不再复用彼此的批次 |
| 前端 | `imp_wizard` / `stu_import` / `cls_roster_import` / `tch_import` 四个导入页加「目标学校」下拉（可管理多所学校时才出现） |
| 类型 | `ImportValidateForm` 与 `importTeacherValidate` 入参类型补 `schoolId` |

服务端的三条判定（`EduImportExportServiceImpl.resolveImportSchoolId`）：

1. 数据范围内一所都没有 → 拒绝（`DS-DENY-02`），与既有口径一致；
2. 传了 `schoolId` → 必须落在本人数据范围内，否则拒绝（`DS-DENY-02`）；
3. 没传 `schoolId` → 可管理多所学校时拒绝并要求显式指定；只有唯一一所时取该校。

## 2. 下拉为什么只在校可管理多所学校时出现

学校租户只有一所学校，原型（`prototypes/functional/v1/pages/import-wizard.html` 等）也没有「目标学校」字段：
多显示一个恒定值只会让页面与原型产生无意义差异。因此下拉用 `v-if="showSchoolSelect"`，
只在 `listSchool()` 返回多于一所时出现；多校账号出现时必填（未选不给提交）。

## 3. 服务端仍然说了算

前端下拉只决定提交内容，学校归属一律由后端按数据范围复核 —— 不允许「取第一个」，
也不允许「留空由数据库默认」。学校归属在请求线程确定后随批次落库，执行阶段按 `edu_import_batch.school_id`
取数，与 D-218 / D-224 的后台任务口径一致。
