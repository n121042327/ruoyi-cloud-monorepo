# CR-126 — 阶段 6 第四十五批：教学班手工创建接口按 CR-017 不接前端

第二轮队列第 4 项「教学班：新建教学班（POST /edu/teaching-class）」。核对后判定**不应接**，
本批产出是判定依据与决策，无代码改动。

## 1. 判定依据

| 证据 | 内容 |
|---|---|
| `cls_teaching` 页面自身 | `scope-hint` 写「数据范围：本校 · 只读（创建走生成向导）」；页内说明条写「教学班的创建入口唯一在「按组合生成教学班」向导，本页只做查询、详情与停用」 |
| 向导实际调用的接口 | `str_gen_class` 调 `previewTeachingClassGenerate` / `executeTeachingClassGenerate`，即 `POST /edu/stream/teaching-class/preview` 与 `/generate` |
| 后端 `POST /edu/teaching-class` | `EduTeachingClassController` 上存在，但按 CR-017 的裁决它是**手工创建单条教学班**的入口 |

CR-017 的裁决是「教学班的创建入口唯一在『按组合生成教学班』向导」。如果把
`POST /edu/teaching-class` 挂到教学班管理页，就会出现**两个创建入口**：

- 向导入口：按选科组合批量生成，保证「选科组合 → 教学班」的一致性与可核对性；
- 手工入口：单条创建，绕过组合分布与差异核对。

这与 AGENTS 第 7 节「每个字段只有一个写入入口」的模块边界规则直接冲突。

## 2. 处置

**不接前端**，`POST /edu/teaching-class` 保留为后端能力（供向导或后续批量场景内部调用），
教学班管理页维持「只读 + 详情 + 停用」的现有形态。

队列第 4 项关闭，下一项进入第 5 项「升班：就绪检查与明细查询」。
