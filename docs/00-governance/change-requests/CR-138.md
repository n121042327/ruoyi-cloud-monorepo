# CR-138 — 阶段 7 第五十七批：学生导出器 + 后台导出的学校隔离口径（GAP-094 第二批）

## 1. 交付

| 项 | 说明 |
|---|---|
| `job/StudentExportHandler` / `StudentExportRow` | 学生导出器（`student`），xlsx + csv |
| 默认列 | 学号 / 姓名 / 性别 / 入学年份 / 学段 / 年级 / 班级 / 学籍状态 —— 取自学生列表页 `PAGE-STU-LIST` 的**非敏感列** |
| 取数路径 | 学生主体是平台级实体（AGENTS 第 7 节），因此经在校记录两段式取数：`edu_student_enrollment.school_id = 任务学校` → 学生 → 在班关系 → 班级 → 年级 |
| 敏感字段 | **默认列不含**联系电话与证件号；明文导出需 `read_sensitive`（REQ-IMP-028 / BR-IMP-012），与明文导出批次一起做 |

## 2. 关键口径：后台导出的数据范围

导出跑在 `@Scheduled` 线程里，**没有登录态**，MyBatis 数据权限插件不会生效。实测口径因此定为：

1. 导出器必须自己按 `EduExportContext.schoolId`（任务落库时的学校）过滤学校级数据；
2. 学校上下文缺失时**抛错拒绝导出**，绝不退回「全平台」；
3. 平台级实体（学生）经在校记录/班级关系两段式取数，不用「UNION 全平台」这种取巧写法。

顺带修正：`TeachingAssignmentExportHandler` 上一批只按 termId / classId / teacherId 过滤，缺学校隔离，本批补上。

## 3. 遗留（GAP-114）

细粒度数据范围（年级主任 / 班主任 / 任课教师）没有随任务落库，后台导出目前只做到学校级隔离。
推荐在发起导出时把解析后的范围（gradeIds / classIds）写入任务参数，执行器按它过滤。
