## 2. 变更原因

### 2.1 字段字典缺 6 条，阶段 5 建表没有权威定义

升班 PRD 7.1 已经给出实体与关键字段：`edu_promotion_task` 用
`tenant_id` / `school_id` / `source_term_id` / `target_term_id` / `status` /
`total_count` / `success_count` / `failed_count` / `task_no`
（`docs/10-prd/modules/promotion/PRD.md` 第 7.1 节）。
但 `06-field-dictionary.yaml` 只登记了 `promotion_task_status` 这个**枚举**与通用的 `task_no`，
上面 6 个字段一条都没有。

字段字典开头的 `purpose` 写明：「任何模块 PRD、原型表单、接口契约、数据库迁移脚本中的字段，
都必须能在这里找到定义」。缺登记的直接后果是阶段 5 只能从 PRD 的表格反推字段类型与必填性，
阶段 6 的 `data-field` 也查不到条目。

### 2.2 取消确认片段没进 PRD 6.1，页面编号无处可查

批次 2-3e-s1 交付时按班级模块的口径实现了取消二次确认（`DIALOG-PRM-CANCEL`），
但升班 PRD 6.1 只登记了 10 个页面，没有这个片段；
`navigation.yaml` 的 `jump_map` 校验又要求跳转目标必须在 `pages` 里，
所以当时的取消入口只能写在 `PAGE-PRM-LIST` 的 note 与 `page-actions.yaml` 的动作组里，跳转登记不了
（班级模块的同片段由 `CR-009` 补进 PRD 6.1）。

### 2.3 为什么不能只留在原型里

取消是**危险动作**，`page-actions.yaml` 的 `state_rules` 明确要求危险动作必须二次确认并写清影响范围；
而「取消后保留已完成部分、不做整批回滚」（PRD 第 12 节已确认 4）是业务口径，
必须落在 PRD 层，否则阶段 6 的实现者可能按「取消 = 回滚」实现，阶段 8 的用例会出现两种答案。

## 3. 变更内容

1. **字段字典新增 6 个字段**（`docs/10-prd/06-field-dictionary.yaml`）：

| 字段 | 中文 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `source_term_id` | 源学年学期 | `bigint` | 是 | 引用 `edu_term`；从该学年学期取在读学生（`BR-PROMO-001`） |
| `target_term_id` | 目标学年学期 | `bigint` | 是 | 引用 `edu_term`；必须晚于源学期（`REQ-PRM-008`） |
| `promotion_task_status` | 升班任务状态 | `varchar(20)` | 是 | `enum_ref: promotion_task_status`；8 个状态（`REQ-PRM-003`） |
| `total_count` | 学生总数 | `int` | 否 | 统计值，受数据范围约束（`DS-DENY-08`）；草稿为 0 且前端显示「—」（`REQ-PRM-011`） |
| `success_count` | 成功数 | `int` | 否 | 统计值，受数据范围约束 |
| `failed_count` | 失败数 | `int` | 否 | 统计值；与失败原因成对出现（`REQ-PRM-032`） |

2. **`unique_keys` 补 1 条部分唯一说明**：
   同一学校 + 同一源学年学期 + 同一目标学年学期，**只对未结束任务**唯一（`REQ-PRM-005`）；
   落地方式（业务唯一 + 应用层校验，或带条件的唯一索引）在详细设计阶段确定。
3. **升班 PRD 6.1 补 `DIALOG-PRM-CANCEL` 行**（同页浮层片段，不单独占用页面编号），
   并按班级模块的写法补一段载体口径说明。
4. **升班 PRD 6.3 补一行**：「列表行内点击『取消』→ 打开取消确认片段 `DIALOG-PRM-CANCEL`；原因必填，
   取消后保留已完成部分（已确认 4 / `REQ-PRM-036`）」。
5. **升班 PRD 版本**由 `1.0.2-draft` 升为 `1.0.3-draft` 并补变更记录。
6. **`navigation.yaml`**：登记 `DIALOG-PRM-CANCEL`（`type: dialog`、`size: sm`、`parent: PAGE-PRM-LIST`、`batch: "2-3"`），
   补一条跳转，并把批次 2-3 声明的页数由 16 改为 17。
7. **原型同步**：`promotion-list.html` 的 `data-field="status"` 改为 `data-field="promotion_task_status"`；
   页面规格的字段清单与自查同步。
