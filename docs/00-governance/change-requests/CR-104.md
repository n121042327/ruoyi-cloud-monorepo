# CR-104 — 阶段 7 第二十四批：去掉 edu_school 的冗余列 school_id，恢复建校链路

用户反馈：租户账号登录后打开「学校管理」，页面打开了但没有数据。

## 1. 现象与定位

| 步骤 | 观察 |
|---|---|
| 该账号（`liubei`，租户 546223 蜀国）的权限 | `/system/user/getInfo` 返回 199 个权限点，含 `org.school:read`；页面 `canRead` 为 true，表格本身是渲染的 |
| `/edu/school/list` | `200 {"total":0,"rows":[]}`；`edu_school` 全库 **0 行** |
| `/edu/school/current` | `500 当前租户尚未接入学校`（同一根因） |
| `POST /edu/school`（直接建校） | `500`，edu 日志：<br>`### SQL: INSERT INTO edu_school (id, school_code, school_name, school_status, create_dept, create_by, create_time, update_by, update_time, tenant_id) VALUES (...)`<br>`### Cause: java.sql.SQLException: Field 'school_id' doesn't have a default value` |

## 2. 根因

生成器 `tools/gen_schema_artifacts.py` 对 `scope: school` 的表会自动注入两列：`tenant_id` + `school_id`。
`edu_school` 在事实源里是 `scope: school`，于是建表脚本产出了 `school_id bigint unsigned NOT NULL COMMENT '学校归属'`；
但这张表**本身就是学校主体**（一所学校对应一个租户，靠 `uk_school_tenant (tenant_id)` 唯一）：

- 实体 `EduSchool` 按阶段 7 主键约定把 Java 字段 `schoolId` 映射到 **`id`**，没有任何字段映射 `school_id`；
- MyBatis-Plus 生成的 INSERT 里因此不含 `school_id`，而该列 NOT NULL 且无默认值 → **建校必然失败**；
- 全仓库 grep：该列没有外键、没有索引、没有任何读写方（连 `edu_campus.school_id` 也没有指向它）。

结论：这是「生成器约定 ≠ 本表语义」的产物缺陷，不是权限或前端问题；学校列表为空正是因为它永远建不出学校。
附带影响：`EduDataPermissionHandler` 把 `edu_school` 放进 `SCHOOL_TABLES`，会生成 `school_id IN (...)` 条件 —— 该列既然写不进去，
数据范围开启后学校侧用户在自己学校的这张表上会查不到数据。

## 3. 改动

| 路径 | 改动 |
|---|---|
| `docs/40-detailed-design/database/schema.yaml` | `edu_school` 的 `scope` 由 `school` 改为 `tenant`，`note` 写明不再注入 `school_id` 及原因 |
| `docs/40-detailed-design/migrations/V8__edu_school_drop_redundant_school_id.sql`（新增） | `ALTER TABLE edu_school DROP COLUMN school_id;`（V1~V7 冻结不动；执行时该表为空，且无外键/索引/读写方引用） |
| `services/RuoYi-Cloud-Plus/ruoyi-modules/ruoyi-edu/src/main/java/org/dromara/edu/datascope/EduDataPermissionHandler.java` | `SCHOOL_TABLES` 移除 `edu_school`（其数据范围由 `tenant_id` 保证一校一租户），并同步类注释 |
