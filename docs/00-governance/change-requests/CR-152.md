## 1. 交付

| 层 | 改动 |
|---|---|
| 学生导出 | `StudentExportHandler` 按生效班级范围经班级关系（`edu_class_member.status = '1'`）落到学生 ID 再过滤 |
| 教师导出 | `TeacherExportHandler` 按生效班级范围经任教关系（`edu_teaching_assignment.status = '1'`）落到教师 ID 再过滤 |

两个导出器都复用 CR-151 的 `EduExportScopeResolver.effectiveClassIds(context)`：
`classIds` 优先；只有 `gradeIds` 时先展开为该年级下的行政班。至此
`student` / `teacher` / `class_roster` / `teaching_assignment` 四个导出器都按发起导出时落库的范围过滤。

## 2. 为什么不能直接按学校列过滤

- 学生主体是平台级实体（`edu_student` 没有学校列），学校侧一律经「在校记录 / 班级关系」两段式取数；
  而范围是班级维度的（班主任 → 本班），因此必须落到 `edu_class_member` 再取学生 ID。
- 教师主体带学校列，但「任课教师只应看到本人任教班级的教师」这一范围只有任教关系能表达；
  因此按 `edu_teaching_assignment` 取该范围内的教师 ID 再过滤。

## 3. 空范围的口径

范围内查不到行时返回**空表**，不得退回本校全量 —— 否则「范围过滤」在边界上等于失效。
只有 `scopeClassIds` 为空（校领导 / 未解析出范围）才表示本校全量，与 D-231 / D-232 一致。
