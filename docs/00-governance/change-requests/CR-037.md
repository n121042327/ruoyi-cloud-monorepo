# CR-037 — 补齐 6 个缺失的接口契约（GAP-080）

承 CR-036：`check_api_contract.py` 报出的 8 个孤儿 `data-api` 里，2 条已改名对齐，余下 6 条确认是**缺契约**。本批按 GAP-080 的推荐（选项 A）补齐——导出沿用已有模块级写法，学生照片与证件号查看按 GAP-027 的结论挂到统一文件服务与敏感字段读取接口。

## 新增接口（PRD 第 8 节）

| 模块 | operationId | 方法 | 路径 | 说明 |
|---|---|---|---|---|
| class | `exportClass` | POST | `/edu/class/export` | 班级列表导出；沿用 `exportStudent` / `exportTeacher` 的模块级写法，≤ 2000 行直接下载、超出转异步 |
| grade | `exportGrade` | POST | `/edu/grade/export` | 年级列表导出；同口径 |
| promotion | `exportPromotionTask` | POST | `/edu/promotion/task/export` | 升班任务列表导出；同口径 |
| student | `uploadStudentPhoto` | POST | `/edu/student/{id}/photo` | 上传 / 更换学生照片，单张，走统一文件服务 |
| student | `getStudentPhoto` | GET | `/edu/student/{id}/photo` | 查看照片原图，需 `read_sensitive`，写敏感数据访问日志 |
| student | `viewStudentIdCard` | GET | `/edu/student/{id}/id-card` | 查看完整证件号，需 `read_sensitive`，写敏感数据访问日志 |

三点依据：

1. 三个导出沿用模块级导出的既有模式（学生、教师、花名册都已经是模块自己的导出接口 + 异步阈值），不新造通用导出参数。
2. 学生照片按 `GAP-027` 的结论走统一文件服务：上传是写接口（`person.student:create / update`），查看原图是敏感读（`read_sensitive`）并写访问日志，与 `page-actions.yaml` 的 `ACT-STU-021` / `ACT-STU-022` 一致。
3. 证件号全量查看对应学生 PRD 7.3 的「敏感字段全量查看」审计事件（查看人、被查看对象、字段、时间），因此登记为独立读接口而不是塞进 `getStudent`。

> PRD 第 8 节的 `operationId` 一栏原文即写明是「建议值，阶段 4 定稿」，路径与命名沿用同模块既有约定；本批只补登记，不改任何业务规则。
