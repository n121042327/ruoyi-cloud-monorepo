# CR-036 — 孤儿接口引用清理（GAP-079）

承 CR-035 的契约检查发现：v2 原型里有 8 个 `data-api` 字符串在 OpenAPI 中不存在。逐条核对后分两类处理。

## 一、有明确对应关系的改名（已落地）

| 原型字符串 | 改为 | 依据 |
|---|---|---|
| `saveTeacherEduRole` | `saveTeacherRole` | 教师 PRD 第 8 节 `saveTeacherRole`（`POST /edu/teacher/{id}/role`，分配角色）；`page-actions.yaml` 的 `ACT-TCH-032` 同步 |
| `saveTeacherLeave` | `leaveTeacher` | 教师 PRD 第 8 节 `leaveTeacher`（`POST /edu/teacher/{id}/leave`，离职 / 调离登记） |

两处都只出现在业务与高保真 v2 教师列表；`tools/gen_api_and_map.py` 的 `API_ALIASES` 增加这两条别名，
让冻结 v1 原型里的历史字符串也不会在派生映射里指向不存在的 operationId（与 CR-029 / CR-035 同一手法）。

## 二、确认缺契约（另立 GAP-080）

`exportClass`、`exportGrade`、`exportPromotionTask`、`uploadStudentPhoto`、`getStudentPhoto`、`viewStudentIdCard`
六条在各自模块 PRD 第 8 节都没有同名或同义条目：

- 班级 / 年级 / 升班任务列表的「导出」按钮没有模块级导出接口（班级只有 `exportClassRoster` 花名册导出，
  升班只有 `exportPromotionPreview` / `exportPromotionResult` 预览与结果导出，年级则完全没有导出接口）；
- 学生照片的上传与查看原图、证件号全量查看都没有登记接口——后者还牵涉 `student PRD 7.3` 的「敏感字段全量查看」审计事件。

按 `GAP-066` 确立的原则（不得把原型字符串当成有效接口，也不批量改指），这里只登记不擅改，
推荐按 A：导出沿用 `exportStudent` / `exportTeacher` 的模块级写法，学生照片与证件号查看按 `GAP-027` 的结论挂统一文件服务与敏感字段读取接口。

## 验证

`python tools/check_api_contract.py`：172 个 operationId、v2 原型 data-api 引用 112 处；余下 6 条（12 处）作为已登记的 GAP-080 只提示不判失败，新出现的孤儿引用仍会让脚本失败。

`python tools/gen_api_and_map.py` 重跑后，`page-action-api-map.yaml` 里再没有 `saveTeacherEduRole` / `saveTeacherLeave`。

回归：教师非在职行 8 项 × 2 层、教师编辑绑定 14 项 × 2 层全部通过；`check_docs.py`、`check_mermaid.py` 通过；冻结 v1 页面未改动。
