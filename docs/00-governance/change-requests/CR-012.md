## 2. 变更原因

### 2.1 `GAP-052`：五个按钮里有四个没有权限点

升班 PRD 的 `REQ-PRM-006` 要求「新建任务 / 预览 / 执行 / 重试 / 取消」按权限与任务状态动态显示，
但权限矩阵的 `promotion.batch` 只有三条授权：超管全量、校领导 `read + approve`、教务主任 `read + create`。

五个按钮里只有「新建任务」能对上 `create`；「预览 / 执行 / 重试 / 取消」都是会改任务状态与明细的写操作，
矩阵里没有对应动作。同时，升班没有审批环节（PRD 1.2 范围内没有审批，`D-041` 也只针对学籍状态），
校领导的 `approve` 没有落点，而 PRD 2.1 / 2.3 却写着「校领导审批升班任务」——这是 PRD 内部的不一致。

如果按现状实现：教务主任能建任务但不能执行，校领导有一个永远点不到的审批按钮，
阶段 4 的 `validatePromotionTask` / `executePromotionTask` / `retryPromotionTask` / `cancelPromotionTask`
四个接口没有权限点，阶段 8 的越权用例会出现两种答案。

### 2.2 `GAP-053`：年级主任被 PRD 列为主要角色，矩阵里却没有任何授权

PRD 6.1 把 `PAGE-PRM-PREVIEW`（升班预览与调整）与 `PAGE-PRM-ADJUST`（调整学生去向）的主要角色
写成「教务主任、年级主任」，2.3 的场景覆盖矩阵里年级主任在 `SCN-PROMO-01` 是「查看 + 调整」；
但矩阵里 `grade_leader` 没有 `promotion.batch` 条目，按矩阵实现年级主任连任务列表都打不开。

同类问题在年级模块（`GAP-035`）与班级模块（`GAP-043`）都出现过，两次裁决都是「按 PRD 补只读权限、写操作仍归教务主任」。

### 2.3 为什么必须回改 PRD 而不是只改矩阵

按钮显隐、菜单可见性、阶段 4 的接口权限点、阶段 6 的 `v-hasPermi`、阶段 8 的越权用例
都以矩阵为唯一依据；但 PRD 5.1 与 6.1 同样会被下游直接引用。
如果只改矩阵，PRD 里「校领导审批升班任务」与「年级主任可调整去向」两句仍会被实现者当成需求，
矩阵与 PRD 会各说一套。因此本次把两处同步收敛。

## 3. 变更内容

1. **权限矩阵（`promotion.batch`）**：
   - `super_admin`：保持全量（不动）
   - `school_leader`：`read + approve` → **`read`**，并补条件说明「升班任务无审批环节」
   - `academic_director`：`read + create` → **`read + create + update`**，
     条件说明写明「预览 / 执行 / 重试 / 取消统一映射到 `update`」
   - `grade_leader`：新增 **`read`**，条件为「仅本人负责的年级（`DS-05`），只读」
2. **升班 PRD 2.1**：
   - 校领导一行由「审批升班任务与学籍异动」改为「审批学籍异动；升班任务只读（升班无审批环节）」；
   - 年级主任一行由「可参与升班预览调整」改为「升班任务只读，可参与预览核对但不可调整去向」。
3. **升班 PRD 2.3**：`SCN-PROMO-01` 的校领导由「审批」改为「查看」、年级主任由「查看 + 调整」改为「查看」；
   `SCN-PROMO-02` 保持「审批」不变。
4. **升班 PRD `REQ-PRM-006`**：权限依据补为
   「`promotion.batch`：新建任务 = `create`；预览 / 执行 / 重试 / 取消 = `update`」，并注明 `read` 决定列表可见性。
5. **升班 PRD 5.1**：`promotion.batch` 的操作集合由 `read / create / approve` 改为 `read / create / update`，
   说明列补「预览 / 执行 / 重试 / 取消统一映射到 `update`」。
6. **升班 PRD 6.1 / 6.3**：`PAGE-PRM-LIST` 的主要角色补「年级主任（只读）」；
   `PAGE-PRM-PREVIEW` 标为「教务主任；年级主任（只读）」；
   `PAGE-PRM-ADJUST` 的主要角色收敛为「教务主任」，年级主任不渲染调整入口；
   6.3 补一行「年级主任打开预览页 = 只读形态，可只看不能改，调整弹窗入口不渲染」。
7. **治理文件**：`GAP-052` / `GAP-053` 关闭；`decisions.md` 追加 `D-069`；`file-catalog.md` 更正升班 PRD 版本。

本次**不新增权限动作**（不引入 `execute` / `retry` / `cancel`），也不改任务状态机（8 个状态不变）。
