## 变更原因

用户 2026-09-30 澄清：**跨校共享的是题库习题、试卷这类资源，不是学生等业务数据。**

现有文档把"数据共享授权"写成了可以扩大被授权学校对**学生数据**的可见范围，与澄清相反。集合证据：

| 文件 | 行 | 现写法 |
|---|---|---|
| `docs/10-prd/modules/student/PRD.md` | 531 | "额外可见范围只能来自运营方创建的共享授权（`BR-DATA-011`、`D-036`），且只读。" |
| `docs/10-prd/modules/student/acceptance.md` | 84 / 257 | 准备数据"A 校 → B 校教师的只读授权"；`AC-STU-115`"有共享授权的账号读取被授权学校数据" |
| `docs/10-prd/modules/import-export/acceptance.md` | 80 / 195 | 同型；`AC-IMP-110`"有共享授权的账号导出被授权学校数据" |
| `docs/10-prd/05-permission-matrix.yaml` | 344 | `PM-Q-005` 答复"跨校可见性只能来自运营方创建的数据共享授权" |
| `prototypes/functional/v1/pages/student-list.html` | 批次 2-1 | 学生列表做出了"跨校只读学生列表 + `DG-2026-0007` 授权提示条" |

## 变更内容

1. **统一口径**：数据共享授权的对象只有教学资源——题库习题（`question_bank_item`）、试卷（`exam_paper`）等；学生、班级、年级、教师、成绩、学籍等业务数据一律不跨校共享。
2. `edu_data_grant` 增加 `resource_types` 与 `resource_scope`；首轮建表保留字段，但**首轮没有可授权对象**（题库与试卷不在首轮交付范围）。
3. 学生模块删掉"共享授权可扩大学生可见范围"的表述；"学校"筛选只有平台运营可切换，学校用户锁定所属学校。
4. 验收用例改写：`AC-STU-115`、`AC-IMP-110` 从"有授权即可读被授权学校数据"改为**负向用例**——不存在共享授权放开学生数据的路径，越权尝试必须被拒绝并写审计。
5. `AGENTS.md` 第 7 节补一句：跨校共享授权只针对教学资源，业务数据不跨校共享。

## 替代方案

- **方案 B：不改文档，把"共享学生数据"保留成可选能力。** 不选：与用户澄清直接冲突，也与 `BR-ORG-008`（不存在按租户树的跨校共享）、`D-026`（集团不看下属学校教学数据）冲突。
- **方案 C：删掉共享授权模型，改成"资源复制"。** 不选：复制后无法撤销、无法审计、责任不清，与 `BR-DATA-013`（授权可随时撤销、立即失效）冲突。

## 如果错了的代价

若将来确实需要跨校共享学生数据，需要重新开启授权模型并补一组越权用例。本次改动只删语义与页面，**表结构保留**，回滚成本低。
