# CR-123 — 阶段 6 第四十二批：导入导出引擎在各业务页的复用核对

第二轮自动化队列第 1 项。本轮**没有代码改动**，产出是核对结论 —— 这个结论本身有价值，
因为它避免了下次重复核对，也把「模块专属入口 vs 通用入口」的疑问一次性说清。

## 1. 核对对象

| 页面 | 校验 / 执行入口 | 是否走统一引擎 |
|---|---|---|
| 学生批量导入 `stu_import` | `POST /edu/import/validate`、`/edu/import/execute`（通用入口） | 是 |
| 教师批量导入 `tch_import` | `POST /edu/teacher/import/validate`、`/import/execute`（模块入口） | 是 |
| 编班表导入 `cls_roster_import` | `POST /edu/class/roster/import/validate`、`/import/execute`（模块入口） | 是 |

**关键结论**：三个页面走的是**不同路径**，但**同一个引擎**。模块入口（`/edu/teacher/import/*`、
`/edu/class/roster/import/*`）在 Controller 里只是设好 `moduleCode` 再转发：

```java
// EduTeacherController
validate.setModuleCode("teacher");
return R.ok(importExportService.validateImportFile(validate));

// EduClassController
validate.setModuleCode("class_roster");
return R.ok(importExportService.validateImportFile(validate));
```

所以「教师导入页没有用统一入口」不是缺陷，而是模块化入口的正常设计。

## 2. 功能点一致性

三个页面的六个功能点逐项比对，**全部齐全且一致**：

| 功能点 | 学生 | 教师 | 编班表 |
|---|---|---|---|
| 模板下载 | Y | Y | Y |
| 上传与校验 | Y | Y | Y |
| 失败行下载 | Y | Y | Y |
| 执行（异步） | Y | Y | Y |
| 进度轮询 | Y | Y | Y |
| 结果文件下载 | Y | Y | Y |

## 3. 参数口径

| 页面 | 校验调用 |
|---|---|
| 学生 | `validateImportFile(file, { module: 'student', termId, duplicatePolicy })` |
| 教师 | `importTeacherValidate(file, { termId, duplicatePolicy })` —— `moduleCode` 由后端强制为 `teacher` |
| 编班表 | `validateImportFile(file, { module: IMPORT_MODULE, termId, duplicatePolicy })` |

`moduleCode` 一律由后端设置（前端传值会被覆盖），这是有意的：模块归属不能由前端决定。
