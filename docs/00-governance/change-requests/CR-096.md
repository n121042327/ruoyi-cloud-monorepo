## 为什么必须本地构建三个镜像

`docker-compose.yml` 里的应用镜像都是上游 `ruoyi/*:2.6.2`。本 fork：

1. `ruoyi-edu` 是**新模块**，上游根本没有这个镜像；
2. `ruoyi-system` 加了 `RemoteUserService.resetPassword` / `changeAccountStatus`；
3. `ruoyi-resource` 加了 `RemoteFileService.downloadByUrl`。

第 2、3 条是 Dubbo 远程契约，用上游镜像跑 edu 会在运行期报「方法不存在」，
所以 edu + system + resource 三个模块都要用本仓库构建的镜像（脚本已按 compose 的 tag 打标，本地同名镜像覆盖上游镜像，只影响本机）。

## 两个关键口径

- **edu 的 Nacos 配置其实是必需的**：`application.yml` 里写的是 `optional:nacos:ruoyi-edu.yml`，缺了不会报错，
  但 master 数据源正是在这个文件里定义的，缺了就没有数据源。
- **Nacos 命名空间必须是 `dev`**：`pom.xml` 的 `dev` 剖面是 `activeByDefault`，`@nacos.server@`→`127.0.0.1:8848`、
  `@profiles.active@`→`dev`，而 `namespace: ${spring.profiles.active}` 取的就是后者；容器用 host 网络，
  所以容器内的 `127.0.0.1:8848` 就是宿主机的 Nacos。
