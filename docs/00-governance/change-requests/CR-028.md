# CR-028 — 学生学籍异动 / 调班 / 异动登记浮层字段分组

用户于 2026-10-01 要求继续此前建议的批次：把 `docs/00-governance/page-field-layout.md` 的约束落到学生页三个未整理的浮层。继续授权不记为人工验收通过；GAP-075 仍未获表态，本批不动教师非在职行入口；GAP-077 未获裁决，本批不新增字段。

## 覆盖对象

`prototypes/{functional,high-fidelity}/v2/pages/student-list.html` 的三个浮层：

| 页面 ID | 名称 | 字段 |
|---|---|---|
| `PAGE-STU-STATUS` | 学籍异动 | 异动类型、生效日期、复学 / 报到后的班级、原因 |
| `PAGE-STU-TRANSFER` | 调班 | 目标班级、调班原因 |
| `PAGE-PRM-CHANGE` | 学籍异动登记（升班与学籍异动口径） | 异动类型、生效日期、原因 |

## 分组与顺序

- 学籍异动：异动信息（异动类型 → 生效日期）→ 复学 / 报到安排（复学 / 报到后的班级）→ 异动说明（原因）。「复学 / 报到后的班级」是异动类型的条件字段，单独成组并紧跟触发组，不与异动类型、生效日期混组。
- 异动登记：异动信息（异动类型 → 生效日期）→ 异动说明（原因）。与学籍异动同为「异动信息 + 异动说明」，字段顺序一致，两窗不产生两套读法。
- 调班：班级关系（目标班级）→ 调班说明（调班原因）。原班级继续以页头只读标签展示，不重复成组。
- 「需要审批」提示属于异动类型的结果，留在异动信息组内；说明性提示位于分区之上或所属分组内。
- 提交与取消固定在 `dialog-footer`，分组内不出现任何动作按钮；校验汇总在分区之外。

## 与冻结版本的差异

冻结 v1 的同名三窗是平铺字段，没有分组标题。v2 只增加 `.layout-sections`、`section[data-layout-group]`、`h3` 与分区边界，字段集、标签、必填标记、提示文案、组件标注（`data-component`）、`id`、动作与接口（`changeEnrollmentStatus` / `transferStudentClass`）逐字未改；字段原文与冻结 v1 的同名块逐行一致（另对「原因」补 `span-2` 让文本域跨满两列，校验汇总移出字段网格并去掉多余的 `span-2`）。

## 缺项

`PAGE-STU-TRANSFER` 与本批没有改字段集，但核对上游时发现口径冲突：学生 PRD 6.1 要求该弹窗含「生效日期」，而学生 PRD 7.3 的调班审计只列「原班级、新班级、学年学期、操作人」，班级模块的同名弹窗 `PAGE-CLS-TRANSFER` 含生效日期。依据 `AGENTS.md` 第 4 节登记 GAP-077 并保持现状，弹窗内已就地标注，未自行补字段。

## 逐字段自检

| 字段 | 所属组 | 组内是否同主题 | 是否跨组掺杂 | 依赖顺序 | 与表格顺序 |
|---|---|---|---|---|---|
| `change_type` 异动类型 | 异动信息 | 是（异动动作） | 否 | 触发字段，排在最前 | 不适用，本批对象是弹窗，页面无对应异动表格 |
| `effective_date` 生效日期 | 异动信息 | 是（异动动作） | 否 | 跟在异动类型之后，先动作后时间 | 不适用 |
| `class_id` 复学 / 报到后的班级 | 复学 / 报到安排 | 是（条件归属） | 否 | 紧跟触发组，不与必填字段混组 | 不适用 |
| `reason` 原因 | 异动说明 | 是（说明） | 否 | 排在动作与归属之后 | 不适用 |
| `class_id` 目标班级 | 班级关系 | 是（班级归属） | 否 | 唯一必填项，排在原因之前 | 不适用，调班不改列表列序 |
| `reason` 调班原因 | 调班说明 | 是（说明） | 否 | 排在目标班级之后 | 不适用 |

学生列表表格与详情抽屉、年级相关浮层不在本批范围，未做表单与表格顺序比对；`scope` 中的其余页面保持 v1 规则，不据此声称全部既有页面通过。
