## 2. 变更原因

批次 2-7a 落地选科配置 / 学生选科 / 选科清单三页时，公共前置反查暴露四类问题：

1. `06-field-dictionary.yaml` 里只有 `stream_deadline`、`primary_subject_code`、`secondary_subject_codes`，
   而选科配置表单还需要「开放期起点」与「逾期需审批」两个字段；组合分布统计还需要「选科组合」这个展示值。
   不补登记，阶段 5 建表与阶段 6 的类型定义就没有权威字段名。
2. 选科模块的权限码在矩阵里已经存在（`stream.config` / `stream.selection` / `stream.change_request`），
   但原型沿用了邻近模块的 `org.subject` / `person.student` / `enrollment.transfer`，
   会让阶段 6 的按钮权限注解指向错误的资源。
3. 选科配置与选科清单把「租户管理员」当作可写 / 可读角色，与 PRD 2.1「租户管理员无选科教学数据范围」冲突；
   同时校领导被当成只读，与矩阵 `stream.config [read, update]` 冲突。
4. `PAGE-STR-STAT` 在登记表里是列表页内的一个区块，但 PRD 6.1 写明是独立页且角色包含校领导
   （校领导并不在选科清单页的角色集合里，若做成区块则校领导没有入口）。
