## 口径（与 PRD / BR / 权限矩阵对齐）

- **只追加**：日志表不提供更新与删除，控制器与 Mapper 都没有对应入口（`BR-AUDIT-003` / `NFR-AUDIT-05` / `REQ-AUD-025` / `REQ-AUD-030`）；数据库账号层面的收权属运维动作（`REQ-AUD-031`）。
- **同事务写入**：`recordLog` / `recordChange` 标 `@Transactional`，供业务侧「业务写 + 日志写」同事务提交（`REQ-AUD-035` / `BR-AUDIT-010`）。
- **幂等写入**：`uk_audit_idempotent = (request_id, object_id, action_type)`，命中直接复用原记录（`REQ-AUD-035`）。
- **只记变化的字段**：`recordChange` 在前后值相同时直接跳过（`REQ-AUD-003`）。
- **敏感字段掩码**：写入与读取都对 18 位证件号（保留前 6 后 4）与 11 位手机号（中间 4 位）做掩码，日志不落明文（`REQ-AUD-010` / `BR-AUDIT-007` / `NFR-SEC-06` / PRD 5.3）。
- **查询不记、导出必记**：日志查询不写日志（避免噪声），日志与运营访问记录的**导出**走导出引擎并落任务记录（`REQ-AUD-011` / `REQ-AUD-029` / `NFR-AUDIT-03`）。
- **时间范围**：列表默认最近 7 天（`REQ-AUD-020`）；单次跨度上限 90 天，超出直接拒绝并提示收窄（`REQ-AUD-021` / `NFR-PERF-02`）。
- **筛选与检索**：按时间范围 / 操作人 / 对象类型 / 对象标识 / 操作类型 / 批次号筛选（`REQ-AUD-018`），关键字检索对象标识、对象名称、请求标识（`REQ-AUD-019`），列表默认时间倒序（`REQ-AUD-020`）。
- **对象时间线**：`listObjectChangeLog` 按 `(object_type, object_id)` 返回该对象全部变更记录（`REQ-AUD-023` / `BR-PROMO-012`）。
- **敏感数据访问**：按 `action_type = 'view_sensitive'` 过滤（动作码取自 `06-field-dictionary.yaml` 的 `audit_action_type`），掩码展示不记录（`REQ-AUD-008` / `REQ-AUD-009` / `REQ-AUD-012`）。
- **登录与安全事件**：按 `login` / `account_locked` / `activation_view` / `activation_reset` / `student_no_change` / `permission_change` 六个动作码过滤，取值与 `v_edu_audit_security_event` 视图定义一致（`REQ-AUD-007` / `BR-AUDIT-012`）。
- **运营访问记录**：按 `operator_role = 'platform_ops'` 过滤，租户侧可自助查询与导出（`REQ-AUD-013` ~ `016` / `SCN-AUDIT-02` / `SCN-AUDIT-03`）；记录归属被访问租户由租户拦截器写入的 `tenant_id` 保证。
- **归档检索**：`searchArchivedLog` 必须给时间范围，按 `edu_audit_log_archive` 检索（`REQ-AUD-033`）；归档批次列表供运维查看范围、行数、状态与失败原因（`REQ-AUD-034`）。
- **权限**：查询用 `audit.log:read`，导出用 `audit.log:export`（`05-permission-matrix.yaml` 第 139—152 行资源清单 + PRD 5.1）。
- **数据权限来源表**：`edu_data_grant` / `edu_data_grant_scope` 只落实体与数据层，供下一批 `DataScopeResolver` 的「叠加共享授权」使用（架构文档 09 第 3 节）；授权管理端点不在 openapi 的 181 个 operationId 内，**不另造接口**（`BR-DATA-015` / `017` / `018`）。

## 两个视图的处理（登记 GAP-095）

迁移脚本 `V4__edu_promotion_stream_support.sql` 第 500 行与第 504 行定义了两个派生视图：

| 视图 | 列 | 本批处理 |
|---|---|---|
| `v_edu_audit_operator_access` | 含 `tenant_id` / `school_id` | 本来可直接查；为与安全事件走**同一套范围条件与排序**，统一改用基表 `edu_audit_log` 加 `operator_role = 'platform_ops'` 等价过滤，再由 `EduAuditOperatorAccessVo` 把 `detail` 投影为 `purpose` |
| `v_edu_audit_security_event` | **没有 `tenant_id`** | 直接查视图会让租户隔离失效（要么跨租户返回、要么给视图加排除项后完全失去隔离）；因此改用基表加同一组 `action_type` 等价过滤，租户隔离交给租户拦截器 |

理由与推荐方案见 **GAP-095**；两个视图是阶段 5 冻结产物，本批不改冻结产物。
