## 2. 变更原因

批次 2-2b-2b 开工前登记的 `GAP-038` 有两个问题：年级 PRD 6.1 写「新建年级 = 弹窗」，
但 `navigation.yaml` 注册成 `drawer`；同时 PRD 6.1 没有「编辑年级」页面，而 4.4 节有 4 条编辑需求。

用户的裁决是「选 A」，并追加了一条更重要的口径：**载体要跟 `apps/plus-ui` 的现状保持一致**。
核查结果（`apps/plus-ui/src/views` 与 `apps/plus-ui/src/components` 全量扫描）：

| 项 | 实测 |
|---|---|
| `<el-dialog>` | **40 处** |
| `<el-drawer>` | **0 处** |
| dialog 宽度分布 | 500px ×13、800px ×4、700px ×3、80% ×3、600px ×2、750px ×2、780px/400px/1100px/650px/550px 各 1、百分比若干 |

即现有前端习惯是"表单与详情都用弹窗"，原型此前的"表单用抽屉"是与代码库不一致的写法。
年级 PRD 6.1 本来就写"弹窗"，因此本次只需改原型规范与 `navigation.yaml`，**不动冻结 PRD**。

## 3. 变更内容

1. `PAGE-GRD-CREATE`（新建 / 编辑年级）→ `dialog`，`size: md`（600px，落地 600px）；编辑复用同一弹窗的编辑态，不另立页面。
2. `PAGE-GRD-BATCH`（按学段批量生成）→ `dialog`，`size: md`；生成的年级清单用**列表**渲染，不用表格（`layout-spec` 禁止在弹窗内放表格）。
3. `PAGE-GRD-LEADER`（指定年级主任）→ `dialog`，`size: md`；任职清单同样用列表渲染。
4. `PAGE-GRD-ARCHIVE`（归档确认）与 `DIALOG-GRD-DELETE`（删除确认）保持 `dialog`，`size: sm`。
5. `PAGE-GRD-DETAIL`（年级详情）保持 `detail + container: drawer`：这是 PRD 6.1 的显式要求，属于"抽屉只用于详情"的例外。
6. `layout-spec.yaml` 新增 `dialog.carrier_rule`，并给出落地宽度映射 sm → 500px、md → 600px、lg → 800px。
7. `prototype-quality-spec.md` 第 5 节补充例外说明，避免后续批次再按"必须用抽屉"返工。

## 5. 替代方案

- 维持抽屉：与 `apps/plus-ui` 现状冲突，阶段 6 要么新引入一套抽屉写法，要么回头改原型。
- 新建时用弹窗、编辑时另立 `PAGE-GRD-EDIT`：页面数 13 → 14，且两份几乎相同的表单会各自漂移。
