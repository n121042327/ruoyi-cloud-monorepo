# CR-100 — 阶段 7 第二十一批：补 ruoyi-edu 缺失的 logback-plus.xml

用户启动 ruoyi-edu 时进程退出（exit 1），报 Logging system failed to initialize using configuration from
'classpath:logback-plus.xml' / FileNotFoundException: class path resource [logback-plus.xml] does not exist。

## 根因

logback-plus.xml 不是公共模块的资源，而是每个应用模块各带一份（auth / gateway / gen / job / resource /
system / workflow / monitor / snailjob / demo / test-mq 都有），ruoyi-edu 在 CR-054 建骨架时漏了。
而 Nacos 的 application-common.yml 里写死了 logging.config: classpath:logback-plus.xml，
文件缺失 → 日志系统初始化失败 → 进程退出（日志里那条 No appenders present in context [default] 就是退化成默认配置的表现）。

## 改动

| 落点 | 说明 |
|---|---|
| `.../ruoyi-modules/ruoyi-edu/src/main/resources/logback-plus.xml`（新增） | 从 ruoyi-modules/ruoyi-system/src/main/resources/logback-plus.xml 复制（各模块该文件差异仅为空白与格式）；文件内 log.path 用 Maven 的 project.artifactId 占位，打包时被资源过滤替换为模块名 |

## 编译与验证

```
mvn -o -DskipTests -pl ruoyi-modules/ruoyi-edu -am clean package   -> BUILD SUCCESS
ruoyi-edu.jar  ->  BOOT-INF/classes/logback-plus.xml 存在，log.path = logs/ruoyi-edu（过滤生效）
python tools/check_stale_classes.py  ->  未发现幽灵 class（通过）
```

按 AGENTS 第 9 节：只声明编译与产物检查通过，未启动服务、未跑接口测试。
证据：`evidence/stage7-backend/2026-10-08_edu-logback-config_fix.log`。

## 经验

新增应用模块时，除了 application.yml 与启动类，还要从同目录的兄弟模块拷一份 logback-plus.xml；
否则启动会直接死在日志初始化阶段，报错位置与真正原因（资源缺失）看起来不相关。
