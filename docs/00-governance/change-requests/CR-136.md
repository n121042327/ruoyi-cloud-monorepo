# CR-136 — 阶段 7 第五十五批：导入导出文件改为真实短时预签名链接 + 下载审计（收口 GAP-093）

自动化队列第 2 项。核对时确认 edu 侧两处「签名链接」都是占位字符串，用户拿到的是一个自造的
`/edu/file/download/{id}?key=...` 路径 —— 既不指向对象存储，也没有有效期概念。

## 1. 改动

| 层 | 文件 | 改动 |
|---|---|---|
| 远程契约 | `ruoyi-api-resource/.../RemoteFileService.java` | 新增 `signedDownloadUrl(String ossId, long ttlSeconds)` |
| 降级实现 | `RemoteFileServiceMock.java` | 服务不可用时返回 null + warn |
| 文件服务 | `ruoyi-resource/.../RemoteFileServiceImpl.java` | `getById` → `removeBaseUrl` → `createPresignedGetUrl(objectKey, Duration.ofSeconds(ttl))` |
| edu 任务 | `EduAsyncTaskServiceImpl.java` | `buildSignedUrl` 改调远程签名；下载后写审计（学校上下文取任务） |
| edu 导入导出 | `EduImportExportServiceImpl.java` | `buildDownload` 改调远程签名；下载后写审计（学校上下文取文件引用） |

结果：模板 / 失败明细 / 结果 / 任务结果四类下载都返回对象存储签发的、带有效期的真实 GET 链接（TTL 5 分钟），
并在下载时写一条 `audit.log`（`actionType=export`、`object_type=file`、`detail=下载文件：…`），满足
`REQ-IMP-042` / `045` 与 `REQ-IMP-043` 的下载留痕。

## 2. 与设计口径的关系

设计里写的是「短时签名链接且与登录态绑定」。本批实现的是**对象存储预签名链接**：有效期由存储侧保证，
谁拿到链接谁就能在有效期内下载（这是预签名机制的固有性质）。「与登录态绑定」由 edu 侧在签发前完成：
数据范围重解析、文件归属校验（`bizId` 必须是本任务）、过期判断、下载计数累加，全部在签发之前执行。
真正的「每次下载都校验登录态」需要走应用代理流式转发（`RemoteFileService.downloadByUrl` 已在学生照片上走通），
但那样会让大文件经过应用服务器，与 `NFR-DATA-03`「文件不落应用服务器」的取向相反，故不采用。

## 3. 遗留（GAP-113）

`edu_audit_log.school_id` 非空。若文件引用 / 任务上没有学校上下文（例如平台级模板），本批只记 warn、
不写下载审计 —— 宁可少一条审计也不阻塞下载。已登记 GAP-113，推荐做法是在文件引用落库时强制写入学校上下文。
