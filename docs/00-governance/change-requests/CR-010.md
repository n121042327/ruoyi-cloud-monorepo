## 2. 变更原因

### 2.1 `GAP-043`：任课教师缺 `org.class` 读权限

班级 PRD 第 101 行写明任课教师的数据范围是 `DS-07`「只读任教班级的必要资料」，
第 188 行 `REQ-CLS-012` 要求任课教师看花名册时按字段裁剪，第 230 行 `REQ-CLS-034` 要求禁止其导出花名册。
但权限矩阵的 `subject_teacher` 只授了 `org.teaching_class: read` 与 `person.student: read`，
漏了 `org.class: read`，导致按矩阵实现时任课教师打不开班级列表。
年级模块出现过同类问题（`GAP-035`），当次裁决为"补权限"，两次保持同一口径。

### 2.2 `GAP-044`：班级状态没有取值，字段也未登记

班级 PRD 7.1 的班级实体列了 `status` 却全文没有取值，字段字典也没有 `class_status` 枚举。
可由已冻结 PRD 文本直接推出的只有两个值：`在读`（`REQ-CLS-004` / `007` 的"在读人数"）
与 `已停用`（`REQ-CLS-043` / `044` 的"停用"、`disableClass` 接口）。

### 2.3 `GAP-045`：校区与教室字段未登记

班级 PRD 7.1 与 6.2 都要求展示"校区、教室"，但字段字典里既没有 `campus_id` 也没有 `classroom`，
原型的 `data-field` 无法回溯到字段字典（`markup-contract.md` 第 9 节自查第 5 条不满足）。

## 3. 变更内容

1. **权限矩阵**：`subject_teacher` 增加 `org.class: read`，条件写明"仅任教班级的必要资料（`DS-07`）；
   不含班主任变更与编班，且禁止导出花名册（`REQ-CLS-012` / `REQ-CLS-034`）"。
2. **`class_status` 枚举**（字段字典）：只登记两个值——`studying`（在读）、`disabled`（已停用）。
   两条口径写进枚举注释：学年归档不改变班级状态（`REQ-TERM-030` 只把归档学年移出新建班级的可选列表）；
   「已合并」随班级合并功能（`REQ-CLS-045`，首轮延后）一并评估，本轮不登记。
3. **字段登记**：
   - `class_status`：`varchar(16)`，必填，`enum_ref: class_status`，`BR-CLASS-006`；
   - `campus_id`：`bigint`，可空，引用 `edu_campus`，注明校区不参与权限判定（`BR-ORG-009`）；
   - `classroom`：`varchar(50)`，可空，自由文本，与容量一样只作参考信息。
4. **班级 PRD 7.1**：字段名 `status` → `class_status`；7.2 的索引前缀同步（并补"按校区列班级"）；
   新增 7.3 节给出取值表与两条口径说明。
5. **页面规格**：`page-specs/class-list.md` 的自查第 5 条由"未满足"改为"满足"。

## 5. 替代方案

- **`GAP-043` 选项 B（不补权限）**：任课教师打开班级列表只有"无权限"态，
  与班级 PRD 2.1、`REQ-CLS-012`、`REQ-CLS-034` 三条冲突，验收无法通过。
- **`GAP-044` 选项 B / C（一次补 4 或 6 个状态值）**：`已归档`、`待启用`、`已毕业` 的语义还没定
  （学年归档后班级是否跟着变、毕业年级班级是否单独一个状态），先猜再改会让数据范围解析与筛选一起返工。
- **`GAP-045` 选项 B（校区存文本）**：失去"按校区分组与统计"的能力，
  与学校模块把校区当独立实体（`edu_campus`、`REQ-SCH-027` / `028`）的设计冲突。
