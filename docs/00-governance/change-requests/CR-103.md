# CR-103 — 阶段 7 第二十三批（二）：edu 表补 `create_dept`，修通用读写 500

修完 CR-102 的权限问题后，页面从「403」变成「500」，`logs/ruoyi-edu/error.log` 给出：

```
### Error querying database.  Cause: java.sql.SQLSyntaxErrorException: Unknown column 'create_dept' in 'field list'
### The error may exist in org/dromara/edu/mapper/EduSchoolMapper.java (best guess)
### SQL: SELECT id AS schoolId, ..., del_flag, tenant_id, create_dept, create_by, create_time, update_by, update_time
           FROM edu_school WHERE del_flag = '0' AND (tenant_id = ?) AND tenant_id = '000000' LIMIT 1
```

## 1. 根因

RuoYi 的 `BaseEntity`（`ruoyi-common-mybatis/.../core/domain/BaseEntity.java`）带
`@TableField(fill = FieldFill.INSERT) private Long createDept;`，阶段 7 约定「platform 继承 BaseEntity、
school/tenant 继承 TenantEntity」，因此 MyBatis-Plus 生成的通用 select / insert / `selectVoById` 一律会带 `create_dept`；
而事实源 `docs/40-detailed-design/database/schema.yaml` 第 14 行的 `conventions.audit_columns` 只登记了
`create_by / create_time / update_by / update_time`，于是阶段 5 生成的建表脚本 43 张 edu 表**一张都没有这一列**。

只有手写 SQL 的列表查询（`selectPageGradeList` 等）能跑，任何走通用 MP 方法的接口（`/edu/school/current`、
`/edu/stream/config`、各种详情 / 新增 / 编辑）都会 `Unknown column 'create_dept'` 报 500。

## 2. 影响范围

| 分类 | 表数 | 说明 |
|---|---|---|
| 受影响（`with_audit: true`） | **31** | 实体继承 BaseEntity / TenantEntity，通用读写全部报 Unknown column |
| 不受影响（`with_audit: false`） | 13 | 实体是普通类、自带字段（`edu_audit_log` / `edu_promotion_item` / `edu_activation_code` / `edu_stream_history` 等），不含 `create_dept` |

## 3. 处置

| 路径 | 改动 |
|---|---|
| `docs/40-detailed-design/database/schema.yaml`（改） | `conventions.audit_columns` 补 `create_dept`，并注明它是 RuoYi 平台通用列、BaseEntity / TenantEntity 默认携带 |
| `docs/40-detailed-design/migrations/V7__edu_audit_create_dept.sql`（新增） | 31 条 `ALTER TABLE ... ADD COLUMN create_dept bigint unsigned NULL COMMENT '创建部门' AFTER <create_by 前一列>`；V1~V6 为已冻结版本不改不重建，口径与 `V6__edu_student_contact.sql` 一致 |
| 本机 `ry-cloud` 库 | 已执行 V7（`docker cp` + `mysql --default-character-set=utf8mb4`） |

## 4. 验证

```
information_schema 中带 create_dept 的表：19（stock）→ 50（19 stock + 31 edu）
edu 侧「有 create_by 却没有 create_dept」的表：0
事务内 INSERT edu_grade(..., create_dept=103, create_by=1) 成功并 ROLLBACK，表内行数仍为 0
/edu/school/current  → {"code":500,"msg":"当前租户尚未接入学校"}      （业务提示，不再是 SQL 异常）
/edu/stream/config   → {"code":500,"msg":"当前学校尚未配置选科开放期"} （业务提示，不再是 SQL 异常）
/edu/term/list、/edu/subject/list、/edu/class/list、/edu/grade/list、/edu/audit/log/list → 全部 200
```

## 5. 遗留（非代码缺陷）

本机 `ry-cloud` 库没有任何 `edu_school` 数据，所以「学校」「选科配置」等依赖学校上下文的页面仍会提示
「当前租户尚未接入学校」。这属于**演示数据未初始化**（`edu_school` → 学年学期 → 年级 → 班级 一条链），
不是接口缺陷；若要跑通业务流，需要先建一所学校。
