## 2. 变更原因

### 2.1 字段字典缺 7 条，向导第 2 ~ 4 步的 `data-field` 回溯不到条目

升班 PRD 7.1（第 379 行起）已经把升班明细定义为
`task_id` / `student_id` / `source_class_id` / `target_class_id` / `result_type` / `status` / `error_msg`，
唯一键 `(task_id, student_id)`；4.3 节的 `REQ-PRM-016` ~ `018` 又要求支持
「留级、转班、毕业、跳过」四种调整方式与「按源班级整体指定目标班级」。
但 `06-field-dictionary.yaml` 里与升班相关的只有任务主体那 6 个字段与 `promotion_task_status` 枚举。

字段字典开头的 `purpose` 写明「任何模块 PRD、原型表单、接口契约、数据库迁移脚本中的字段，都必须能在这里找到定义」。
缺登记的直接后果：

- 向导第二步（预览与调整）的每一行都需要 `data-field`（学号 / 姓名 / 原班级 / 目标班级 / 结果类型 / 调整原因），查不到条目；
- 第三步（校验）需要「通过 / 警告 / 错误」的三分类（`REQ-PRM-023`），没有枚举可引用；
- 第四步（结果）的四类清单（成功 / 失败 / 留级 / 毕业）直接依赖 `result_type` 与明细状态的取值；
- 阶段 5 的 `edu_promotion_task_item` 缺字段名与取值依据（`result_type` 是列还是字典表也定不下来）。

### 2.2 「任务状态」与「明细状态」都叫 `status`，必须显式分工

PRD 7.1 的两行都用 `status`：任务行指 `promotion_task_status`（8 个值），明细行指明细自身的状态。
`CR-013` 已把任务行落地为 `promotion_task_status`；本次把明细行落地为 `status` + 枚举 `promotion_item_status`，
并在 PRD 6.1 / 7.1 各加一段口径说明，避免同一个词在一页里指两个对象。

### 2.3 `BR-PROMO-006` 只说「显式指定」，没说去到哪个年级

「留级」在数据上表现为「学生在目标学年学期的同学段同名年级」（如 2026 级 高一 → 2027-2028 学年 高一），
原规则只写了「不参与默认升级、需显式指定」，实现者可能理解成「留在源学年的原年级」——那是改写历史，
与 `BR-PROMO-001`（按学年追加、不改写历史）冲突。本次把去向补进规则原文。

## 3. 变更内容

1. **字段字典新增 7 个字段**（`docs/10-prd/06-field-dictionary.yaml`，`fields:` 的升班分组之后）：

| 字段 | 中文 | 类型 | 必填 | 枚举 | 说明 |
|---|---|---|---|---|---|
| `task_id` | 所属任务 ID | `bigint` | 是 | — | 与 `student_id` 组成唯一键；幂等键的组成部分（`REQ-PRM-029`） |
| `student_id` | 学生 ID | `bigint` | 是 | — | 平台级学生主体，不参与学校租户隔离（`D-037`） |
| `source_class_id` | 源班级 ID | `bigint` | 否 | — | 毕业年级或源学年无行政班关系时为空 |
| `target_class_id` | 目标班级 ID | `bigint` | 否 | — | 必须属于目标学年学期（`REQ-PRM-022`）；留级 / 毕业 / 跳过时为空 |
| `result_type` | 升班结果类型 | `varchar(16)` | 是 | `promotion_result_type` | 默认升级，可逐条调整（`REQ-PRM-014` / `017`） |
| `status` | 明细状态 | `varchar(16)` | 是 | `promotion_item_status` | 与任务状态分层 |
| `error_msg` | 失败原因 | `varchar(500)` | 否 | — | 逐条记录，支持只重试失败项（`REQ-PRM-032`） |

2. **字段字典新增 3 个枚举**：

| 枚举 | 中文 | 取值 | 依据 |
|---|---|---|---|
| `promotion_result_type` | 升班结果类型 | 升级 / 留级 / 转班 / 毕业 / 跳过 | `REQ-PRM-014`（默认升级）、`REQ-PRM-015`（毕业）、`REQ-PRM-016` / `017`（留级 / 转班 / 毕业 / 跳过） |
| `promotion_item_status` | 升班明细状态 | 待处理 / 成功 / 失败 / 跳过 | `REQ-PRM-020`（预览只生成明细）、`REQ-PRM-032`（逐条失败原因）、`REQ-PRM-034`（成功 / 失败清单）、`REQ-PRM-017`（跳过） |
| `promotion_validation_level` | 升班校验级别 | 通过 / 警告 / 错误 | `REQ-PRM-023`（原文三分类）、`REQ-PRM-024`（容量只警告）、`REQ-PRM-025`（错误必须处理） |

3. **`BR-PROMO-006` 补去向**（`docs/10-prd/04-business-rules.md`）：
   留级的去向是「目标学年学期的同学段同名年级」，仍不改写源学年记录。
4. **升班 PRD 6.1 补字段口径说明**：调整弹窗写 `result_type` 与 `target_class_id`；明细状态用 `status`，
   与任务状态 `promotion_task_status` 分层；7.1 第 1 行的 `status` 指 `promotion_task_status`。
5. **升班 PRD 6.3 补两行交互**：「预览中指定留级」（去向为同学段同名年级）、
   「预览中指定转班」（目标班级必须属于目标学年学期，目标班级已停用时校验报错）。
6. **升班 PRD 7.1 修正**：`result_type` 的取值补「转班」（原文只写了升班 / 留级 / 毕业 / 跳过，与 6.1 的
   `PAGE-PRM-ADJUST`、4.3 的 `REQ-PRM-017` 不一致），并加一段任务 / 明细状态的区分说明。
7. **升班 PRD 版本**由 `1.0.3-draft` 升为 `1.0.4-draft` 并补变更记录。
