# CR-033 — 学生详情抽屉字段分组

用户要求继续。本批把 `docs/00-governance/page-field-layout.md` 的约束落到学生详情抽屉——学生列表页最后一个未整理浮层。继续授权不记为人工验收通过。

## 覆盖对象

`prototypes/{functional,high-fidelity}/v2/pages/student-list.html` 的 `PAGE-STU-DETAIL`（抽屉，lg）。

## 原状与问题

抽屉第一张卡片标题是「基本信息」，卡片内 9 个字段平铺在同一个 `form-grid` 里：
姓名、性别、学号、全国学籍号、证件号码、联系电话、入学年份 / 学段、年级 / 班级、学籍状态。
这些字段分属四个主题（基础信息、教育信息、证件信息、联系方式），混在一组；字段顺序也与 CR-027 的新增 / 编辑学生表单不一致（表单是 学号 → 全国学籍号 → 姓名 → 性别）。

## 改动

- 卡片标题由「基本信息」改为**学生信息**，卡片内分四组：
  基础信息（学号 → 全国学籍号 → 姓名 → 性别）／教育信息（入学年份 / 学段 → 年级 / 班级 → 学籍状态）／证件信息（证件号码）／联系方式（联系电话）。
- 顺序与 CR-027 的学生表单一致：基础信息在前，其次是教育信息，再到证件与联系方式。
- 证件号码与联系电话各自成组，字段级「查看完整」按钮（`ACT-STU-023`）随字段留在本组内；证件号码与联系电话改为 `span-2`，避免跨列错位。
- 监护人（上限 3）与变更记录两张卡片保持原样：前者是子清单（含 `ACT-STU-024` / `ACT-STU-034`），后者是时间线区块。
- 抽屉页头继续显示姓名、学籍状态与学号标签（身份摘要）；详情字段仍按 `sd-f-*` 的 id 填充，重排不影响取值。

## 验证与验收

新增 `evidence/stage2-prototype-v2/verify-student-detail-layout.html`，业务与高保真各 8 项（分组顺序、组内字段、证件与联系方式不混组、卡片标题、按 id 填充、页脚操作、无重复字段）；先用冻结 v1 跑出 7 项失败的基线。学生模块回归 `verify-student-layout-list-cr029.html` 28 项通过。本批合计 44 项通过，计数与命令见 `evidence/stage2-prototype-v2/2026-10-02_student-detail-batch-verification.log`。

人工验收：打开学生列表，点任意一行进入详情抽屉，确认四组标题与字段顺序，并确认证件号码、联系电话的「查看完整」仍在各自组内。人工验收待确认；接口与数据权限未执行。
