## 2. 变更原因

批次 2-2b-2b 开工前按 `D-051` 做公共前置反查，发现年级模块有四处「上游文档之间或文档与现实之间对不上」，
会直接决定原型上按钮、菜单与字段的形态，因此先停下来登记缺项，不自行补造。

| 缺口 | 一句话问题 | 推荐裁决 |
|---|---|---|
| `GAP-034` | 校领导对年级是只读还是可写，年级 PRD 与权限矩阵写法相反 | 选项 B：校领导对 `org.grade` 只读 |
| `GAP-035` | 年级主任 / 班主任 / 任课教师能不能进年级管理看自己范围内的年级 | 选项 A：三个角色各补 `org.grade` 的 `read`，范围按 `DS-05` / `DS-06` / `DS-07` 收窄 |
| `GAP-036` | 建错的空年级能不能删掉，谁有权删 | 选项 B：教务主任与租户管理员可删空年级（逻辑删除） |
| `GAP-037` | 年级状态、班级数、在读学生数、年级主任任职字段没有权威字段名 | 选项 A：一次补全年级模块字段 |

## 3. 变更内容（已按推荐方案执行，见第 8 节执行记录）

### 3.1 `GAP-034`：校领导对 `org.grade` 收为只读

```yaml
  - role: school_leader
    entries:
      - { resource: org.grade, actions: [read] }   # 由 [read, create, update] 收为 [read]
```

并在年级 PRD 第 2.1 节补一句口径说明：校领导对本模块**只读**，
年级主任任职的变更由校领导审批（`SCN-TEACHER-01` 的「审批」列），不由校领导直接录入。

### 3.2 `GAP-035`：补三个角色的年级读权限

```yaml
  - role: grade_leader
    entries:
      - { resource: org.grade, actions: [read], condition: 仅本人负责的年级（DS-05） }

  - role: homeroom
    entries:
      - { resource: org.grade, actions: [read], condition: 仅本班所属年级（DS-06） }

  - role: subject_teacher
    entries:
      - { resource: org.grade, actions: [read], condition: 仅任教班级所属年级的年级摘要（DS-07） }
```

同时确认：三个角色都**没有** `org.grade` 的 `create` / `update` / `delete`，
对应年级 PRD 第 2.1 节「年级主任只读本人负责年级」「班主任与任课教师只读年级摘要」。

### 3.3 `GAP-036`：年级删除的权限点与入口

```yaml
  - role: academic_director
    entries:
      - { resource: org.grade, actions: [read, create, update, delete] }
        condition: delete 仅在年级下无班级且无学生关系时可用

  - role: tenant_admin
    entries:
      - { resource: org.grade, actions: [read, create, update, delete] }
        condition: 同教务主任
```

约束（与 `REQ-GRD-030` 不冲突，因为删除是逻辑删除，不是物理删除）：

1. 年级下存在班级或学生关系时，接口直接拒绝，提示改用归档（`BR-GRADE-005`）
2. 二次确认并必填原因，写审计（`REQ-GRD-031`）
3. 原型新增浮层片段 `DIALOG-GRD-DELETE`（小尺寸二次确认）
4. 年级 PRD 第 6.1 节页面清单与第 6.3 节交互表补删除入口

### 3.4 `GAP-037`：字段字典补年级模块字段

新增枚举 `grade_status`：`在读` / `已归档`（取值与 `06-field-dictionary.yaml` 的既有命名风格一致；
若年级还需要「未启用」「已删除」等中间态，请一并指出）。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `grade_status` | 年级状态 | `varchar(16)` | 是 | 枚举 `grade_status`；归档后为「已归档」，仍可查询（`REQ-GRD-029`） |
| `class_count` | 班级数 | `int` | 否 | 统计值，受数据范围约束（`REQ-GRD-006`、`DS-DENY-08`） |
| `student_count` | 在读学生数 | `int` | 否 | 统计值，口径与班级模块一致（`REQ-GRD-009`） |
| `leader_user_id` | 年级主任用户 ID | `bigint` | 否 | `edu_grade_leader.user_id` |
| `leader_status` | 年级主任任职状态 | `varchar(16)` | 否 | 生效中 / 已解除 |
| `effective_date` | 任职生效日期 | `date` | 否 | `REQ-GRD-027` 的审计要素 |
| `expire_date` | 任职失效日期 | `date` | 否 | 学年切换时写入 |

> 说明：`stage_name`、`school_name`、`term_name`、`leader_name` 属于展示名，由引用实体的名称列带出，
> 与 CR-004 对教师模块的处理保持一致，不单独登记为业务字段。

## 5. 替代方案

- `GAP-034` 选 A：年级模块会成为全平台唯一由校领导直接录入组织数据的模块，与 CR-004 的口径不一致。
- `GAP-035` 选 B 或 C：`DS-05` 这条数据范围在原型与生产端都没有落点，
  「年级主任只看本年级」无法演示也无法验收。
- `GAP-036` 选 A：建错的年级会永久占用「学校 + 学段 + 入学年份 + 学段内序号」这个唯一键，
  只能靠人工改库，开学季最容易踩到。
- `GAP-037` 选 B 或 C：年级详情与年级主任任职两个浮层会立刻用到这些字段，分两次补要重复走两遍 CR。

## 6. 如果错了的代价

- `GAP-034` 若日后确要给校领导写权限：改回一行矩阵并补验收用例，不涉及数据迁移。
- `GAP-035` 若日后要收回某个角色的读权限：删掉该角色的一行 entries，范围与菜单同步变化。
- `GAP-036` 若日后不允许删除：把权限点收回并让删除入口只保留给租户管理员，已软删的数据不需要回滚。
- `GAP-037` 若某个字段名不合适：改字段字典一行加一处 `data-field`，此时尚未建表。
