# CR-105 — 阶段 6 第二十五批：学校管理页补「新建学校 / 编辑学校」弹窗，并修状态字段名

上一批（CR-104）修好建校接口后，学校管理页仍然只能靠接口建校：`CR-059` 把这批浮层排在"下一批"。
本批补齐 `PAGE-SCH-CREATE` / `PAGE-SCH-EDIT` 两个弹窗，并修掉该页三个字段名不一致的问题。

## 2. 顺带修掉的字段名不一致（本页可见缺陷）

| 现象 | 原因 | 处置 |
|---|---|---|
| 状态列永远显示「正常」，停用按钮永远显示「停用」 | 后端 `EduSchoolVo` 字段是 `schoolStatus`，前端读的是 `row.status`（恒 undefined） | 统一改 `schoolStatus` |
| 查询区「状态」筛选无效 | 前端传 `status`，后端 `queryPageList` 读的是 `SchoolBo.schoolStatus` | 查询参数改 `schoolStatus`（后端 `eq(schoolStatus)` 已支持） |

## 3. 按模块边界做的取舍（见 D-184 / D-185 / GAP-101 / GAP-102）

1. **「开设学段」不放进新建弹窗**：原型把学段作为新建必填项，但学段的写入入口按模块边界只有一处
   （`POST /edu/school/{id}/stage` 的「学段配置」与「开通初始化」向导），新建弹窗里再写一次会出现两个写入入口；
   而且 `POST /edu/school` 返回 `R<Void>` 不带 schoolId，弹窗内拿不到新学校 ID。
2. **「所属租户」只读**：学校与租户一一对应（BR-ORG-002），且后端 `insertByBo` 的 `tenant_id` 取登录会话，
   不接受前端指定；跨租户建校属于平台运营的开通流程。
3. **「学校编码」由用户确认**：原型写「由系统生成」，但后端契约是 `EduSchoolBo.schoolCode` 非空 + `uk_school_code` 唯一，
   编码规则在产品侧没有定义；本批按推荐口径落地为「按当前租户预填建议值，用户可修改」，并登记 GAP-102。
4. **学段筛选与列表统计列暂不实现**：`listSchool` 的后端查询只支持 `schoolStatus` / `schoolCode` / `keyword`；
   列表的「开设学段 / 校区数 / 班级数 / 在读学生」在 PRD 里只定义了详情页的统计摘要（`REQ-SCH-010`、`getSchoolSummary`），
   没有列表聚合口径 —— 登记 GAP-101，不擅自编聚合规则。
