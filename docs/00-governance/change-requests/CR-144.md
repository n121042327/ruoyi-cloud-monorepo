# CR-144 — 阶段 7 第六十三批：导入执行阶段 + 编班表执行器（GAP-094 第四批其一）

## 1. 交付

| 组件 | 说明 |
|---|---|
| `job/EduImportExecutor` / `EduImportRowResult` | 模块导入执行器接口；行结果三态 success / skipped / failed |
| `job/EduImportTaskRunner` | 导入任务异步执行器：抢占 → 重读文件 + 重跑校验 → 逐行执行 → 统计 → 写失败行 → 回写批次与任务 |
| `job/ClassRosterImportExecutor` | 编班表执行器（写班级关系，复用班级服务） |
| `EduAsyncTaskExecutor`（改） | 领取范围放开到导入任务；无模块执行器的导入任务不领取（保持 queued） |

## 2. 三个实现细节

1. **执行阶段重跑校验**：文件在对象存储里是不可变的，但「只执行通过的行」这件事不应依赖上一次的结论，
   因此执行前重跑一遍校验（只读）。校验阶段已写过的 `invalid` 行不重复写，执行阶段只补 `failed` 行。
2. **无执行器的模块不领取**：`tryRun` 先看批次模块有没有登记执行器，没有就返回 false，任务留在 `queued`。
   这样「学生 / 教师导入执行器还没落地」不会表现为「任务失败」，进度条也不会骗人。
3. **编班表走班级服务落库**：执行器只把行翻译成 `EduClassMemberBo`，冲突判定与写入由 `IEduClassService.addRoster`
   负责 —— 与页面编班走同一套规则（DP-01：班级关系的唯一写入口在班级模块）。

## 3. 幂等与冲突

| 情形 | 结果 |
|---|---|
| 学生已在本班 | `skipped`（幂等，不报错） |
| 学生已在别的行政班 | `failed` + 提示去班级管理调班（BR-STU-003） |
| 班级 / 学生不存在（理论上有校验挡着） | `failed` + 原因 |
