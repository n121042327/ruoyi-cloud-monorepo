## 口径（与架构文档 / BR 对齐）

- **拒绝规则**：缺少执行人或租户上下文一律 `ServiceException` 拒绝（`DS-DENY-01` / `DS-DENY-02` / `NFR-SEC-05`）；**不继承租户管理员的放行逻辑**（`DS-DENY-05`）。
- **唯一例外**：`LoginHelper.isSuperAdmin()` → `unrestricted`，跳过范围解析（`DP-07`）；按架构文档要求这一类访问仍要写审计（写入 API 已由 CR-092 的 `recordLog` / `recordChange` 提供）。
- **空集语义**：范围为空集时**返回空结果**，不退化为全量（`DS-DENY-03`）；SQL 侧体现为恒假条件 `1 = 2`，服务侧可先判 `isEmpty()` 直接短路。
- **共享授权叠加**：只取 `grant_status='active'` 且在生效期内、`grantee_type='tenant'` 且被授权对象是当前租户的授权，且 `access_level` ∈ {read, export}——**首轮不开放 write**（`BR-DATA-012` / `BR-DATA-013` / `BR-DATA-015` / `BR-DATA-018`）。
- **表清单来源**：`EduDataPermissionHandler` 的三组表名由 `schema.yaml` 推导（`scope: school` → `school_id`；显式 `grade_id` / `class_id` 列 → 并集条件），含派生表 `edu_audit_log_archive`；**平台级实体**（`edu_student` / `edu_guardian` / `edu_student_guardian`）与租户级表不参与学校范围判定。
- **条件全部来自上下文**：SQL 片段只用集合里的数字 ID，不接受任何请求参数，避免注入面。
- **班级任教关系只读**：唯一写入入口在教师模块（AGENTS 第 7 节模块边界），班级侧只提供只读清单与跳转（`BR-TEACHER-003`）。
