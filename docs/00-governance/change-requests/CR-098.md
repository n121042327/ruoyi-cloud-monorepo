# CR-098 — 阶段 7 第十九批：修正本机 Docker 环境的 MySQL 端口发布 / Redis 挂载 / 数据源密码

用户报「Navicat 连接不上 docker 里的 mysql」，排查后定位到三个独立问题并修掉前两个可静态修的：

## 三个问题与处置

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | Navicat 连 127.0.0.1:3306 失败 | mysql 用 `network_mode: "host"`，在 Windows + Docker Desktop(WSL2) 下端口只存在于虚拟机网络命名空间，**不会发布到 Windows**；`ports:` 在 host 模式下被忽略 | compose 里 mysql **去掉 host 网络**，改用默认 bridge + 已有 `ports: 3306:3306` |
| 2 | 密码 `ruoyi123` 登录被拒 | 数据卷 `/docker/mysql/data` 早已初始化，`MYSQL_ROOT_PASSWORD` **只在首次初始化生效**；实际 root 密码是 `root`（nacos 自带配置也写的是 root/root） | `script/config/nacos/datasource.yml` 四处密码 `ruoyi123` → `root`，与本机实际对齐（不改数据库） |
| 3 | redis 容器 Exited(1)、nacos 容器 Exited(1) | redis：compose 把宿主 `/docker/redis/conf` 挂到 `/redis/config`，Windows 下该路径在 WSL2 VM 内且不存在 → 空目录 → `redis-server` 找不到 redis.conf 退出；nacos：`ry-config` 库不存在，启动时连不上 | redis 卷改为相对 compose 文件的 `./redis/conf`、`./redis/data`；`ry-config` 库新建并导入 `script/sql/ry-config.sql` |

## 顺带完成的环境初始化（非仓库改动）

- `ry-cloud`：用 `--default-character-set=utf8mb4` 重新导入 `script/sql/ry-cloud.sql`
  （首次导入报 `Data too long for column 'nick_name'`，是**客户端字符集**问题而非文件编码——文件经校验是合法 UTF-8）；
  再按 V1→V6 导入 `docs/40-detailed-design/migrations/*.sql`。

## 结论与遗留

**Navicat 连接参数：主机 `127.0.0.1`、端口 `3306`、用户名 `root`、密码 `root`**（不是 `ruoyi123`）。

仍然存在的一项：`6379` / `8848` / `9000` 在 **Windows 侧不可达**（redis/nacos/minio 还是 host 网络，端口只存在于 WSL2 VM 内）。
Java 服务若跑在容器里（同 host 网络）不受影响；但若想在 Windows 的 IDE 里跑服务、或用浏览器访问网关 8080，就需要把这几个也改成 bridge + 发布端口——注意 nacos 改成 bridge 后必须把 `db.url.0` 指向 `mysql:3306`（服务名）而不能再用 127.0.0.1。此项未做，留待用户确认走哪条路（容器内跑服务 vs Windows 上跑服务）。
