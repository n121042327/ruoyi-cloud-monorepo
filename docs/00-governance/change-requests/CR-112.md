# CR-112 — 阶段 6 第三十一批：教育域页面不再展示内部编号与设计裁决说明

用户在 `/edu/import/wizard` 用浏览器批注指出页面上出现了内部设计说明（"是不是不应该出现在界面里"）。
这类文字指的是模板里的 `（REQ-IMP-002 / GAP-086 裁决）`、`（BR-IMP-007）` 这类括注 ——
它们写出来是为了对齐契约，读者是设计和实现者，不是产品的使用者。

终端用户是教务主任、年级主任、班主任：他们需要读到的是业务规则本身，不是需求编号。

## 1. 口径

- **不进 UI**：`REQ-*` / `BR-*` / `GAP-*` / `DS-*` / `RV-*` / `NFR-*` / `DP-*` / `IMP-*` / `PAGE-*` / `CR-*`
  等编号，以及「按 GAP-0xx 的推荐方案实现」「CR-0xx 裁决」这类设计裁决说明。
- **保留在代码里**：需要追溯的信息放 HTML 注释（`<!-- ... -->`）或写进 `docs/00-governance/**`；
  本次扫描与清理全程**跳过** HTML 注释。
- **业务说明照写**：去掉编号后句子本身是业务规则的，保留。
  例：`模板字段变更必须升版本；旧版模板会先报「模板版本过期」强提示，仍可继续。`
- **格式与业务示例不误伤**：`YYYY-MM-DD`、业务任务号 `PRM-20260930-0012`、班级示例 `高一 (2)(3) 班` 保留。

## 3. 保留项（逐条复核过，不是漏删）

| 保留内容 | 理由 |
|---|---|

| `高一 (2)(3) 班` / `高二 (1) 班` | 班级命名示例，括号里是班号 |

## 4. 过程中的三次工具缺陷（记录下来，避免再犯）

批量文本清理先后踩了三个坑，每一处都在提交前修复并复扫：

1. **非贪婪匹配漏扫**：`.vue` 里存在 `<template #header>` 这类嵌套标签，
   用 `<template>(.*?)</template>` 非贪婪匹配会在第一个 `</template>` 截断，大部分内容根本没进入扫描范围。
   改为贪婪匹配根 template。
2. **编号正则漏两段前缀**：`(?:REQ|BR|...)-\d+` 匹配不了 `REQ-IMP-036`（`REQ-` 后面是字母，不是数字），
   导入类页面的编号整批漏删。改为 `前缀-[A-Z0-9]+(?:-[A-Z0-9]+)*`。
3. **误删非编号括号**：把「只含编号的括号」规则放宽到纯数字，
   删掉了 `高一 (2)(3) 班` 的班号；同一轮的空括号清理还把模板表达式里的 `.trim()` 削成 `.trim`。
   两处都按 HEAD 逐条对比恢复（13 处），并把括号规则收紧为「必须以需求编号开头」。

教训：这类批量文本清理在提交前**必须与 HEAD 做逐条 diff 复核**，只看复扫计数会漏掉误删。
