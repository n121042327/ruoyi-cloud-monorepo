## 口径（与 PRD / BR 对齐）

- 异动记录**追加式、不更新不删除**（`BR-PROMO-012`）；`addEnrollmentChange` 对不需审批的异动立即改在校记录状态，需审批的等 `approveEnrollmentChange`。
- **退学 / 开除 / 死亡需校级管理员审批**（`REQ-PRM-043` 口径）：登记时置「待审批」，驳回必须填审批意见（≥ 5 字）。
- 终态学籍（已毕业 / 转出 / 退学 / 开除 / 死亡）写入时同时写 `leave_date`。
- 跨校转学：**接收动作本身即审批**（已确认 3），**接收前不计入在读数**（`REQ-PRM-053`）——所以 `acceptTransfer` 只落接收信息，`checkInTransfer` 才建 / 改在校记录为在读。
- **未报到前可撤销**（`REQ-PRM-054`）：已报到的转学单直接拒绝撤销；撤销必须填原因（≥ 5 字）。
- **同一学生未完成转学单唯一**（`REQ-PRM-057`）：发起时查待接收 / 已接收的未完成单，命中即拒绝。
- **转学单只暴露必要字段**（`REQ-PRM-055`）：`EduTransferOrderVo` 只给学号 / 姓名 / 性别 / 原学校 / 原年级 / 目标信息与状态，不暴露转出校的其它业务数据。
- 报到时的班级关系**仍由班级管理写入**（`DP-01`）：`checkInTransfer` 调 `IEduClassService.addRoster`，不自己插 `edu_class_member`。
- 激活码（`D-039` / `GAP-021`）：班主任打印密码条分发 → 学生首登设密码 → 用完即废 → 丢码由班主任重置；**同一学生同一时刻只允许一个未使用激活码**（数据库生成列 `active_guard` + `uk_activation_active` 强制），因此重置时先把旧码置「已作废」再发新码；激活码字符集去掉了易混字符（0/O/1/I）。
