# CR-035 — 学生列表契约样板与批量调班收敛（GAP-066 选项 A）

用户于 2026-10-02 对挂起缺项批注「按推荐走」，本批落实 GAP-066：补学生列表契约样板，并把批量调班收敛到班级模块的调班接口。

## 1. 学生列表查询参数（新版本补样板）

- 学生 PRD 新增小节「**8.1 `listStudent` 查询参数**」，把小节标题与表格列固定成生成器可读的约定：
  标题 ``### 8.N `<operationId>` 查询参数``，表格列「参数 | 位置 | 类型 | 必填 | 说明」。
- 表内 12 个参数：`schoolId` / `termId` / `gradeId` / `classId` / `enrollmentStatus` / `gender` /
  `enrollYear` / `stageCode` / `keyword` / `idCardSuffix` / `sortBy` / `sortOrder`；分页参数仍由生成器统一追加。
- `tools/gen_api_and_map.py` 新增 `parse_query_params()`：从各模块 PRD 读回参数表并写进 OpenAPI。
  阶段 4 的接口清单只有「路径 + 说明」两列，放不下逐字段参数，因此参数的权威源定在 PRD，接口清单与 OpenAPI 保持派生关系。
- 生成结果：`openapi.yaml` 的 `listStudent` 现在声明 14 个参数（12 个业务参数 + `pageNum` / `pageSize`）。

## 2. 批量调班收敛到 `transferClass`

- v2 学生列表的「批量调班」按钮（`ACT-STU-020`）`data-api` 由 `batchTransferStudent` 改为 `transferClass`；
  `page-actions.yaml` 的 `ACT-STU-020` 同步，并在 condition 里写明「单条 = 调班，多条 = 批量迁移」。
- `tools/gen_api_and_map.py` 的 `API_ALIASES` 增加 `batchTransferStudent → transferClass`，
  这样冻结 v1 原型里的历史字符串也不会在派生映射里指向不存在的 operationId（与 CR-029 处理 `transferStudentClass` 同一手法）。
- 学生 PRD 第 8 节补一句说明：批量调班同样复用 `transferClass`，`batchTransferStudent` 只是历史字符串。

## 3. 新增契约一致性检查

`tools/check_api_contract.py`：

1. v2 原型里每个 `data-api` 必须是 OpenAPI 中真实存在的 `operationId`（对应 `CHK-ORPHAN-API`）；
2. 模块 PRD 声明的查询参数必须与 OpenAPI 里该操作一一对齐；
3. `listStudent` 的最小参数集合必须齐备。

只检查 v2；冻结 v1 原型里的历史字符串由生成器的别名表负责映射，不作为失败项。已登记的孤儿引用（`GAP-079`）只提示不判失败，新出现的孤儿引用会让脚本退出码为 1。
