## 结构对照（交互对照的可执行部分）

`python tools/check_fe_page_structure.py` 通过：

- 查询区 9 项，顺序 学校 → 学年学期 → 年级 → 班级 → 学籍状态 → 关键字 → 性别 → 入学年份 → 证件号后四位；
- 表格 11 列，顺序 学号 → 姓名 → 性别 → 入学年份 → 学段 → 年级 → 班级 → 学籍状态 → 联系电话 → 更新时间 → 操作，分组分别为 基础信息 / 教育信息 / 联系方式 / 管理信息 / 操作。

分组与顺序依据 `docs/00-governance/page-field-layout.md`，并与原型表头的 `data-layout-group` 一一对应；
原型的「选择」列（批量操作）本批不做，已在检查器里显式登记原因，不算失败。

## 边界

- 后端接口属阶段 7，本批只对齐契约：运行 `pnpm dev` 时下拉与列表会因接口 404 而为空，页面按空态与失败态降级，不伪造数据。
- 本批未做：导入、批量导出、批量调班、学籍异动、跨校转学、异动登记、详情抽屉、变更记录，以及表单的「证件与联系」「监护人」两组；这些按原型 `PAGE-STU-*` 在后续批次交付。
- `dynamicRoutes` 里的静态路由只用于阶段 6 的开发与对照，阶段 8 由 `sys_menu` 下发同名路由后拆除，避免两条路由争用同一路径。
- 冻结的 `prototypes/**/v1` 未改动；本批没有新增依赖。
