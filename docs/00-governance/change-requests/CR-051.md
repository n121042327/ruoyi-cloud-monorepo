# CR-051 — 阶段 6 第八批：跨校转学（转入校）向导

继续阶段 6，交付转入校侧的 4 步向导，跨校转学的两个方向至此都可用。

## 交付内容

| 落点 | 说明 |
|---|---|
| `apps/plus-ui/src/views/edu/promotion/prm_transfer/index.vue` | 4 步向导：待接收转学单（只列发往本校且未完成的转学单）→ 核对信息与接收（只读必要字段 + 目标年级 / 转入班级）→ 接收确认（只读预览 + 状态机说明）→ 报到（`已接收待报到`，可办理报到或撤销申请） |
| `apps/plus-ui/src/api/edu/promotion/**` | 补 `acceptTransfer`（接收）、`checkInTransfer`（报到）；与上一批的 `listTransfer` / `cancelTransfer` 组成转学单完整生命周期 |
| `apps/plus-ui/src/router/index.ts` | 登记 `/edu/promotion/transfer`（权限 `enrollment.transfer:read`） |
| `tools/check_fe_page_structure.py` | 新增向导对照：4 步标题与 4 个步骤分组 |

## 与原型 / PRD 的对应

- 步骤与动作对齐 `prototypes/functional/v1/pages/promotion-transfer.html`：`ACT-PRM-050` 接收（`acceptTransfer`）、
  `ACT-PRM-051` 办理报到（`checkInTransfer`，权限 `enrollment.status:update`）、`ACT-PRM-054` 撤销申请（`cancelTransfer`）。
- 口径：接收前学生不计入转入校任何在读数与花名册（`REQ-PRM-053`）；接收动作本身即审批；报到后转为在读（`REQ-PRM-051` / `BR-STU-023`）；
  转学单只暴露必要字段（`REQ-PRM-055`）；两侧操作都写审计（`REQ-PRM-056`）。

## 边界

- 待接收清单在校验失败或跨租户读取失败时不展示任何一侧数据（原型的失败态口径）；
  接口不可用时列表为空并给出空态，不伪造数据。
- 报到时可选班级（`checkInTransfer` 的 `toClassId`）；若接收时未指定班级，报到是最后一次指定机会。
