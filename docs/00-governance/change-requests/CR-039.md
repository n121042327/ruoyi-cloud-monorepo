# CR-039 — 追踪矩阵与逐元素映射全量扩展（GAP-063 / GAP-064）

用户于 2026-10-02 批注两个样板「已验收」，并要求把生成生产代码之前的任务做完。本批把两份样板扩展为全量覆盖，两者都用生成器 + 人工保留字段的方式落地，避免手工誊抄。

## 一、需求追踪矩阵全量（GAP-063）

新增 `tools/gen_traceability.py`，机械连接四类上游：

| 字段 | 来源 |
|---|---|
| 需求编号 / 标题 / 业务规则 / 权限 | `docs/10-prd/modules/<模块>/PRD.md` 的需求表 |
| 验收用例 | `docs/10-prd/modules/<模块>/acceptance.md` 的 `AC-* → REQ-*` 列 |
| 原型页面（当前版本 + 冻结 v1） | `prototypes/functional/v1/navigation.yaml` + `high-fidelity/v1/page-manifest.yaml` |
| 前端计划路径 | `docs/40-detailed-design/frontend-page-tree.yaml` |
| 模块接口索引 | `docs/30-architecture/06-api-catalog.md` |

结果：**626 条需求记录**（原 11 条），覆盖 11 个模块，其中 **582 条**挂上验收用例；新增 `module_api_index`，按模块列出 178 个 operationId，满足 `CHK-ORPHAN-API` 的模块级粗粒度追溯。**已有人工判断的字段（`api_operation_ids` / `tables` / `tests` / `status` / `notes`）在重跑时原样保留**，脚本只补机械可得的字段，不覆盖人工结论。

需求到接口与表的**逐条**对应关系没有自动生成——那需要逐条判断，脚本猜测会制造虚假覆盖。这部分另立 **GAP-081**（626 条中已核对 8 条），推荐按模块推进，先做学生与班级。

## 二、逐元素映射全量（GAP-064）

新增 `tools/build_component_mapping_all.py`，逐页解析 `prototypes/high-fidelity/v1/pages` 下全部 45 个高保真页面（含同页浮层片段），输出 `prototypes/high-fidelity/v2/component-mapping-all-pages.yaml`：

- **1361 条元素**，每条有页内唯一 id（`EL-<页面>-<序号>`）、定位用 selector、Element Plus 组件名、props 与判定依据（原型明确声明 / 按 v1 通用规则 / 已声明浮层载体）；
- 按类分布：button 655、input 219、select 136、textarea 21、el-table 60、pagination 21、带 `data-component` 的其他元素 197、浮层片段 52；
- 每页同时记录 `manifest_counts`（`page-manifest.yaml` 的原口径），两个口径并列便于逐页比对——本文件的元素范围更宽（manifest 只统计 class 带 `btn` / `input` / `select` / `el-table` 的元素）；
- 选择器唯一性如实标注：1361 条中 607 条选择器在页内唯一，其余是行内重复模式（`selector_unique: false`），靠 id + page_id + panel_id + action_id 区分，**不假装选择器唯一**。

学生列表的 v2 精修样板（`component-mapping.yaml`，207 条含权限 / 接口 / 角色字段）保持不变，作为 v2 页面的参考；两个文件的定位在 file-catalog 里写清。

## 边界

矩阵里的 `frontend.page` / `backend.*` / `tests.*` 仍为空——生产代码与测试要到阶段 6 / 7 才产出，空着并写明原因，**不填猜测路径、不标为已验收**。映射覆盖的是可交互元素，只读展示元素（标签、卡片、字段值）不在范围内。
