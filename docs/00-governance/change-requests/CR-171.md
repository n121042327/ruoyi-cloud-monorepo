# CR-171 — 阶段 8 验收缺陷修复（第五批）：导入模板缺失（GAP-119）

按业务链路做完「学校 → 校区 → 年级 → 班级 → 教师 → 学生」后，继续验收第 6 项「导入导出链路」，
第一步就断了：**下载模板必然失败**。

## 1. 现象

```
GET /edu/import/template            -> {"total":0,"rows":[],"code":200}
GET /edu/import/template/student    -> {"code":500,"msg":"导入模板不存在：student"}
```

导入向导与学生导入页的模块下拉都直接取 `GET /edu/import/template`，表为空 → 用户连模块都选不到，
后面的「上传 → 校验 → 执行 → 结果下载 → 下载审计」一步都走不到。

## 2. 根因

`edu_import_template` 在迁移 `V4__edu_promotion_stream_support.sql` 里**只有建表、没有种子**；
而 `EduImportTemplate.file_id` 指向对象存储里的模板文件，SQL 迁移无法凭空产生文件 —— 也就是说，
这套设计在原样下**没有任何途径**产生第一份模板（既没有管理员上传模板的接口，也没有生成逻辑）。
`resolveTemplateDownload` 直接对空表 `selectOne`，于是稳定报「导入模板不存在」。

## 3. 修复（D-241：模板列以校验器声明为权威来源）

- `EduImportExportServiceImpl.queryTemplatePageList`：在 DB 结果上合并「已登记校验器、但表里还没有记录」的模块，
  合成一行「当前版本 / 列数 = 表头数 / 文件按需生成」的模板行 → 模块下拉可用；
- `EduImportExportServiceImpl.resolveTemplateDownload`：DB 无记录时调用新增的 `generateTemplate`：
  1. 取该模块校验器声明的 `templateHeaders()`（**与校验阶段的表头严格比对同源**）；
  2. `writeTemplateWorkbook` 用 FastExcel 写一个**只有表头行**的 xlsx（不写示例行 —— 示例数据会被当成真实导入行校验失败）；
  3. `RemoteFileService.upload` 上传统一文件服务，登记 `edu_file_ref`（`file_kind = import_template`，学校取当前登录态）；
  4. 登记 `edu_import_template`（版本 `v1`、状态当前版本、列数 = 表头数），唯一键 `module_code + template_version` 保证幂等
     （并发首次下载时后到的一方复用先落库的行）；
- 返回值仍是统一文件服务签发的**短时签名链接**（REQ-IMP-042），下载照常写审计（REQ-IMP-043）。

三个导入模块的模板列（来自各自校验器声明，与 PRD「导入模板列」小节一致）：

| 模块 | 列数 | 列 |
|---|---|---|
| `student` | 14 | 姓名 / 性别 / 入学年份 / 学段 / 年级 / 班级 / 全国学籍号 / 证件类型 / 证件号码 / 出生日期 / 监护人姓名 / 与监护人关系 / 监护人电话 / 联系地址 |
| `teacher` | 10 | 工号 / 姓名 / 性别 / 所属学校 / 手机号 / 邮箱 / 入职日期 / 教育角色 / 登录名 / 备注 |
| `class_roster` | 4 | 学号 / 姓名 / 目标班级 / 班级类型 |

## 4. 为什么选「现场生成」而不是「管理员上传模板」

模板列的权威来源本来就是模块校验器（校验阶段严格比对用的就是这份声明）。让模板文件从同一份声明生成，
可以从根上消除「模板与校验器漂移」这一类随机失败；管理员上传的方式需要人工维护 3 个 xlsx，
一旦某模块加列就会变成「下载的模板通不过校验」。若后续确需人工排版，现有代码仍优先使用 DB 里已登记、
`file_id` 非空的模板行，两者不冲突。
