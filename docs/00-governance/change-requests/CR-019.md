## 2. 变更原因

`REQ-IMP-038` 要求「超过最大重试次数的任务进入死信，提供运维查看与重放；重放动作写入审计」，
`layout-spec.yaml` 的 `state_rules` 又要求「危险动作（删除 / 停用 / 归档 / 覆盖）必须二次确认，且文案写清对象与影响范围」。
重放会真的改动业务数据（复用原批次号重新入队），属于危险动作，必须有二次确认。

但导入导出 PRD 6.1 的页面清单只有 4 个页面，没有登记这个确认片段。
这正是 `GAP-059` 已经认定的判定口径：「PRD 6.3 提到的每个浮层都在 6.1 的页面清单里有编号」——
重放虽未写进 6.3，但它由 4.6 的需求 + `layout-spec` 的强制规则共同推出，不登记就会出现一个没有编号的浮层。

## 3. 变更内容

1. `docs/10-prd/modules/import-export/PRD.md`：版本升 `1.0.1-draft` 并补变更记录；

   与 `dead_letter`（`ACT-TASK-040` ~ `051`）两组动作。
