# CR-170 — 阶段 8 验收缺陷修复（第四批）：GAP-118 派生列与码值

按「学校 → 校区 → 年级 → 班级 → 教师 → 学生」的业务链路验收时，教育域若干列表把已经存在的业务数据
读成了空值或英文码值，本批一次修完 GAP-118 的四项。

## 1. 班级列表「在读」人数（`student_count`）

- 现象：班级列表「在读」列显示 0（该班实际有 1 名在班学生），`enrolledCount` 为 null。
- 根因：`edu_class` 表不存在读人数；`EduClassServiceImpl.fillNames` 只回填学校 / 年级 / 学期 / 校区名称，
  没有任何聚合统计，`EduClassVo` 的 `enrolledCount` / `capacity` 也从未被赋值。
- 修复：新增 `fillAggregates`，按 `edu_class_member.class_type='administrative' AND status='1'`（在班）
  分组统计，写入 `studentCount`（对齐高保真原型 `class-list.html` 的 `data-field="student_count"`），
  并同值回填 `enrolledCount` 与 `capacity`（班级详情 `cls_detail` 与调班弹窗 `StudentTransferDialog` 已在用的别名）。
  口径与年级列表（CR-169）、班级详情一致，均为实时统计。

## 2. 班级「类型」显示英文码值 `administration`

- 现象：班级列表 / 班级详情 / 年级抽屉的下辖班级里，类型列显示 `administration`。
- 根因：两层 ——
  1. `EduClassServiceImpl.validateClassForInsert` 不校验班级类型枚举（schema 注释只允许
     `administrative` 行政班 / `teaching` 教学班），脏值直接落库；
  2. 阶段 8 验收自建的最小数据里，那条班级正是用 `administration` 建出来的（`POST /edu/class`）。
- 修复：新增枚举校验（非法值直接 400，中文提示），并把该条测试数据修正为 `administrative`。
  前端列表本就有 `CLASS_TYPE_LABEL` 码值翻译，无需改动 —— 这是典型的「页面没错、数据错了」。

## 3. 年级「所属学校」为空

- 现象：年级列表接口 / 详情抽屉的「所属学校」显示「—」。
- 根因：`EduGradeServiceImpl` 没有学校取数，`EduGradeVo.schoolName` 永远为 null。
- 修复：`fillListCounts` 内批量回填 `schoolName`（`edu_school`），并让 `queryById` 也走同一填充，
  详情抽屉与列表口径一致。

## 4. 学生「联系电话」列无值（敏感字段）

- 现象：学生列表的「联系电话」列永远为空；`EduStudentVo` 没有该字段。
- 口径：字段字典 `student_phone` 明确「默认掩码展示，查看全量经 `viewStudentPhone` 并写数据访问日志」。
- 修复：`EduStudentVo` 补 `studentPhone`，`fillListFields` 从在校记录（`edu_student_enrollment.student_phone`，
  即学籍所在校的登记号码）取数并按前 3 后 4 掩码；明文仍走既有 `viewStudentPhone`（已写审计）。
  未新增接口、未放宽任何权限。

## 5. 顺带修正：班级列表「状态」列读错字段

- 现象：班级列表「状态」列取 `row.status`，而接口返回的是 `classStatus` —— 停用班也会显示「正常」。
- 修复：列 `prop` 与模板改为 `classStatus`，与班级详情（`cls_detail`）及原型 `data-field="class_status"` 一致。
