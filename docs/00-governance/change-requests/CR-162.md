## 2. 为什么不在本批直接改

GAP-117 的推荐口径是「给原型补齐 `data-role="column"` 标记」——这只适用于**原型已有表**的情况
（第一、二批的 3 张表都属于这一类）。上面三张是**原型没有表**：补标记无处可补，
直接在生产页删列（对齐原型里语义不同的表）会丢信息（任教类型 / 跨校 / 变更明细都是业务必需），
属于产品内容决策，不能由实现者拍板。

## 3. 待用户拍板（已写入 GAP-117 的 `ask_2026_10_10_batch3`）

**这是什么**：`TeachingAssignmentTable` / `GuardianTable` / `ClassChangeLogTable` 的原型里没有对应表，

**不选会怎样**：这三张表的列序与列名变更不会被任何检查拦住；若硬对到语义不同的原型表（例如把
监护人表对到花名册的「监护人 / 联系电话」两列），会得到「看起来有门禁、实际比错对象」的假覆盖。

**可选项**：① 以现有生产页的列定义为准，把这三张表补进对应原型页并冻结为阶段 3 新版本（推荐）；
② 改生产页去对齐原型里语义不同的表（会丢任教类型 / 跨校 / 变更明细等信息）；
③ 三张表不做原型对照，只靠人工评审。

**推荐方案与理由**：推荐 ① —— 这三张表在生产端已经按 PRD 与字段字典实现，把它们补进原型可以让
原型重新成为「列序的事实源」，同时不改任何已实现功能；需要你确认的是「以生产页现有列定义为准」
这一来源口径（避免我凭空设计列）。
