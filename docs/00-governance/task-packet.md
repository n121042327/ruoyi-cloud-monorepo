# 任务包模板

一个小批任务只有写成本模板的形状，才允许开工。目的是让任何人（包括上下文全新的执行者）拿到它就能干活并判断是否干完。

---

## 任务包

```markdown
# TP-<阶段>-<批次> <一句话标题>

## 1. 基本信息

- 阶段：
- 批次：
- 状态：待开始 / 进行中 / 待验收 / 已验收 / 阻塞
- 前置任务包：
- 关联 GAP：
- 关联 REQ：

## 2. 输入文件

| 文件 | 用途 | 是否已存在 |
|---|---|---|

规则：任何一行"是否已存在"为否，且该输入是本任务的必要条件时，**停止，登记 GAP，询问用户**。

## 3. 输出文件

| 文件 | 说明 |
|---|---|

## 4. 验收标准

可执行、可观察的判据，逐条列出：

- [ ] ...
- [ ] ...

禁止写"质量高""效果好"这类无法判定的标准。

## 5. 验收方法

逐条给出验证命令或人工检查步骤：

| 验收项 | 验证命令 / 步骤 | 期望输出 |
|---|---|---|

## 6. 明确不做

（例如：本批不做导出、不做移动端适配）

## 7. 风险与已知缺口

## 8. 执行记录

| 时间 | 动作 | 命令 | 结果 |
|---|---|---|---|
```

---

## 批次的粒度约定

| 阶段 | 一批的规模 |
|---|---|
| PRD | 1 个模块，或 1 组公共前置文件 |
| 原型（业务 / 高保真） | 2—3 个页面 |
| 详细设计 | 1—2 个模块的表结构 + 接口 |
| 前端 | 2—3 个页面，含 api / types / composable |
| 后端 | 1 个模块 |

首个批次必须是**样板**，只做一件，等到"好看 / 好用 / 对得上"结论后再批量。

---

## 样板批次的额外要求

样板批次除了上面的内容，还必须产出《标准固化说明》，写清：

1. 这一批里哪些做法要被后续批次照抄（命名、目录、组件用法、间距取值）
2. 这些做法固化在哪个文件里（例如 `design-tokens.json`、`component-mapping.yaml`）
3. 后续批次允许偏离的边界
