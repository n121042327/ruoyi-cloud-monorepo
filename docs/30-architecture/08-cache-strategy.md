# 缓存策略

## 1. 原则（来自 `NFR-CACHE-01` ~ `03` 与 `DP-06`）

| 编号 | 原则 | 落地方式 |
|---|---|---|
| C-01 | **缓存只放"能重算"的东西**：权限范围解析结果、热点读、字典。权威数据只在数据库 | 写操作一律先写库再失效缓存，不做"先写缓存" |
| C-02 | **键必须带租户前缀**，禁止跨租户复用 | 键格式统一为 `edu:<tenant_id>:<domain>:<key>` |
| C-03 | 权限来源变更必须**立即失效** | 班主任 / 年级主任 / 任教关系 / 教育角色 / 授权变更时主动删键（不是等过期） |
| C-04 | 缓存失效失败不能导致越权 | 解析结果带版本号；版本号变更视为失效；解析结果里存的是"范围"而不是"是否允许" |
| C-05 | 首轮不引入本地缓存（Caffeine） | 单服务多实例下本地缓存会造成"改了一个实例、另一个实例还放行"，先只用 Redis |

## 2. 键设计

| 域 | 键 | 值 | TTL | 失效时机 |
|---|---|---|---|---|
| 数据范围 | `edu:<tenant>:scope:user:<user_id>` | 该用户的 `DataScope` 片段（范围类型 + 学校 / 年级 / 班级 ID 集合 + 学科限制） | 10 分钟 | 角色变更、年级主任任职变更、班主任变更、任教关系变更、授权变更（C-03） |
| 班主任解析 | `edu:<tenant>:scope:class-head:<user_id>` | 该教师担任班主任的班级 ID 集合 | 10 分钟 | `edu_class.head_teacher_id` 变更 |
| 年级主任解析 | `edu:<tenant>:scope:grade-leader:<user_id>:<term_id>` | 负责年级 ID 集合 | 10 分钟 | `edu_grade_leader` 变更 |
| 任教关系 | `edu:<tenant>:scope:teaching:<user_id>:<term_id>` | `{class_id: [subject_id...]}` | 10 分钟 | `edu_teaching_assignment` 变更 |
| 共享授权 | `edu:<tenant>:grant:<school_tenant_id>:<resource_code>` | 生效中的授权范围（学校集合 / 资源范围） | 5 分钟 | 授权创建 / 撤销 / 到期（`DP-04`） |
| 当前学年学期 | `edu:<tenant>:term:current` | 当前学年学期（`year_id` + `term_id`） | 30 分钟 | 「设为当前」操作后立即删除 |
| 学科与选科角色 | `edu:<tenant>:subject:roles` | 学科 → `stream_role` 映射（选科固定集合的依据） | 30 分钟 | 学科角色配置变更（`NFR-CACHE-02`） |
| 选科配置 | `edu:<tenant>:stream:config:<term_id>` | 开放期 / 截止时间 / 逾期是否需审批 | 10 分钟 | `saveStreamConfig` 后立即删除（`REQ-STR-068`） |
| 选科统计 | `edu:<tenant>:stream:stat:<term_id>:<range_hash>` | 组合分布统计结果（受范围约束） | 5 分钟 | 选科提交 / 审批通过后删除（`REQ-STR-040`） |
| 学校 / 校区 / 年级 / 班级字典 | `edu:<tenant>:dict:<domain>:<school_id>` | 下拉选项（用于筛选级联） | 30 分钟 | 对应实体的增删改 |
| 令牌与登录态 | 由 Sa-Token 管理（沿用基线键前缀） | — | 随基线 | 登出 / 账号锁定 / 密码重置 |

> 键里出现的 `range_hash` = 当前用户数据范围的稳定摘要（范围片段排序后的哈希），
> 保证"同一范围复用同一份统计缓存"，且范围变化时自然落到新键（C-04）。

## 3. 失效链路（必须与业务写操作绑定）

| 写操作 | 必须删除的键 | 依据 |
|---|---|---|
| 班级「指定 / 变更班主任」 | `scope:user:<新班主任>`、`scope:user:<原班主任>`、`scope:class-head:<两者>` | `REQ-CLS-051` / `DP-06` |
| 年级「指定 / 变更年级主任」 | `scope:user:<新主任>`、`scope:user:<原主任>`、`scope:grade-leader:*` | `DP-06` |
| 教师「分配教育角色」 | `scope:user:<教师>` | `DP-06` |
| 任教关系设置 / 批量设置 | `scope:teaching:<教师>:<term>` | `BR-TEACHER-003` |
| 数据共享授权创建 / 撤销 | `grant:<school_tenant>`、受影响用户的 `scope:user:*` | `DP-04` / `DP-06` |
| 学科选科角色变更 | `subject:roles` | `NFR-CACHE-02` / `REQ-SUB-022` |
| 选科配置保存 | `stream:config:<term>` | `REQ-STR-068` |
| 学生选科提交 / 审批通过 | `stream:stat:<term>:*`（按范围） | `REQ-STR-040` |
| 「设为当前学年学期」 | `term:current`、`scope:*`（范围与学期相关） | — |

## 4. 缓存与权限的关系（最容易出错的地方）

| 风险 | 处理 |
|---|---|
| 缓存里存"允许 / 拒绝"结论，范围变了仍放行 | **只缓存范围片段**，是否允许由每次查询按当前资源类型判断（C-04） |
| 删除键失败导致越权 | 解析结果带 `version`（用户权限版本号）；写操作同时递增版本号，命中时比对版本号 |
| 内存缓存跨实例不一致 | 首轮不用本地缓存（C-05） |
| 大 key / 热点 key | 范围片段按用户维度（单用户 key 很小）；统计缓存按 `range_hash` 分片 |
| 缓存穿透 | 空范围也缓存（值为"空集合"），避免每次穿透到数据库 |
| 并发写导致旧值回填 | 失效采用"删除"而非"更新"（删除后再读会重建，避免写序竞争） |

## 5. 降级策略

| 场景 | 行为 | 依据 |
|---|---|---|
| Redis 不可用 | 直接查库（性能下降但不越权）；日志与审计照常写库 | `01-system-context.md` 第 4 节 |
| 缓存与库不一致（巡检发现） | 以库为准，删除缓存键并告警 | C-01 |
| 统计缓存过期 | 重新计算（受当前范围约束，不复用发起时的范围） | `DS-DENY-08` |

## 6. 结论

- 10 类键全部带租户前缀，TTL 与失效时机逐项对应到 PRD 的具体要求（`REQ-CLS-051`、`REQ-STR-040`、`NFR-CACHE-02` 等）。
- 缓存只放范围片段与可重算数据；权限判定不落缓存，避免"缓存导致越权"这类最难排查的问题。
- 首轮不引入本地缓存，避免多实例下的不一致。
